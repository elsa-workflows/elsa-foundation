# Elsa.Activities.Bpmn

Foundation's BPMN host adapter uses the released `Bpmn.Model` and `Bpmn.Semantics` **0.5.0** NuGet packages. The library owns graph validation, token transitions, gateways, event policies, compensation and pruning. Foundation owns its authored payload, activity bindings, values, exact runtime identities and transactional application of the returned commands.

The integration follows the [host compatibility contract](../../../../../specs/1006-bpmn-library-adoption/contracts/compatibility.md). Domain terminology belongs to the [Elsa glossary](../../../../../docs/glossary/elsa.md); the selected library's [supported constructs](https://github.com/valence-works/bpmn/blob/021d2c5bba494f17d346144d97763cd3b2a13a4b/docs/reference/supported-constructs.md) describe its neutral profile. The [parity cut ledger](../../../../../docs/reports/evidence/bpmn-adoption-0.5.0/cut-ledger.md) distinguishes that profile from Foundation's binding capabilities.

## Authored and stored contracts

`BpmnProcess` and `BpmnDecision` retain their published activity identities and frozen authoring contracts. The process uses `elsa.bpmn.structure` **1.0.0** and the `Bpmn.Activities` child slot. Foundation's authored DTOs retain `childNodeId`, `listenerNodeId`, variable declarations, default-flow markers and designer data. `BpmnGraphAdapter` translates those references into the library's binding references against the complete compiled child inventory. Unbound, conflicting and orphan work is refused at that boundary.

The private-state alias remains `Elsa.Bpmn.ExecutionState`. The compatibility codec reads existing version **1**, translates its `activeChildren` and `producingActivityExecutionId` fields internally, and writes the declared version and original wire names when that execution continues. Fresh executions write version **2**. Library package version, neutral payload version, authored schema and private-state version are separate contracts. Unsupported or ambiguous documents are retained and refuse further dispatch; callbacks cannot initialize missing state.

Exact parent, node, element, semantic token, iteration and activity-execution identity determine live/stopped work. Complete durable child history supplies legacy handles before library pruning. Reusing a node or a null iteration does not identify an invocation. Released pruning runs after a complete evaluation; Foundation retains the compatibility codec and runtime ledger rather than a second semantic state model or pruning policy.

Actual old-writer captures and old/current process controls are retained in the [legacy checkpoint evidence](../../../../../specs/1006-bpmn-library-adoption/evidence/legacy/README.md), [legacy calls](../../../../../specs/1006-bpmn-library-adoption/evidence/legacy-called-workbench-recovery.md) and [active compensation recovery](../../../../../specs/1006-bpmn-library-adoption/evidence/ordinary-compensation-host-recovery.md). Continuing a supported v1 document does not promise rollback to an old engine after released pruning.

## Runtime and called workflows

The scoped `IBpmnProcessRuntime` adapter supplies the library's live-work/value/capability snapshot and applies returned commands through Foundation's scheduler, subtree cancellation, parent notifications and checkpoint authority. It folds notifications and terminal classification in order, stages one verdict, and retains outward signals even when the final verdict faults. Only the exact incident identified by an absorbed error disposition is resolved; original child fault/status information remains truthful.

Newly compiled waited Call Activities opt into the generic `elsa.bpmn` child-control protocol **1** only when the pinned parent declares it. Actual child-root notifications and terminal classification are carried by durable ordered sources. A contiguous accepted prefix reaches the exact calling token together; an empty terminal-success or ordinary-fault barrier cannot skip an earlier ordinal. Interruption retires only that invocation. Existing pins without the capability keep their ordinary DispatchWorkflow outcome path. The [called-control reconciliation](../../../../../specs/1006-bpmn-library-adoption/evidence/called-control-reconciliation.md) records actual public-host and fresh-EF qualifications and their limits.

BPMN named-event publication uses the host's durable first-delivery recipient snapshot. That snapshot preserves delivery-time matching and is reused on retry, excluding later rearmed waits or new bindings. Per-recipient starts/resumes use existing durable receipt identities. Activation, old-writer preflight, retention and source/claim authority are Foundation responsibilities, recorded in the [broadcast reconciliation](../../../../../specs/1006-bpmn-library-adoption/evidence/broadcast-delivery-reconciliation.md). Native Sequence and Flowchart parents retain their own completion/join behavior.

## Composition and authoring tools

Enable `ActivitiesBpmnFeature`. It registers the authored structure handler, compatibility codec, exact work ledger, one scoped `IBpmnProcessRuntime`, and start-trigger/recurring-schedule providers. A nested process sets `CanStartWorkflow=false` to suppress independent external starts. Publish-time inspection and execution share the released graph translation. [Extension points](EXTENSION_POINTS.md) describe the remaining host boundary.

XML import/export lives in the separate [interchange module](../Interchange/README.md). Its registered binder reports actual host readiness; retained XML or successful neutral graph validation alone does not qualify execution. Unsupported date/cycle delivery bindings and retained condition expressions remain explicit. The binder preserves duration descriptors while normalizing supported literal waits, and uses actual active recommended catalog contracts.

The old Foundation engine, behavior registry/contexts, graph/coordinator/mutator, semantic state DTOs and `PruneForPersistence` are removed. Integrations consuming those retired preview APIs must use the library's neutral contracts or a supported host adapter. The frozen authoring surface and supported stored-state representations remain independently qualified. Tests guard public Semantics simple-name collisions and the deleted source/type/pruning surfaces.

The [post-deletion standard-host and Studio qualification](../../../../../specs/1006-bpmn-library-adoption/evidence/post-deletion-host-qualification.md) records actual frozen-v1 continuation after writer removal, strict real-child calls, registered import/broadcast and normal browser authoring/publication/execution/reload/export. Its pinned build and evidence scopes remain distinct from final required checks and resulting-main verification.
