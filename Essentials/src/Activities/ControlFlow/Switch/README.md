# Elsa.Activities.Switch

Switch 4.1 / structure schema 2.0.0 evaluates ordered Boolean case conditions through the normal typed input pipeline. In `MatchFirst` (the default), the first true case runs its branch and yields its label; later conditions are never evaluated. In `MatchAny`, all conditions materialize before any body starts, and every matching populated case is scheduled once in case order with independent branch provenance. Bodies may finish in any order. Switch waits for all selected bodies to succeed, then selects all matching labels in case order. A matching empty case contributes its label and suppresses Default. If none matches, only the optional Default body runs, followed by `Default`. A cleared predicate is false; an evaluated expression failure starts no body and records the normal blocking input-failure incident.

In Studio, select Switch, open **Slots**, choose **Match mode**, add a case, and choose the condition's expression syntax with the standard input control. Labels, conditions and branch activities are separate. Move up/down changes case priority. Stable case IDs keep expression documents and open branch navigation attached during reorder/rename. Workflow authoring uses the persisted typed context after autosave. Activity Definition graphs reuse their existing syntax and scoped-variable controls; their ordinary-input server-language-service limitation also applies to case inputs.

Existing schema 1.0.0 workflows and artifacts retain ordinal `Value` string matching. **Upgrade to case conditions** changes the source version/schema in one document mutation while preserving matches, Value, descendants and unknown payload members. Each retained case continues matching Value until **Use condition** is selected. Value is evaluated only if a legacy case is reached and omitted from compilation when all cases are predicates. Activation-only Secret Value bindings must be replaced before upgrading; direct Secret predicates are refused.

Case labels remain unique across both schemas. `SwitchDuplicateCaseValidator` reports malformed identities, unsupported bindings and duplicate labels; publishing and runtime guards provide independent backstops. Each branch retains its runtime slot `Switch.Case[{match}]`; author-facing surfaces display the label. `Default` and `Break` remain fixed outcomes.

The structure handler projects normal Boolean input definitions and states. Publishing produces ordinary typed input bindings/contracts; the Switch-owned keyed policy materializes only consumed inputs before the Running checkpoint. The immutable snapshot pins selection for redelivery/recovery. Activation supplies that snapshot through `IRuntimeStructureInputConsumer`, and Switch selects without reevaluating expressions. Runtime remains independent of Design models (Elsa §E2.2). See [extension points](EXTENSION_POINTS.md).

MatchAny case bodies are unordered relative to each other; Default is mutually exclusive with them. Sibling result availability remains conservative. Suspension retains the pinned selection; recovery aggregates current direct-child successes without re-running completed bodies. A child fault retains the existing blocking child incident and does not complete Switch successfully. Switch does not opt into processed-child fault rescheduling or input rematerialization. Native `Break` cancels live selected child subtrees atomically and propagates immediately; workflow Finish and enclosing cancellation retain their runtime semantics. The new body-containing MatchAny shape rejects a case label `Done`. Downstream graph join behavior is unchanged. See [S-12](../../../../../specs/1233-switch-match-any-bodies/spec.md).
