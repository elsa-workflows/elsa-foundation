# Extension points — Workflow Runtime API

`WorkflowsRuntimeApiFeature` is the host-independent composition root for the supported Runtime management-client routes documented in [README.md](README.md). It does not depend on `Elsa.Workbench`.

## API-facing replacement contracts

| Contract/service | Role in this API |
|---|---|
| `IWorkflowExecutableStore` | Lists and loads immutable executable artifacts for inspection and execution. Persistence providers replace the in-memory implementation. |
| `IWorkflowActivationAuthority` | Supplies read-only activation-slot projections for the runtime activation-slot GET routes. The API does not expose deactivation. |
| `IWorkflowExecutableReferenceStore` | Supplies read-only source provenance. Mutation remains with Publishing operations. |
| `IWorkflowExecutionStateStore` | Supplies instance, activity-execution, and incident projections and retained executable roots. |
| `IWorkflowDispatchStore` | Supplies exact detached-dispatch lookup while preserving the original #676 store contract. |
| `IWorkflowDispatchQueryStore` | Additive bounded query capability used for parent/child/status dispatch inspection; tenant scope comes from provider access context, never request input. |
| `WorkflowExecutableInspector` / `IWorkflowExecutableInspector` | Assembles stable executable and provenance views from Runtime-owned stores. The endpoint classes dispatch through the interface seam; both registrations use `TryAddScoped`, so a host may replace the projection strategy. A replacement takes over the redaction the default applies to sensitive, encryption-requiring and secret-bound inputs (README, [Withheld and protected values](README.md#withheld-and-protected-values)). |
| [`IActivityInspectionContextAsync`](../Inspection/Core/EXTENSION_POINTS.md) (contract in `Elsa.Workflows.Runtime.Inspection.Core`) | Separately authorizes structural inspection, redacted value evidence, and raw captured-value payload resolution. The default delegates to Foundation Identity, and its effective authorization profile participates in cursor binding. |
| `IActivityExecutionValuePayloadReader` | Owns the non-disclosing raw-payload resolution result contract. The feature registers only this contract; hosts may replace the implementation without coupling the endpoints to the default reader. Resolution fails closed unless the authorization context supplies a stable attributable audit subject. The default answers `unavailable` for a record that carries a withheld marker (spec 188), whatever it carries beside the marker. |
| `IActivityExecutionValuePayloadAuditSink` | Receives every authorized, denied, or unavailable raw value-payload resolution attempt, including the stable audit subject and request correlation ID, without receiving the payload itself. The default writes structured metadata to the host logger. |
| `ActivityExecutionLayoutReader` | Projects composite-boundary structure from the pinned executable artifact and joins optional source-reference geometry. It never loads Design state and retains authored nodes that did not execute, including immediate nested boundary roots while keeping their descendants lazy. |
| Runtime diagnostics settings store and `IRuntimeDiagnosticsSettingsService` | Back the canonical diagnostics settings resource; durable or centrally managed hosts may replace the underlying settings persistence. |
| `IWorkflowRuntimeOperatorAccess` | Answers whether the caller may manage one run (spec 260 FR-416), for the `permissions.canManage` signal on the run details, and, through `CanManageRuntimeAsync`, whether the caller may manage the runtime itself, for the diagnostics settings' `permissions.canManage` (#3130). The default (`HttpContextWorkflowRuntimeOperatorAccess`) evaluates `workflows/runtime:manage` with Foundation Identity's evaluator and the caller's tenant, with the run as resource or no resource, and fails closed; an implementation that does not override `CanManageRuntimeAsync` answers `false`. A display hint only: submission and saving still enforce the permission. |
| `ActivityStateViewProjectorRegistry` | Holds the composed `IActivityStateViewProjector` contributions (spec 260 R-6) by private-state alias, by optional cleared-state activity type, and by optional executable-node descriptor kind, for the state view route. A descriptor-kind projector reads a provider-owned family of user-defined activities, whose type keys are not known in advance, with or without private state, and takes precedence over alias and cleared-type matching. A duplicate alias, activity type or descriptor kind fails startup through `ValidateActivityStateViewProjectorsStartupTask`. `RuntimeActivityStateViewCapabilitySource` advertises the `activity-execution-state-view` link only when a projector is composed. |
| `IWorkflowAlterationRequestContext` | Supplies authenticated submitter, tenant partition, authority scope, and request correlation evidence, and decides per run whether the caller may manage an explicitly named run (`CanManageAsync`, the permission run deletion evaluates, with the run's state as the resource). Request bodies never choose tenant/authority scope. |
| `IWorkflowAlterationAdmissionGate` | Checks bounded capacity before a durable alteration plan exists. A rejection maps to `429`; it must not consume the idempotency key. |
| `IWorkflowAlterationStore` | Runtime's plan/job persistence port. The API uses redacted projections only and never decrypts `ProtectedPayload`. |
| `IWorkflowExecutableInspection` (contract in `Elsa.Workflows.Runtime.Core`, spec 1193 D4) | Reads one exact Executable by artifact id for other domains (such as Weaver's `Elsa.Weaver.Workflows.Runtime`) that couple only to `.Core` contracts. The default, `WorkflowExecutableInspection` (internal sealed, this package), reads through the same `IWorkflowExecutableInspector` as `GET runtime/workflows/executables/{artifactId}` and maps a subset of its response: identity, Artifact Hash, the compiled node tree with input bindings by name, source and sensitivity (no value or source detail, a secret read's reference included), child slots and structure-owned connections, every Source Reference the endpoint lists, and the direct dependencies (not the chosen reference with its layout, compatibility metadata, input contract, output captures, BPMN projection or retained execution count). An unknown artifact is `null`. It decides no authority: a consumer requires `workflows/runtime:read`, the endpoint's permission, before disclosing anything; a caller that bound an Artifact Hash compares it with the returned one. One registration per shell: a second one fails configuration and shell startup (`WorkflowExecutableInspectionStartupTask`). |
| `IWorkflowRunInspection` (contract in `Elsa.Workflows.Runtime.Core`, spec 1193 D4, slice G) | Reads one exact Run (its Workflow Instance) and, where one is selected, one exact activity execution of it, for other domains (such as Weaver's `Elsa.Weaver.Workflows.Runtime`) that couple only to `.Core` contracts. The default, `WorkflowRunInspection` (internal sealed, this package), reads through the run endpoints' own services: `IWorkflowInstanceDetailsService` (the instance with its Executable identity and Artifact Hash, its incidents and one activity page, clamped to 50), `IActivityExecutionInspectionService` (the selected execution, its bookmarks, incidents and value evidence), `IActivityExecutionStateViewService` (the state view) and `IActivityExecutionValuePayloadReader` only for the evidence ids the caller names in `ResolveEvidenceIds` (at most 32 per read; each read is authorized and audited by that reader, so a consumer resolves, and the reader audits, only what it discloses). Each service applies the endpoints' per-run authority (`IActivityInspectionContextAsync`: structure, values, payload resolution) for the current request; `CanInspectValues` and `CanResolveValues` report the last two, so a consumer can withhold a retained read its actor no longer covers. The consumer requires `workflows/runtime:read` before calling. It is stricter than the run page, because its consumer discloses to a model: a `WithheldKind` marker or any sensitive value (captured or not) is `Withheld` and is never released or resolved; an incident message is withheld (`MessageRedacted`, `SensitiveInputs`) unless its activity's non-sensitivity is established from both sources, the Executable node's input bindings (the node named, and the execution's own) and the activity execution's own value evidence, and, for an incident propagated from a child (`runtime.causalActivityExecutionId` from `IActivityFaultCausation`, a structural parent's `runtime.completedChildActivityExecutionId`, a parent's `runtime.notifyingChildActivityExecutionId` when it faulted handling that child's notification), the same for that causal child; an incident a child-control consumer raised (`runtime.childControlActivityExecutionId`, or the `ChildControlFaulted` sub-status) or one recorded for poisoned scheduler work is always withheld; a causal key present but blank counts as sensitive. The causal chain is followed through each child's own incidents in this Run, because a propagated message can carry a descendant's text (a nested BPMN process copies its child's fault message); a chain deeper than 8 counts as sensitive. A child-control consumer's returned fault or failed disposal recorded before the runtime named the calling child carries neither marker and is not recognized (stores written by builds before #3736, pre-4.0 previews). Each execution's verdict is cached and at most 32 executions are read per read (beyond that they count as sensitive, also cached), and the selected execution's verdict applies to its run-level incidents too, in both the top-level and the selected activity's incidents; an incident without an activity execution, a causal child named only partly, an unreadable Executable or execution, or one beyond the bound counts as sensitive. The selected activity's state view is withheld in the same way (`Withheld`). A redacted or unresolvable value is `NotPermitted`; an uncaptured one (`notCaptured`, `metadataOnly`, `captureFailed`, `unavailable`) `NotCaptured`; a missing payload read, activity inspection or state view, a `NoProjector` state view, or no activity state to project, `Unsupported`; a selected execution an incident of the Run names, or whose activity state the Run still holds, but whose inspection record is gone, or a value whose evidence vanished, `Pruned`; a selection the Run never recorded has neither an execution nor a reason. `WorkflowRunValueDisclosure`'s default is `Withheld`, so an unset disclosure fails closed. `IsTerminal` and `ReadAt` (stamped before the first store read) attribute an in-progress Run to the time it was read as of. An unknown or hidden Run is `null` (as the endpoint's 404). One registration per shell: a second one fails configuration and shell startup (`WorkflowRunInspectionStartupTask`). |

The Runtime API also dispatches through the engine contracts composed by `AddWorkflowRuntime()`. Those execution, checkpoint, actor, trigger, scheduling, retention, and recovery seams are documented in the [Runtime domain extension catalog](../Elsa.Workflows.Runtime/EXTENSION_POINTS.md); this API catalog does not duplicate them.

Optional stimulus/trigger providers are additive contributors to Runtime routing. Executable/reference/execution/dispatch stores are single-owner persistence ports and must be replaced deliberately. Dispatch endpoints always map records to `WorkflowDispatchView`; replacing a store does not widen the safe API projection.

Activity-execution detail exposes capture truth and stable evidence identities but never embeds raw captured payloads. Clients resolve a payload through the dedicated `value-evidence/{evidenceId}/payload` capability only after the separate payload-resolution authorization and audit path succeeds.

Alteration endpoints are a durable command/query surface: submit and cancel require `workflows/runtime:manage`; plan
and job reads require `workflows/runtime:read`. Hosts add custom alteration implementations through the Runtime
`AddWorkflowAlterationHandler<T>` contribution, not by adding API request handlers or wire-level CLR type names. The
API exposes no handler payload schema endpoint: descriptor-only discovery remains the trusted host's
`IWorkflowAlterationRegistry` concern, avoiding handler construction and executable payload-type leakage.

Canonical ownership and retention rules are defined in the [domain-owned API spec](../../../../../specs/220-domain-owned-apis/spec.md); terminology is defined in the [Elsa glossary](../../../../../docs/glossary/elsa.md).

## User Tasks API

`WorkflowsRuntimeApi` owns User Task routes, source-generated JSON/error DTOs and its five task/form permissions through `WorkflowRuntimePermissionContributor`. `TaskRequestAccess` is the default scoped `IUserTaskAccess` adapter only when the host has not selected another one. It requires normalized canonical user/tenant claims and reloads active users, roles, memberships and current global/resource permissions. Incomplete directories fail task operations closed without making unrelated minimal hosts unstartable.

`UserTaskCapabilitySource` advertises `elsa.api.user-tasks` v1 only for the selected qualified durable journal/execution pair or the explicit volatile development composition. It contributes task/lifecycle/forms/version/targets/identity relations. Task views omit private invocation/recipient details; field-error keys remain opaque JSON. Revision/request receipts distinguish durable `CompletionPending` (202) from canonical completion (200). All routes participate in Runtime's schema refusal/fault family. See the [guide](../../../../../docs/user-tasks.md) and [owning runtime contract catalog](../Elsa.Workflows.Runtime/EXTENSION_POINTS.md#user-tasks).

## Standalone triggers API

`StandaloneTriggersApiFeature` is a separate bounded composition root. It installs authoring aggregation, permission/capability contributions and management projections without calling `AddWorkflowRuntime()` or installing intake/pumps. The host supplies the selected resource store, target discovery and input mapper. Its default authoring committer refuses activation; a protected source-resource participant enables the source-aware committer only for actually installed source types. The [feature README](StandaloneTriggers/README.md) owns the route and composition details.

The API consumes Core's `IStandaloneTriggerStore`, `IStandaloneTriggerTypeCatalog`, `IStandaloneTriggerTargetDiscovery`, `ITriggerInputMapper`, `ITriggerManagementCommitter`, `IRuntimeIngressDeliveryStore`, `IRuntimeIngressReservationReader`, `IRecurringTriggerScheduleStore`, `IIngressReservationPolicy`, `IWorkflowTriggerBindingStore` and `IWorkflowExecutableSourceReferenceStore`. These are replacement contracts owned by the [Runtime domain catalog](../Elsa.Workflows.Runtime/EXTENSION_POINTS.md#standalone-trigger-authoring-and-source-boundaries), not additional API extension ports. Internal actor/view/command types are not a module integration contract. Resource and target permissions apply equally to trigger and workflow surfaces; preview tokens never supply authority.

Capability `elsa.api.standalone-triggers` v1 is advertised only when resource store/discovery/mapper resolve; delivery relations additionally require actual physical inspection support. Mapping-context expression discovery lists installed portable-handler languages and actual evaluator availability; delivery list filters are limited to trigger/paging. Readiness/capability projection is not provider, restart or Studio qualification; see the [operator guide and limits](../../../../../docs/standalone-triggers.md).

Impact review uses the installed source-owned semantic reservation policy across all relevant physical-scope pages and active legacy bindings, preserving original hashes. Scoped source provenance excludes a known foreign publication before route metadata is decoded. Missing inspection support makes that change unavailable; the protected writer still arbitrates the final race.
