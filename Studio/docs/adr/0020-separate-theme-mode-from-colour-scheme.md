# Separate the theme mode from the colour scheme

A Studio theme renders in one of four modes: Light, Dark, Dim and High contrast. Light and Dark are required of every theme; Dim and High contrast are optional palettes a theme opts into by defining them. The mode is a user preference, not a property of the theme: the preferred mode is stored once and survives theme switches, and when the current theme lacks it Studio falls back within the same luminance family, so a user who prefers Dim or High contrast sees Dark rather than a flash of Light, and gets their preference back when they return to a theme that has it.

The mode and the colour scheme are published separately on `<html>`. `data-theme-mode` keeps its original meaning — the light/dark colour scheme — and Dim and High contrast both report `dark` there. The exact mode is published as `data-theme-appearance`. Independently bundled modules and external hosts already key dark-scheme adjustments on `[data-theme-mode="dark"]`; widening that attribute to four values would have silently dropped their dark treatment under Dim and High contrast. Keeping it as the scheme means every existing dark rule applies to the new modes unchanged, and modules express mode differences through tokens rather than per-mode selectors.

A theme definition also carries its typography (sans, mono and display font stacks) and shape (the corner-radius scale), validated as plain font-family lists and `px`/`rem` lengths. They live in the definition, not in per-theme CSS, so a duplicated or store-authored theme carries them along. Elevation recipes stay in `tokens.css` keyed by theme, because shadows are composite CSS values the theme store does not accept. Typefaces are bundled with the host rather than fetched from a font CDN, so Studio keeps its look offline and in locked-down networks; a browser downloads a face only when an element renders in it.
