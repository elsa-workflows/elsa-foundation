# Author BPMN element structure through the shared graph canvas

A BPMN graph's authored material is its element structure — events, gateways, tasks, subprocesses, and the sequence flows between them — and the child activities those elements bind. Every graph host that opens a BPMN-mode scope renders and writes that structure through the shared BPMN canvas layer. A host that cannot render elements and sequence flows does not offer BPMN at all; it does not fall back to projecting the bound activities alone. Projecting only the activities silently discards the process: the elements and flows disappear from view, and any activity the host adds is written without a matching element, so the next BPMN-aware save drops it.

BPMN canvas node identity is the element id, not the activity node id. Element identity is what layout, selection, and connection routing key on, so a BPMN scope's layout records are keyed by element id and reconciliation preserves records for elements rather than pruning them as unknown activity nodes. Every capability that addresses an activity — slot navigation, inspection, delete cascade, presentation cleanup — routes through the element's bound activity node id instead. Routing such a capability through the element id resolves to nothing and blanks the canvas rather than failing loudly, so hosts translate at the element boundary and never pass a canvas node id into an activity-addressed API.

A subprocess is not a distinct authoring mode. An activity-bearing element whose bound activity is a container exposes that container's slots exactly as an ordinary activity node does, and entering one is ordinary slot navigation producing an ordinary scope frame. The scope reached that way is itself a BPMN scope when the bound activity is a BPMN process, so the same canvas construction, write-back, breadcrumb, and layout reconciliation apply unchanged at every depth. Studio does not introduce a separate drill-down mechanism, a BPMN-specific breadcrumb, or a per-node navigation closure for this; slot navigation stays a canvas-level context handler so node data identity remains stable while unrelated nodes are dragged.

This governs how ADR-0012's BPMN composition choice is honoured. Offering BPMN at creation commits the host that opens the result to the whole of this contract, including the BPMN shape palette that makes events and gateways authorable; a host that only binds activities to tasks cannot express a BPMN process and must not advertise the choice.
