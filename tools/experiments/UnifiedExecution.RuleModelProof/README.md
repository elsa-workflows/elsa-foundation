# Finite rule-model extension proof

This isolated .NET 10 experiment implements a finite, positive, ground propositional rule model as a separately built and packed assembly. The host uses the public `UnifiedExecution.WorkProof` APIs without modifying that project. Nothing here adds a production execution-engine promise or a production model extension contract.

The pinned artifact starts with `{seed}` and contains five finite rules. Each durable round computes the immediate consequences of all rules against the frozen fact set, adds only new facts, and stores the firing/addition trace. The host advances only after accepting the round receipt. It completes only when a full round adds no facts. For this finite monotone rule set, iterating the immediate-consequence operator from the base facts reaches its least fixed point; the unreachable rule remains inactive. Four persisted round invocations yield `{seed, left, right, joined, final}`.

`Assets/model-manifest.json` declares the model and package versions, artifact SHA-256, package assembly SHA-256, entry-point type, state schema, declared worker-handler set, and host capability requirements. The build script creates a runtime manifest with the SHA-256 of the exact newly compiled package before creating any execution. The checked-in template deliberately cannot execute without that step; it does not pretend one local binary hash is reproducible across source commits and build paths. The resolver never refreshes a pin during resume. Both coordinator resume and worker claim validate the full persisted package/descriptor pin; the swap probe rejects an alternate binary even with unchanged model and handler versions. The generic registry checks the capability set and both hashes, verifies the bytes of the assembly actually loaded, loads the package through its declared entry point, and checks the package descriptor. The persisted policy ID binds the execution to the artifact, schema, package identity and bytes, handler declarations, and host requirements. A negative control builds a descriptor-compatible package assembly with different bytes and verifies that a fresh resume host rejects it. These hashes provide integrity pinning for this proof, not package publisher authentication or a production trust policy. The shared model-contract project has only identity/status fields in its common inspection summary; the rule engine’s round and trace remain model-specific detail JSON.

The proof starts and resumes the coordinator in separate OS processes. A separate worker process claims and executes each rule round using the package. Before a fresh resume process applies each result, the harness replays the same result and verifies the durable duplicate receipt. A negative capability preflight is rejected before execution creation or work dispatch. The cancellation case cancels a claimed round, then verifies that a late result is rejected, cannot be reclaimed, and does not add facts. This is work-level cancellation: the model execution remains `Running`; terminal model cancellation is not part of this proof.

The artifact models one immutable finite rule set with no variables, negation, updates, or external effects. It has one worker handler, though the experimental package manifest declares handlers as a list. The proof covers a local SQLite store and fresh local processes. It does not establish multi-host operation, a general parallel rule scheduler, arbitrary model migration, or a stable production extension contract. The package registry and contract assembly exist only inside this experiment directory.

Run the reproducible build, package check, and process witness from the repository root:

```bash
bash tools/experiments/UnifiedExecution.RuleModelProof/run-proof.sh
```

The script restores/builds the host’s project graph and the isolated same-source alternate-assembly project, packs the engine into a temporary directory, runs the host witness, and writes `evidence.json` under a unique temporary scratch directory. The report includes the package and artifact pins, final inspected state/trace, child process IDs/exits, cancellation and package-swap outcomes, and every assertion. The pack output and SQLite databases are not left in the repository.
