# Owned native-work queue capture

The ETL/BPMN recovery controller invokes this SDK client against its own temporary Workbench store. It requires that controller's live process, model identity and nonce marker. The model must retain its original Running invocation, exact native pin and undelivered start source; the worker and its queue must still be absent.

`--enqueue-start` uses the existing `IWorkflowSchedulerDrainPolicy` seam to defer inline draining. `--enqueue-checkpoint` requests one normal scheduler work item, leaving the generated WorkflowStarted checkpoint queued. Both call the production `IWorkflowStartDispatcher`, actor/router and qualified EF queue. The same real model-owned worker identity and complete origin are retained. Standard Workbench hosts perform the recovery afterward.

The enqueue operations compose the normal persistence modes, perform no migration and write no workflow/activity/bookmark or ETL state. Their output includes the accepted command, exact queued envelope, unchanged model, absence of a native header, expected retirement commit identity and product hashes/versions. These are owned qualification runs; the controller supplies a fresh temporary root and cleans up every process.

Build through the standard build-slot wrapper, then use `e2e-tests/etl/qualify_http_recovery.py` with `--model-cancel-before-admission --queued-native-stage start` or `checkpoint` and the built `--dispatcher-assembly`. The hosting test project and `Elsa.Server.slnx` include this build dependency.

For an admission/cancellation race, `--drain-checkpoint` processes the retained native checkpoint through the production drain orchestrator; `--cancel-model` calls the supported BPMN runtime cancellation operation. These operations require the original queued checkpoint and compose the production BPMN feature and event services before qualified persistence, then initialize the normal protocol registry. The native operation also uses the existing two-cycle orchestration budget. The accepted admission-first capture commits the native header and schedules its root activity, retaining the next StartActivity queue item before activity invocation. Reaching this deliberate budget is reported explicitly; it leaves invocation to the standard host. A per-pass one-item scheduler budget alone also follows delivered continuations and is insufficient for this cut.

The controller's `--admission-race-order cancel-first|admit-first` pauses the first writer with an optional `--gate` directory in its owned root. A pass-through `IRuntimeCheckpointCommitEnricher.ValidateFinalAsync` records the actual proposal, its fingerprint and observed model before the provider transaction. It waits for the controller to commit the competitor, then releases the unchanged proposal. This is a deterministic observation hook in the SDK tool; the production writer, model semantics and standard recovery hosts are unchanged.

`--consume-native-result` qualifies acknowledgment loss on the actual admitted ETL journey. It composes the existing ETL runtime/native adapter/persistence features using only the controller's original owned bindings and existing stores; it starts no background worker. When model cancellation is still owed, the production outbox processor queues its native Cancel command and its normal recovery mailbox commits the real terminal checkpoint. The processor delivers the original ETL-cancel source, queues the original native result without acknowledgment, and the normal protocol-aware recovery mailbox commits its exact model input receipt. The SDK requires the source to remain FailedRetryable afterward. It writes no acknowledgment and seeds no persisted workflow state or fabricated domain result/receipt. Its receipt includes the actual delivery/drain results, original origin, model/native state, exact input/source and eight product identities. `--pending-cancellation-crash --consumed-before-ack-crash` leaves final acknowledgment and ETL terminal delivery to fresh standard Workbench hosts after process loss. Both public native-originated and model-originated cancellation use the same operation.
