# Owned native-work queue capture

The ETL/BPMN recovery controller invokes this SDK client against its own temporary Workbench store. It requires that controller's live process, model identity and nonce marker. The enqueue modes require the original Running invocation, exact native pin and undelivered start source, with the worker and its queue still absent. The consumption and authorization controls below validate their own actual journey boundaries.

`--enqueue-start` uses the existing `IWorkflowSchedulerDrainPolicy` seam to defer inline draining. `--enqueue-checkpoint` requests one normal scheduler work item, leaving the generated WorkflowStarted checkpoint queued. Both call the production `IWorkflowStartDispatcher`, actor/router and qualified EF queue. The same real model-owned worker identity and complete origin are retained. Standard Workbench hosts perform the recovery afterward.

The enqueue operations compose the normal persistence modes, perform no migration and write no workflow/activity/bookmark or ETL state. Their output includes the accepted command, exact queued envelope, unchanged model, absence of a native header, expected retirement commit identity and product hashes/versions. These are owned qualification runs; the controller supplies a fresh temporary root and cleans up every process.

Build through the standard build-slot wrapper, then use `e2e-tests/etl/qualify_http_recovery.py` with `--model-cancel-before-admission --queued-native-stage start` or `checkpoint` and the built `--dispatcher-assembly`. The hosting test project and `Elsa.Server.slnx` include this build dependency.

For an admission/cancellation race, `--drain-checkpoint` processes the retained native checkpoint through the production drain orchestrator; `--cancel-model` calls the supported BPMN runtime cancellation operation. These operations require the original queued checkpoint and compose the production BPMN feature and event services before qualified persistence, then initialize the normal protocol registry. The native operation also uses the existing two-cycle orchestration budget. The accepted admission-first capture commits the native header and schedules its root activity, retaining the next StartActivity queue item before activity invocation. Reaching this deliberate budget is reported explicitly; it leaves invocation to the standard host. A per-pass one-item scheduler budget alone also follows delivered continuations and is insufficient for this cut.

The controller's `--admission-race-order cancel-first|admit-first` pauses the first writer with an optional `--gate` directory in its owned root. A pass-through `IRuntimeCheckpointCommitEnricher.ValidateFinalAsync` records the actual proposal, its fingerprint and observed model before the provider transaction. It waits for the controller to commit the competitor, then releases the unchanged proposal. This is a deterministic observation hook in the SDK tool; the production writer, model semantics and standard recovery hosts are unchanged.

`--retry-held-model` and `--cancel-held-model` submit supported runtime commands against the actual revision-two held service failure. With `qualify_http_recovery.py --held-race-order retry-first|cancel-first`, the first process pauses its unchanged proposal at the existing hook and records its ambient ownership lease. A separate SDK process submits the competing command through the normal actor/mailbox. Both pending admissions, actual protected FIFO order and unchanged model are retained before releasing the original proposal. The capture requires stale ownership to prevent that old proposal from advancing the model, then leaves both inputs to cold standard-host recovery. This checks same-model concurrent admission and fenced FIFO recovery; it does not manufacture two simultaneous provider transactions or bypass the protected queue.

`--consume-native-result` qualifies acknowledgment loss on the actual admitted ETL journey. It composes the existing ETL runtime/native adapter/persistence features using only the controller's original owned bindings and existing stores; it starts no background worker. When model cancellation is still owed, the production outbox processor queues its native Cancel command and its normal recovery mailbox commits the real terminal checkpoint. The processor delivers the original ETL-cancel source, queues the original native result without acknowledgment, and the normal protocol-aware recovery mailbox commits its exact model input receipt. The SDK requires the source to remain FailedRetryable afterward. It leaves native/model source acknowledgment to the standard hosts and seeds no persisted workflow state or fabricated domain result/receipt. Its receipt includes the actual delivery/drain results, original origin, model/native state, exact input/source and eight product identities. `--pending-cancellation-crash --consumed-before-ack-crash` leaves final acknowledgment and ETL terminal delivery to fresh standard Workbench hosts after process loss. Both public native-originated and model-originated cancellation use the same operation.

The controller's `--pending-parent-result-crash` additionally selects this operation for an actual cancelled outer RunBpmn parent. The live ownership marker must bind that parent ID, and it must equal the original model invocation's lossless ID. The SDK first delivers and consumes the original embedded cancellation, then follows the same worker/ETL cancellation and exact native-result consumption path. The model must remain TerminalPendingSettlement; its native parent return is left to standard hosts after a second process loss. This tool path alone is not a recovery qualification; accepted receipts must retain its actual coupled stores and subsequent fresh-host result.

`--consume-native-success <root> <model> <nonce> --parent-return-stage pending|consumed|settled` is the corresponding actual success path. It composes the existing activity runtime, CLR activation, Sequence/Flowchart/CompensationScope consumers and serialization/type registry, and records all fourteen SDK product identities. The live ownership marker binds the actual original RunBpmn invocation; its retained private state must match the model's parent document. After actual ETL/native success, the normal processor queues the native result and the protocol-aware model mailbox consumes it. `pending` leaves the parent source untouched. `consumed` delivers the original parent result and requires actual typed RunBpmn consumption. `settled` additionally drains the exact queued model parent-settlement command, retaining its accepted receipt while source ACK remains owed. Native workflow completion/successors remain independent native work and are finished by standard hosts after process loss. The controller's `--successful-parent-result-crash` captures and cold-recovers these distinct boundaries; see the [actual twelve-case qualification](../../../specs/1017-direct-bpmn-hosting/evidence/pipeline/successful-native-parent-return/README.md).

`--create-auth-probe-users` creates four ordinary password-backed Identity accounts with bounded stored roles through the existing user/role services. Its private controller request is deleted after setup; public output excludes credentials and cookies. The controller signs in through normal HTTP login before/after retry and after another host restart. [Actual authorization evidence](../../../specs/1017-direct-bpmn-hosting/evidence/pipeline/retry-authorization/README.md) retains role/tenant boundaries separately from focused GET authorization-order regressions.

`--probe-obsolete-result` requires the actual failed native result and its accepted receipt/source, plus one different live replacement for the same semantic invocation. The controller supplies that replacement's real HTTP429 wait and quiesces its owned Workbench while the SDK uses the normal model actor/mailbox. Exact original result bytes replay without changing the accepted receipt or revision3 replacement. A single changed fault code and a new input address for the unchanged old result both refuse before admission. Output retains every transported command, actual dispatch/refusal, full model/receipt/source after each probe and five product identities. No execution state is seeded. [Actual obsolete-result evidence](../../../specs/1017-direct-bpmn-hosting/evidence/pipeline/obsolete-service-results/README.md) includes coupled whole stores and subsequent completion/cold restart.

`--probe-pending-native-cancel` attempts the real cancelled native-worker result before its exact ETL cancellation source is delivered. It requires the original running revision1 model and independently Cancelled worker, verifies retryable refusal with no model/receipt/queue change, and leaves both original sources for normal cold-host recovery. The controller uses `--native-result-before-etl-cancel --native-cancel --pending-cancellation-crash`, directly or under a real native parent. This is an actual transport ordering probe, not a state seeder.
