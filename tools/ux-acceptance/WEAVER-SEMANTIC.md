# Opt-in external protocol observation

This separate `weaver-semantic` profile is source preparation under #3831 / Program #3428, **unrun**. The existing default composed journeys and [provider-unavailable inventory profile](WEAVER-INVENTORY.md) retain their own gates. Machine protocol evidence does not establish live-model reasoning, independent visual/UX approval, all story1 behavior, or whole T045 acceptance.

After integrating the owned `copilot_protocol.py` peer and the shipped API's current `activeSurface.route` admission, run from a clean committed checkout:

```sh
nice -n 10 python3 tools/ux-acceptance/run.py \
  --profile weaver-semantic \
  --output /absolute/new-semantic-output
```

The runner builds normal Workbench (`ElsaDashboardQualification=false`), frontend and Studio host. It copies tracked Development configuration into owned hosts and keeps normal admin seeding, login/token exchange, Studio bridge, feature Apply and shell readiness. Each appearance owns fresh SQLite/files, server processes and an external loopback `CopilotProtocolPeer(private_root, connection_token)`. Shipped `WeaverGitHubCopilot` options point the real pinned SDK at its `runtime_url`; only a generated connection token supplies connection auth. Local provider token/env/logged-in options are suppressed, host environments are allowlisted and SDK state is owned. No replacement provider, host fixture/bootstrap, publisher action, provider credential or purchase is introduced.

Four desktop/narrow light/dark appearances each run two browser executions. The first submits four ordinary composer turns: baseline; immediately after backend + EF and Studio deselection while still on Workflow definitions; after opening structured logs; unknown route with an explicitly absent module. The second submits one turn after a clean backend stop, actual root ExtensionBuilder switch/restart, Studio Apply and native root-route readback. Every question names the actual `structured-logs`, `extension-builder` and `absent-module` IDs and a generated benign nonce. Only the unknown-route question also asks about the current route, without spelling its path. Expected native states and answers are never supplied to the peer.

Private `weaver-semantic.json` retains the actual POST body, session/client request/accepted message identities, admitted context, completed assistant DOM and server readback, and pre/post native generation. `semantic_verdict` joins these to detached private `turn_records` using nonce, actual SDK session, payload/user-request/response hashes, JSON-RPC request ID and SDK message identity. RPC integer IDs may repeat across connections; distinct payload/message identities and nonces remain required. The peer's actual admitted metadata must match `Elsa.Weaver` / `weaver.host-support` / schema1, with `ClientSnapshot` Studio claims and `AuthoritativeRead` backend session hints. Canonical projected content is compared, allowing JSON property/row order and optional null differences, without equating raw browser JSON with sanitized admission. Route evidence must come from actually admitted Studio `activeRoute` and match the captured POST, never historical session metadata or the question. Unknown-route turns admit only host support and carry no resource target/owner. Backend module identity is never inferred from Studio names or prefixes.

Native feature selections, complete registry rows, root route, full desired state/configuration preservation, generation stability and unrelated package identities are checked independently of the service. Successful correlation requires exactly 20 physical turns over eight exact browser executions, no duplicates/retries/skips, complete transport delivery, and a response equal to both the recorded and completed rendered assistant. The peer derives its response from actual admitted support; no expected phase is an input.

Public phase evidence contains named PNG/ARIA captures taken with the assistant closed, `weaver-semantic.json` (native allowlist plus correlated hashes/counts), bounded `weaver-interaction.json`, a projected Playwright report and `safe-export.json` hash manifest. Prompts, responses, nonces, raw session/message IDs, private configurations, auth, logs, transport and original traces stay private. Every selected byte is scanned before any export write, on success and failure. Per-appearance `protocol.json` selects only the peer's `targetSdkVersion`, protocol version, counters, hashes, wire completion and clean-close counts. Five turns and zero live threads/connections/errors are required; clean close alone is not acceptance. The runner joins that final safe snapshot back to every phase correlation.

The peer interface is a context manager with `runtime_url`, immutable detached `turn_records`, `safe_receipt()`, `close_receipt` and `assert_healthy()`. New fields cannot silently enter exported peer receipts. Build commands are bounded to 15 minutes each, browser commands to five minutes each (four-minute test budget); owned process groups use the existing termination cleanup. Existing composed CI budgets this as a separate step/artifact in the same job. Timing, product behavior, socket compatibility and authored synthetic regression controls all remain **unrun** until exact-source CI. Failure stops qualification; absence of observed transport/route/admission facts is never converted into a canned answer.
