# Opt-in normal-host Weaver inventory

This prepares the shipped-host inventory part of spec1203/T045 under leaf #3831 and Program #3428. Source preparation is **unrun**. It does not mark T045, the broader T044 gate, independent UX acceptance, the package witness, or Program acceptance passed.

User goal: identify installed and deselected modules from the actual Studio registry/loader and selected Workbench's support observations, then enable ExtensionBuilder without mistaking shell selection for root-host activation. Reference: the existing Modules/Features settings and Workflow definitions screen, using the existing composed runner's captures, accessibility snapshots and Playwright trace lifecycle. See [Studio UX acceptance](../../docs/contributing/studio-ux-acceptance.md).

The default command and its Copilot-disabled dashboard/native profile retain their existing journey inventory. Explicitly opt in from clean committed source:

```sh
nice -n 10 python3 tools/ux-acceptance/run.py \
  --profile weaver-inventory \
  --weaver-witness-root /absolute/retained-same-source-qualifier \
  --output /absolute/new-private-inventory-output
```

The witness input is the existing `Weaver.Conformance.Probe/qualify.py` report with its passed `authors.protocol` receipt, locked package-only author graph, packed `Acme.Weaver.ProtocolFixtures` and retained dependency archives. The report, author and normal source hosts must have the exact same source SHA. No private consumer profile, developer configuration, user secrets or installed cache discovery supplies inputs. The runner does not invoke the package qualifier, materialize an external Workbench consumer, pack a replacement fixture, or call a live model.

The actual Workbench and Studio projects build from the checkout. With the witness supplied, their private qualification build uses the witness's `Version`/`PackageVersion` and source revision in Release configuration. This avoids treating an unversioned development assembly as a package-admitted candidate; no committed version line or publisher changes. Actual deployed host hashes and CLI MVIDs are retained separately from independently packed candidate image identities in each phase's projected `composition.json`. Different source-built and independently packed bytes are not presented as identical. The existing locked-graph archive selector validates exact host-provided dependency versions, then genuine archives enter the owned Workbench's ordinary Nuplane directory feed and feature discovery. The selected actual provider is Copilot with the external factory fixture in observation mode. The Anthropic dependency may be present in that genuine closure but its provider and fixture features are never selected. Native loaded-package and runtime-descriptor observations, plus an actual provider request/observation, are required to establish admission; a prepared configuration does not establish it.

Each desktop/narrow and light/dark appearance gets a fresh owned host pair. The baseline journey records complete native Studio discovery and selected backend support, retains a discovered disabled ExtensionBuilder row, deselects structured logs' backend and EF features together through native Apply, and independently deselects its Studio feature. It reloads the structured-log route, then an unknown route. Discovered deselected rows must remain disabled rather than becoming inferred installation absence. The same appearance's backend must then exit cleanly before the runner flips the owned root `Elsa:ExtensionBuilder:Enabled` switch and starts it again. The second journey enables only Studio through native Apply and opens ExtensionBuilder. The root capability route is observed with ordinary bearer authority denied; Studio's normal management bridge uses a generated run-owned server key that never enters browser configuration or receipts.

Named states are `reference`, `inventory-baseline`, `inventory-deselected`, `inventory-unknown`, and, after restart, `reference` and `inventory-enabled`. Every state retains PNG/ARIA evidence. The feature-specific JSON records native state, bounded network method/path/status facts, authority attribution, backend-admitted support and the actual adapter request payload. The fixture emits a fixed observation sentence and supplies no semantic module answer. The driver compares actual typed host-support contents across admission and provider boundaries. It requires complete loader/registration observations and an unrelated loaded Workflows module; route-only unknown context must carry no invented resource context. A failed request, missing capture, duplicate/missing appearance or state, retry, skip, missing native package admission, missing admitted context, or non-observation provider turn fails the gate.

Without `--weaver-witness-root`, the same opt-in command prepares the independent registry, selection, root restart and capture work, but it ends **incomplete** with a failing provider-admission gate. Such output does not establish loader/context/provider disclosure. Ordinary Nuplane composition of this external fixture in the actual source-built Workbench remains unproven until this new profile executes successfully. A native admission failure must retain its concrete package/version/runtime failure rather than be replaced by package-consumer evidence.

The runner keeps raw Playwright/protocol traces, original reports, server/browser logs, private configurations and synthetic server credentials in its owned temporary root, outside `--output`. Raw originals can contain login bodies, bearer headers, cookies, browser storage and seed data; they are removed during owned cleanup. No recursive copy or generic attachment copy selects them for export. Each exported phase contains only named post-login PNG/ARIA captures, an allowlisted inventory projection, a bounded network/interaction projection, projected source/assembly/package identities, a projected Playwright report and an explicit `safe-export.json` byte-hash manifest. Raw provider prompts and message bodies are replaced by hashes and metadata, preserving the actual admission comparison's private provenance. The interaction artifact explicitly says it is a projection and does not claim raw-trace inspection or sharing. The gate verifies the export's file inventory and hashes again.

The exporter validates all selected bytes before its first output write on both success and failure. Known run secrets, seed password, bearer/header/JWT patterns, private filesystem paths and authentication-surface accessibility text refuse export. Unlisted raw attachments never enter its file plan. This source adds negative controls for those refusals and post-export tampering; they remain **unrun**. Runtime export success, exact-source screenshots and independent review are still required before claiming downloadable UX acceptance. Machine assertions never grant visual approval. The default UX baseline's existing trace contract is unchanged.

The independent module's nested-contribution removal belongs to the packaged probe, as do the fixture's effect, policy, review and result journeys. This shipped inventory profile does not substitute for them or claim live-provider evidence. Loading/failure/denied states beyond the explicit authority-denied root read require separately named journeys; source preparation does not silently qualify them.
