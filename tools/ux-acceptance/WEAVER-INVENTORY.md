# Opt-in shipped-host Weaver inventory observations

This source prepares the normal-host portion of spec1203/T045 under leaf #3831 and Program #3428. It remains **unrun**. A successful machine run establishes only its native inventory, selection, root restart, provider-unavailable boundary and named captures. Weaver's semantic answers, Studio loader/context and backend-admitted/provider disclosure remain unverified; full story1/T045 and independent UX acceptance remain incomplete. Deterministic fixture scenarios stay in the existing packaged probe. Optional FR024 live-provider evidence is not claimed or purchased.

User goal: distinguish installed and deselected modules from native Studio discovery and the selected Workbench's support observations, then enable ExtensionBuilder through its actual root-host restart boundary. Reference: the existing Modules/Features settings and Workflow definitions screen. Follow [Studio UX acceptance](../../docs/contributing/studio-ux-acceptance.md) for current-source visual evidence and independent review.

From a clean committed checkout, explicitly opt in:

```sh
nice -n 10 python3 tools/ux-acceptance/run.py \
  --profile weaver-inventory \
  --output /absolute/new-inventory-output
```

The profile builds the actual Workbench with `ElsaDashboardQualification=false`, the normal Studio frontend and the normal Studio host. It adds no test bootstrap, readiness endpoint, provider, package fixture, version override or consumer composition. It uses the shipped development admin-seeding configuration, native sign-in/token and Studio bridge authorization, the shipped `/health/live` and `/health/ready` endpoints, and actual shell generations. Owned configuration changes only local origins, disables the shipped Copilot provider, and supplies a generated run-owned server management key. The key stays on the server processes and never enters browser configuration or export receipts. No developer configuration, user secret, credential cache or existing listener supplies state.

Each desktop/narrow and light/dark appearance gets fresh owned stores and host processes. The baseline records native Studio discovery, backend feature selections and sessionless Weaver support. It deselects structured logs' backend and EF features together through native Apply, then deselects its Studio feature independently. Every Apply sends the complete desired feature state, including all retained enabled configurations and native secret placeholders; native readback must preserve unrelated selections/configurations. Discovered deselected modules must retain disabled rows rather than become inferred installation absence. The journey opens the deselected structured-log route and an unknown route. These route observations do not establish route-only provider disclosure while the provider is unavailable.

The same appearance's backend must exit cleanly before the runner flips the owned root `Elsa:ExtensionBuilder:Enabled` switch and starts it again. The second journey enables Studio independently through native Apply and opens ExtensionBuilder. An ordinary bearer read observes the root capability route's authorization boundary. Shell Apply alone cannot register the root subsystem.

At every named state the driver reads the actual Weaver bootstrap, opens Weaver with keyboard interaction, and checks the unavailable status and disabled composer/send controls. It records the intended question and its unanswered/provider-unavailable state without substituting an answer or submitting a fake request. Neither native discovery's `complete: true` nor sessionless support's `completeness: complete` is treated as an admitted Studio support snapshot or provider output. Machine success for these native observations never means story1 was answered or T045 accepted. A live provider's absence alone does not make the bounded native-observation machine gate fail.

Named captures are `reference`, `inventory-baseline`, `inventory-deselected`, `inventory-unknown`, then `reference` and `inventory-enabled` after restart. Missing states/captures, duplicate or missing appearances, retries, skips, unexpected request failures, incomplete discovery, lost selections/configurations or an unclean backend stop fail the machine gate. The default composed UX suite and isolated gallery remain separate gates; this profile does not replace them.

All build/frontend/server/browser logs, original Playwright reports/traces, private configurations and seed/auth data stay in the owned temporary root outside `--output`, including failed runs. No isolated gallery runs in this profile. Before cleanup, exported fixed classifications retain native HTTP status/category, feature selected/runtime facts, package status, shell readiness/generation, process exit code and bounded compiler/NuGet error codes where available. Arbitrary error messages, bodies, configuration values, credentials and private paths are not exported.

The explicit export contains only named post-login PNG/ARIA captures, allowlisted inventory and bounded interaction/network projections, a projected Playwright report and a `safe-export.json` byte-hash manifest. Raw trace originals are represented only by their private-scope hash and are removed on owned cleanup. The interaction artifact says it is a projection and does not claim raw-trace inspection/sharing. Every selected byte is checked before the first export write on success and failure; known run secrets, seed password, bearer/header/JWT patterns, private paths and authentication-surface accessibility text refuse export. No generic attachment or recursive copy can publish originals. The gate rechecks the export file inventory and hashes. Source privacy and state-regression tests remain **unrun**; exact-source execution and independent capture inspection are still required.

Independent nested-module removal, effect/policy/review/result scenarios and deterministic provider-protocol proof remain in their assigned probe journeys. No product/core/provider/host contract is added by this profile.
