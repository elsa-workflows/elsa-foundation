# Elsa.Etl.Persistence.EntityFrameworkCore

EF Core stores for ETL design (drafts and immutable published artifacts) and the ETL runtime (runs, partitions, batches, outputs and terminal delivery). The package depends only on EF Core and its relational layer; a host brings the provider package for its engine.

- **Features:** `EtlDesignEntityFrameworkCore` and `EtlRuntimeEntityFrameworkCore`, each with its own context, schema family and migration history. They register no event handlers or tasks.
- **Design store engines:** SQLite, SQL Server, PostgreSQL and MySQL ([spec 1202](../../../../../specs/1202-etl-design-store-providers/spec.md)). The `Provider` setting selects the engine's context; key columns use the engine's binary collation; publication retries a transient write conflict (a serialization failure, a deadlock, a lock timeout or a busy or locked SQLite database) as a whole unit; a draft update retries its one conditional statement, and every store and catalog read outside a publication attempt retries, the same way.
- **Runtime store engines:** the schema exists on SQLite, SQL Server, PostgreSQL and MySQL ([spec 1203](../../../../../specs/1203-etl-runtime-store-schema/spec.md)). On the server engines a run's key is a 64-character hash of its id, which `RunId` keeps in full, and a row whose key is not its id's hash is refused; check constraints are written once and rendered per engine (`EtlRuntimeConstraintDialect`). Runtime registration selects all four engines after the store concurrency controls in [spec 1206](../../../../../specs/1206-etl-runtime-concurrency/spec.md); the native Flowchart → JSONL ETL → Done journey and completed-state host restart pass with both stores on each server engine ([receipts](../../../../../specs/1206-etl-runtime-concurrency/evidence/workbench-journey.json)). Mid-work crash recovery, old-writer recovery and Studio remain separate proof. The runtime's server migrations are generated with `tools/etl/generate-etl-design-migrations.sh <Name> <Provider> runtime`.
- **Migrations:** the SQLite design and runtime chains under `Migrations/Sqlite` are hand-maintained. The server engines' design migrations under `Migrations/EtlDesign/<Provider>` are generated as internal classes with `tools/etl/generate-etl-design-migrations.sh`, which uses the `Elsa.Etl.Tooling` design-time project.
- **Tests:** the design-store contracts run on SQLite in `Elsa.Etl.Tests` and on the three server engines in the `etl-ef` container suite (`Extensions/Etl/tests/Persistence/ProviderTests`).

Runtime store operations use one bounded retry budget for the complete database transaction and release failed transaction/tracking state before another attempt. They refuse caller-owned transactions before mutation. Terminal infrastructure failures become Core `EtlStoreException`, retaining the operation, known scope/run and original cause; cancellation, validation/corruption and schema refusal remain distinct. Physical connector I/O is outside this database retry boundary. Existing schemas, migrations, authoring/state shapes and the SQLite default are retained.
