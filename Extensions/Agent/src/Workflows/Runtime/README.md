# Runtime-side workflow contribution to Weaver

This optional server module lets Weaver explain one exact, immutable workflow Executable. The Executable Inspector names an Executable by its artifact id and the Artifact Hash it shows; the server reads it through Workflows Runtime Core (`IWorkflowExecutableInspection`) under the host's `workflows/runtime:read`, refuses a read whose hash differs as stale, and `workflow_read_executable` returns its identity, Artifact Hash, compiled graph (input binding names, never values) and the Source References that point at it. Nothing is ever changed.

It also lets Weaver explain one exact Run. The run page names a Run by its Workflow Instance identity and the activity execution selected there; the server reads it through Workflows Runtime Core (`IWorkflowRunInspection`) under the same permission and the run endpoints' own per-run authority, and `workflow_read_run` returns its instance and Executable, status (a Run still executing is attributed to its read time), recorded incidents, a page of activity executions and the selected execution's value evidence. A withheld value stays withheld, and so does any sensitive value (even one a capture policy captured) and any incident message that could echo a sensitive input, another Run's data or a handler's exception text, and the state view of an activity with a sensitive input, so Weaver never sees values the run page itself can show; unavailable data is reported by reason (not captured, pruned, not provided by this backend, not permitted), and retry, cancel, delete and dispatch stay with the run page's own controls.

The package references Agent, Agent Core and Workflows Runtime Core only, so it composes in a Runtime-only host, where Design journeys are explicitly unavailable; the Design-side workflow contributions live in [`Elsa.Agent.Workflows`](../Elsa.Agent.Workflows/README.md). Select the shell feature `FoundationWorkflowsRuntimeAgent`. See [the module extension-point catalog](EXTENSION_POINTS.md).

## Cross-domain contributions

This package contributes to [Agent foundation](../../Elsa.Agent/EXTENSION_POINTS.md) through `Elsa.Agent.Core`: two `IAgentContextProvider`s (`workflows.executable-context` and, from slice G, `workflows.run-context`), two `IAgentTool`s with `IAgentToolAuthorization` (`workflow_read_executable` and `workflow_read_run`) and one `IAgentCapabilityProvider` (`workflow.executable-explain` and `workflow.run-explain`). It consumes Workflows Runtime Core's [`IWorkflowExecutableInspection` and `IWorkflowRunInspection`](../../../../../Essentials/src/Workflows/Runtime/Api/EXTENSION_POINTS.md) and registers no fallback for either. See [the module extension-point catalog](EXTENSION_POINTS.md) for each contribution's admission, bounds and refusals.

## Upgrade requirement

Studio's Executable Inspector sends its `workflows.executable` context whenever an Executable is shown, and the run page its `workflows.run` context whenever a Run is shown. The inspector is only routable when the backend offers the Workflows Runtime API, but Studio cannot see which Weaver modules the backend composed: a host that composes the Workflows Runtime API and Weaver must also select `FoundationWorkflowsRuntimeAgent`, or every Weaver turn on those pages is refused as `agent.context.kind_unsupported` ("No installed module admits the supplied context kind and owner."). The Workbench and the Docker compose shells select it.
