# Decisions API

`DecisionsApiFeature` contributes capability `elsa.api.decisions` v1 with relation `decisions` and maps the normal endpoint catalog under `/decisions`. It depends on Decisions Design and the host's canonical capability/identity composition. The eight grants are owned by `DecisionPermissions`: read, manage, publish, evaluate, test, history, source and sensitive-values.

The caller is the single trusted normalized identity with exactly one nonblank canonical Elsa tenant ID and persisted user ID. Raw `tenant_id`, `sub` and NameIdentifier aliases never select persistence scope or operation ownership. Every request rechecks the canonical permission evaluator; cached browser capabilities are discovery only. The principal-backed access policy is a cross-domain consumption of Foundation Identity's public permission contracts and preserves an explicitly installed host replacement.

Inventory/detail return metadata and disclose XML only with Source plus sensitive-value access where applicable. Published evaluation requires Evaluate and protected-output permission, independent of Source/Test/History. Manage does not grant Publish. Saved cases and tests require their explicit grants. Error responses contain safe codes/messages without XML, cell or input fragments. The request body is bounded even when Content-Length is missing.

The routes cover create/update, validation, immutable publication/versions, clone-to-draft, exact published evaluation, XML export, saved-case CAS, synchronous tests, history and history deletion. API models live in `Elsa.Decisions.Design`; list responses wrap `items`. Decision numbers retain Core's exact tagged decimal-text representation; dictionary keys retain their casing. Test comparisons carry the evaluator's actual matched/selected rules and cell traces. Summary-only history never reconstructs raw values from current cases.

No task or event handler is registered. Permission contributions are aggregated by Foundation Identity's existing catalog. Endpoint/capability contribution uses the existing Api/Minimal Endpoints infrastructure. See [extension points](EXTENSION_POINTS.md) and the [lifecycle contract](../../../../specs/1195-business-decisions/contracts/lifecycle.md).
