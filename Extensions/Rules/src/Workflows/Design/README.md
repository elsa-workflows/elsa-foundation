# Rules Workflows (Design)

`RulesWorkflowsDesignFeature` registers an `IExecutableCompilationSource` contribution for `RunRules` with `TryAddEnumerable`. The shell feature depends on `RulesRuntime` and `WorkflowsPublishing`; it does not replace the host's publishing composition. The contributor accepts only the bounded literal `Program` value, uses the runtime's artifact compiler, and captures the trusted implementation identity once during publication. It stores the canonical artifact, source hash, validated vocabulary count and semantic pin in executable node metadata. Runtime consumes those frozen publication values without depending on this Design package, querying mutable design storage, or performing a later package selection.

The published pin is an integrity-covered claim; it cannot authorize runtime to recompile or repin an admitted invocation. Direct and native invocations freeze their facts and resolved positive round budget separately. See the [Runtime README](../Runtime/README.md), [Rules quickstart](../../../../../specs/999-durable-rules/quickstart.md), [artifact-only runtime glossary entry](../../../../../docs/glossary/elsa.md#artifact-only-runtime), and [package identity contract](../../../../../specs/999-durable-rules/contracts/package-identity.md) for the shared publication and recovery rules.
