# Elsa.Rules.Runtime

`RulesRuntimeFeature` registers the finite evaluator, complete round/admission validators, `IRuleInvocationFactory`, `IRuleArtifactCompiler`, a trusted deployment identity reader and one bounded worker per service provider. It uses the existing Tasks lifecycle for shells and `IHostedService` for plain hosts; both resolve the same idempotently started worker. A plain host waits for application startup, after migrations, before polling. Shell Tasks activation already follows Prepare-phase migrations. Cancelling an activation call does not cancel an activated worker. Shutdown requests cancellation and waits for actual attempt tasks to unwind.

The direct entry point is `IRuleInvocationFactory.PrepareAsync`: it snapshots initial facts, encodes the immutable artifact, resolves an omitted round limit and captures the installed implementation pin once. Retain its returned envelope for `IRuleRunStore.AdmitAsync`, cancellation and retries. Do not prepare a replacement envelope to retry an old invocation. Read results with `IRuleRunReader.ReadTerminalAsync`; command confirmations carry no successor payload.

The worker claims one durable responsibility per attempt. A new round uses one frozen input, including all applicable firings; acceptance and consumption remain separate store commands. Accepted common receipts can be consumed without the old interpreter. Further evaluation requires the exact verified pin. A successful attempt releases its live lease; interruption leaves it recoverable by database-time expiry. Late work cannot commit through an expired or replaced lease. The computation and native-delivery workers share an internal Rules lifecycle implementation and retain separate concurrency controls.

The default identity source reads the host-selected absolute `HostDepsPath`, `DeploymentReceiptPath` and `HostRoot`. Its receipt schema is `{ "receiptSchemaVersion": 1, "pin": ... }`, with the canonical pin fields defined in [package identity](../../../../specs/999-durable-rules/contracts/package-identity.md). It validates the active dependency target, package IDs/versions, any supplied NuGet content hashes, selected asset paths and the full names and file SHA-256 values of the default-context loaded semantic assemblies. Each of the three required Rules packages must identify its actual executing assembly. Paths and reads are bounded; no package download or assembly loader is introduced. The validated pin, or unavailability, is snapshotted for this provider generation. Changed deployment evidence requires a new provider generation. Empty paths, source-project entries, missing files and mismatches are unavailable; there is no source-build identity fallback. To qualify a changed deployment, use the [package and retained-upgrade commands](../../../../specs/999-durable-rules/quickstart.md) and retain the generated receipts; ordinary source-host tests do not establish package provenance.

The feature preserves host registrations made before it through `TryAdd`; normal later registrations can replace `IRuleImplementationIdentitySource`, `IRuleInvocationFactory`, `IRuleArtifactCompiler`, `IRuleAdmissionValidator` and `IRuleRoundValidator`. Replacements own their respective trusted contracts. `AcceptNewInvocations = false` disables new admission through the default validator; the store checks retained identity/replay first, so exact existing admission replay, cancellation and recovery remain available. It does not stop workers or discard accepted receipts. Operational settings bound concurrent attempts (1–64) and idle polling (10–60000 milliseconds). They do not change model budgets or persisted identities.

Focused tests run the actual features, migration lifecycle, SQLite store and worker in pooled and nonpooled hosts. Their injected pins and synthetic dependency manifests are not NuGet provenance proof. The accepted package consumer, PostgreSQL process recovery and A→B→A retained-run proof are recorded in the [package/Workbench checkpoint](../../../../specs/999-durable-rules/evidence/package-workbench-checkpoint.md), [process checkpoint](../../../../specs/999-durable-rules/evidence/process-checkpoint.md), and [retained-upgrade checkpoint](../../../../specs/999-durable-rules/evidence/retained-upgrade-checkpoint.md); native persisted retry and proof-before-acknowledgment are recorded in the [native recovery checkpoint](../../../../specs/999-durable-rules/evidence/native-recovery-acceptance-checkpoint.md). These are bounded acceptance results, not multi-machine or external exactly-once guarantees. The [quickstart](../../../../specs/999-durable-rules/quickstart.md) owns current commands and remaining integration gates. This domain-specific worker is not a general task runner, pause policy, or queue-control product; see the [future worker-layer boundary](../../../../specs/999-durable-rules/plan.md#future-worker-layer).
