# Elsa.Rules.Persistence.EntityFrameworkCore

This project owns the EF Core mapping for Rules durable runs and their append-only receipt and fact history. The context depends on the Rules provider-neutral persistence contracts and shared EF persistence infrastructure; inference and receipt semantics remain in `Elsa.Rules.Runtime`.

The current provider context is SQLite. This is an initial implementation slice, not four-provider qualification. The module declares its own migration-history identity and schema family, so later migrations can coexist with the host's other EF modules. The SQLite Initial migration and model snapshot are retained here; schema creation goes through the shared migration lifecycle, and tests and hosts must not use `EnsureCreated` as a substitute. The nonpackable Rules migration host lives in `Extensions/Rules/src/Tooling`; use `bash tools/rules/generate-rules-migrations.sh <MigrationName>` to add a migration without replacing existing history.

The run row keeps a lowercase digest as its indexed key and retains the complete framed identity for exact equality checks. `ModelRevision` tracks semantic progress; `ConcurrencyToken` is a provider-level optimistic concurrency token. Round receipts retain logical semantics separately from the first accepted physical attempt, and fact history uses an integer position rather than database atom collation.

The internal store currently implements admission, deterministic refusal, cancellation and bounded status/terminal reads. Identity-first replay does not require the old interpreter. Terminal state and any frozen native delivery are committed in the same Rules transaction. This partial slice is not registered as the complete public store: worker leases, round acceptance/consumption, progress paging and delivery settlement remain pending.
