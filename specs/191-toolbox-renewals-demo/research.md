# Research decisions
- Existing Notes sample supplies EF provider selection, two releases, migration validation, schema-family chain and finalization patterns.
- Foundation.Host deliberately has no authoring or identity feature implementations; all required Elsa features must arrive through Nuplane.
- The prior authoring fixture is incomplete for authenticated Studio. Portable vendor store binding/bootstrap must be packaged, not placed in Host.
- ActivityVersionId pins a catalog contract. A new NuGet release does not change the workflow's selected contract; optional additive inputs permit the original contract to keep executing on the loaded implementation.
- Fleet readiness uses durable membership, actual readable schema declarations and the shared finalization gate.
- Elsa Cloud's actual scoped marketing/application CSS uses IBM Plex Sans/Mono, white/offwhite surfaces, near-black ink and #D6006A accents. Legacy generic root tokens in its CSS are not the active marketing theme.
