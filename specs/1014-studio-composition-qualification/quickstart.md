# Validation quickstart

From the repository root, use the existing supported .NET10/native profile, built committed Studio producer frontend inputs, Python and the Studio Playwright browser. Consumer frontend tools are denied; producer and browser driver tooling are separate.

1. Run the new native endpoint-filter regression against the original product; require an actual enrolled package/result replacement and later-request failure. Restore the correction and require the same case plus the whole Studio suite to pass.
2. Run `python3 tools/studio/Composition.Probe/qualify.py` after implementation. Retain actual candidates, private lock/cache, published consumers and all four composition reports.
3. Run its documented missing-module-asset and disabled-auto-reload controls, require their precise failures, then restore originals and rerun normally. Native refusal or unrelated process/restore failures do not count as expected controls.
4. Inspect real custom contribution/deep link/assets and shared runtime; omitted addon routes/services; cold auth/status/header observations; actual generation and pre/post console markers; persisted theme/material/default state and unchanged directory source after restart.
5. Verify affected whole suites/discovery, architecture/maps, exact reviewed head and actual main. No release/deployment/publisher is activated by any command.

CLI flags, final measured outcomes and exact artifact roots are recorded in the tool README/validation evidence as implemented. Existing independent Api/Hosting qualifications remain documented in their canonical READMEs.
