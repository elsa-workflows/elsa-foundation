## Phase 3: User Story 1, use a stored secret in a workflow (P1)

**Goal**: A `Secret` binding resolves at CLR activation for the execution's tenant, re-resolves on every activation, never enters persisted state, and is refused at publish on every activity kind that reads inputs outside the activator and on every input an activity persists or a publish-time reader needs as a literal (research R3a).
**Independent test**: Run a secret-bound test activity, rotate, suspend and resume, and run two tenants; the activity always sees its own tenant's current value, and persisted rows hold only the withheld envelope (A01 to A04); `SendHttpRequest` sends a secret as its `Authorization` header to a local endpoint (A23).
