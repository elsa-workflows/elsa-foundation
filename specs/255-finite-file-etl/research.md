# Research and source decisions

**Status:** Reviewed design. The native checkpoint seam is source-verified; bounded ETL host execution is implemented; native/API/Studio and two-process acceptance remain open. Optional `Elsa.Etl` is adopted in [ADR-0087](../../docs/adr/0087-etl-owns-its-execution-domain.md) under the owner's delegated self-review/approval authority.

**Scope:** Research for the finite CSV-to-JSONL slice in [spec.md](spec.md), not a general ETL architecture. The parent #2908 remains open. No throughput target, new actor provider, HTTP/SQL/RabbitMQ connector, BPMN invocation, or fourth-model qualification is implied.

The cited native source establishes extension points and transaction boundaries, not delivered native ETL integration. The ETL store owns its run, partition, quota, manifest, terminal-result, and terminal-outbox transactions. It is not part of the workflow checkpoint transaction; the durable intent bridges the stores. No distributed transaction or exactly-once physical effect is claimed.

The proposed package set is `Elsa.Etl.Core`, `Design`, `Runtime`, `Persistence.EntityFrameworkCore`, `Api`, `Workflows.Design`, `Workflows.Runtime`, and `Elsa.Studio.Etl`, as detailed in ADR-0087. Keep only demonstrated shared contracts in Core; add no standalone connector or provider package without a real consumer/deployment boundary.

## Chosen runtime boundaries

Workflow publication pins the ETL artifact identity/hash, finite topology, and host binding aliases. It does **not** pin current file content. At run admission, the host resolves source and lookup aliases to immutable revisions with host-supplied expected SHA-256 values. ETL copies those revisions into retained, content-addressed run snapshots and verifies the hashes before creating dispatchable partitions. A binding without a stable revision or expected hash is not eligible. A missing revision, missing expected hash, or content mismatch refuses admission. Once retained, changing the original configured file does not change or invalidate an existing run; substituting the retained run snapshot does.

This requires the host binding contract to return a stable immutable revision. Hashing a copy of an arbitrary concurrently changing path does not prove which logical revision was copied and is insufficient. Authored ETL definitions contain only approved alias identifiers; host paths and credentials remain in host configuration and authorization.

The finite source is parsed/indexed as logical CSV records and divided into stable, disjoint, exhaustive contiguous ranges. At least two non-empty partitions are leased independently. A durable per-batch reservation is created before dispatch; retries reuse it rather than creating new owed quota. Batch and output identities are derived from the run, pinned artifact and snapshot identities, partition, and record range. Lease/worker identity is excluded.

Workers write bounded JSONL to attempt-private staging, flush/close and verify complete hashes, then atomically publish immutable chunks without overwriting final keys. An interruption mid-write leaves staging, never a partial final chunk; cleanup requires the writer to have stopped. Output destination revisions are pinned per run so retargeting an alias cannot redirect recovery. The authoritative run manifest lists accepted chunk hashes in stable logical order; its entries are updated in the same ETL-store transaction as batch acceptance, cursor advancement and quota settlement. There is no shared concurrent append. A worker must present the current partition fence and expected cursor for acceptance. A stale task may finish physical I/O, but cannot make a chunk authoritative or mutate state. Matching complete chunks replay by hash verification; conflicting content faults. Physical effects remain at least once.

Worker-local record and byte permits are held until the actual task unwinds. Lease expiry does not release them or prove the old task stopped. A retry after takeover reuses the durable batch reservation but must acquire its own local permits; aggregate memory/heap use is not inferred from the durable byte budget.

One ETL transaction wins the terminal compare-and-set and writes the terminal outbox item. Each send uses the same delivery identity and may be repeated. The native workflow applies a terminal trigger once and maps it to a distinct success, business-error, fault, or cancellation outcome using the existing stateful-activity transitions. Sequence and Flowchart keep their normal composition behavior.

## Alternatives rejected for this slice

- **ETL under `Elsa.Pipelines` or as a workflow composite:** middleware pipelines compose messages; workflow composites compose activities. Neither owns dataset schemas, run identity, leases, record cursors, or file effects.
- **A workflow or actor per record/batch:** this would turn finite data volume into workflow/actor lifecycle overhead and would put ETL cursor/effect semantics in unrelated orchestration state. ETL owns one run and its partitions.
- **Run the ETL from a long post-commit handler:** the current outbox processor may redeliver a handler that exceeds its visibility timeout. The handler should create/reconcile durable ETL work, not hold a lease while processing a file.
- **Append directly to one shared output file:** there is no transaction spanning file append and durable cursor advancement. Immutable chunk writes plus a manifest make accepted output and retry identity explicit; an interrupted append is not mistaken for accepted output.
- **Treat lease timeout as process termination:** a timed-out worker may still hold buffers or finish I/O. Durable fences protect acceptance; local permits protect each live worker process.
- **Adopt an actor provider or universal connector API now:** the built-in native host is already qualified for this slice. Orleans remains optional/deferred, no Proto.Actor spike is required, and a connector abstraction should wait for a real independently selectable connector.

## Remaining implementation evidence

The source seam is verified, but integration proof remains required: cancellation before ETL admission; a `BookmarkCreated` commit carrying the ETL start intent; post-commit replay; frozen/versioned trigger diagnostics; execution-node and tenant/partition binding checks; repeated terminal sends with one accepted parent continuation; and two workers recovering real durable partitions across effect-before-cursor interruption. Source/lookup binding adapters must demonstrate stable immutable revisions and expected-hash enforcement. These are implementation gates, not product questions in this spec.

## Native adapter integration checkpoint

The [suspension projector](../../Essentials/src/Activities/Runtime/Elsa.Activities.Runtime/Services/StatefulActivitySuspensionProjector.cs) assigns actual registration IDs while persisting `ActivitySuspended`; the [invocation handler](../../Essentials/src/Activities/Runtime/Elsa.Activities.Runtime/Services/WorkflowInvokeActivitySchedulerWorkHandler.cs) then queues the corresponding bookmark work. There is no activity-facing bookmark-ID allocation API. Do not copy the internal attempt/index ID formula into ETL. Private state freezes the run, artifact, trusted scope/parent/executable/node and expected typed trigger fields. Both admission and pre-consumption cancellation combine it with exactly one matching persisted ETL trigger registration; admission additionally verifies the actual committed bookmark. The existing cancellation planners preserve private state/registrations, and delayed bookmark work refuses canceled/stale activity state. A typed native claim atomically retires the live registration and records a consumed delivery; subsequent cancellation must recover the real registration from that receipt, including after its payload is retired, rather than requiring a live wait or guessing an ID.

The workflow hasher includes literal input bindings but deliberately omits node metadata. Publication therefore uses a canonical `EtlPublishedSelection` literal containing definition ID, version and the full content hash, alongside the bounded artifact in ETL-owned node metadata. Runtime compares the retained artifact to the hashed literal. This needs no generic hash-format change or ETL-as-workflow dependency edge. ETL's shared internal document codec preserves exact opaque identity code units through native private-state/outbox JSON while retaining the existing EF v1 bytes.

BPMN CallActivity already composes through ordinary native child activity completion. Its DispatchWorkflow staging buffer/custom checkpoint specialization is not an ETL template: the ETL adapter uses checkpoint enrichment and per-kind durable intent handling instead. This finite-file slice does not add BPMN invocation or change BPMN execution semantics.

## Durable native composite checkpoint

The real SQLite journey exposed a generic callback-correlation gap in CompensationScope: a typed bookmark resume command carries delivery metadata rather than the child's original scheduling metadata. The ETL child completed and its outbox was consumed, but the scope read the resume command and silently deferred forever. The child's committed `ActivitySchedulingProvenance.Metadata` retained the exact scope/role/step. Completion/fault callback contexts now expose an immutable `ChildSchedulingMetadata` snapshot from that persisted child; the old constructors remain available and no command metadata is merged or reinterpreted. CompensationScope reads the snapshot. The [checkpoint](evidence/native-composite-checkpoint.md) records the retained failure, regression-removal check and actual scheduler proof.

The fixture stores a runtime executable through the normal publication/start helpers and invokes the actual ETL compiler and pin contributor, but it does not run the workflow-definition compiler/contributor chain. Complete API/Studio publication remains a separate acceptance gate. It proves normal child continuation in three composites and explicit absence of implicit ETL reversal after a later scope fault. It does not qualify all parallel same-node Flowchart/BPMN correlations, every ETL terminal outcome, two OS processes, or final materialization.

The later [persisted parent publication checkpoint](evidence/persisted-parent-publication.md) closes that fixture's compiler-chain gap for Sequence and Flowchart: real catalog rows, draft promotion, ordinary workflow publication and v2 ETL editing precede execution of the retained v1 parent in a separate runtime-only provider. It does not use the earlier fixture's manual executable/enricher/publication path. Picker/catalog and API/Studio acceptance remain separate open gates; the other native/process checkpoints keep their original scope and provenance.
