# Data model: The calculator derives the dependency map

No persisted data changes shape. The dataset keeps schema version 2, and the `publish-state` record and the calculator output keep schema 1. This file lists the in-process types that change or appear.

## Dependency-map dataset (unchanged shape)

| Field | Type | Notes |
|---|---|---|
| `schema_version` | int | 2. The calculator refuses any other value. |
| `generator` | string | `tools/maps/Elsa.Maps.Generator`. It stays the same when the calculator derives the dataset, so derived and generated bytes are equal (research R4). |
| `nodes[]` | `ProjectFacts` | Ordinal by `path`. Holds `path`, `name`, `kind`, `domain`, `sub_domain`, `role`, `declared_target_framework`, `packable`, `package_id`, `line` and `edges[]` (internal → external → pinned-transitive). |

**Validation** (calculator, `DependencyMapDataset.Parse`, unchanged): the schema version, a repo-relative `.csproj` path, a packable node with a package id and line A or B, unique package ids (case-insensitive), unique paths, and typed edges.

## Dataset source (new, calculator)

```text
DatasetSource = Auto | Committed | Derived      // default Auto

Auto:      tree has docs/maps/dependency-map.json ? Committed : Derived
Committed: read the blob; a missing file → InvalidOperationException (exit 2) naming commit and path
Derived:   DependencyMapJson.Serialize(CommitTree(commit)) → Parse(json, "derived dependency map at <commit>")
```

It applies to every snapshot one computation builds: the built commit's and the record commits'. `VersionCalculator.Compute` gains an optional `DatasetSource source = Auto` parameter. The Publisher keeps calling it without one.

## Repository tree view (new, shared library)

```text
interface IRepositoryTree
    IReadOnlyList<string> ProjectFiles()     // backend .csproj paths (RepoLayout.IsProjectPath), ordinal
    bool                  Exists(string path)
    byte[]                Read(string path)   // throws when absent
```

| Implementation | Lives in | Lists from | Reads from |
|---|---|---|---|
| `RepoContext` (working tree) | library; the generator constructs it | `git ls-files --cached --others --exclude-standard -- <ProjectPathspecs>` (as now) | disk |
| `CommitTree` (git tree) | calculator | the commit's `ls-tree` entries, filtered by `RepoLayout.IsProjectPath` | `ObjectCache` blobs |

**Invariant**: for a clean checkout of commit C, `Serialize(RepoContext)` and `Serialize(CommitTree(C))` are byte-identical. A self-test and a calculator test pin it.

## Shared library contents (`tools/maps/Elsa.Maps.ProjectGraph`)

| Type | From | Change |
|---|---|---|
| `ProjectFacts`, `DependencyEdge`, `InternalEdge`, `ExternalEdge`, `PinnedTransitiveEdge`, `ProjectGraph` | generator `ProjectFacts.cs` | reads through `IRepositoryTree` instead of `File.*`/`RepoContext.Absolute` |
| `ProjectFile` | generator | `Load(IRepositoryTree, path)` parses from bytes |
| `PackageVersions` | generator | `Load(IRepositoryTree)` |
| `PinnedTransitiveDependencies` | generator | lock file via `IRepositoryTree.Read` |
| `RepoLayout` (project-path part), with the new `IsProjectPath` | generator | `ProjectPathspecs` stays; the source/catalog pathspecs stay in the generator |
| `RepoContext` | generator | moves with the library; implements `IRepositoryTree` |
| `DependencyMapJson.Serialize` | generator `DependencyMap` | new home of the dataset record and JSON options. `DependencyMap.Generate` keeps writing the file |

The generator's markdown layers keep consuming `IReadOnlyList<ProjectFacts>` unchanged.

## State transition: the file on `main`

```text
committed + checked (today) ── removal commit ──▶ ignored; derived by the calculator; published on generated-maps
```

Pre-removal commits keep their committed bytes forever. `Auto` reads them (research R2).
