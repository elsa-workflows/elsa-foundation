# Opt-in bearer normalization contract

Proposed additive contract owned by existing `Elsa.Foundation.Identity.Oidc`. No implementation is present in this specification PR.

## Configuration surface

| Setting on OIDC feature/options | Meaning |
|---|---|
| `NormalizeBearerClaims` | Default false; explicit installation of the guarded request bridge. |
| `Audience` | Optional bearer audience; absent uses ClientId. Explicit blank fails opt-in activation. Does not select interactive registration. |
| `ProviderId` | Existing options field, exposed declaratively; nonblank static namespace. Existing default `oidc` remains. |
| `TenantId` | Existing options field, exposed declaratively; required nonblank static namespace in opt-in mode. |
| `JwtBearerScheme` | Existing developer option; exact handler scheme. Validate it against actual registration; it is not the output authentication type. |
| `Authority`, `RequireHttpsMetadata` | Existing issuer/discovery settings. Production HTTPS remains default; loopback proof explicitly opts out only for its local issuer. |
| `ClientId`, `ClientSecret`, `IsDefault` | Existing meanings; ClientId alone controls interactive registration and legacy audience fallback. Host-chosen defaults remain authoritative. |

Existing absence/default behavior must be unchanged. Configuration field presence matters for Audience absent versus blank. Feature binding must pass a supplied blank through rather than silently dropping it. The host must initialize the ordinary scoped persistence access context to the configured static tenant before IAM or request-store resolution. Use existing `AddPersistenceCore(defaultScope: configuredTenant)` before default registrations, or an equivalent host-owned accessor carrying that same ordinary scope. The adapter never overwrites/rebinds an existing context. Opt-in activation checks the actual accessor matches; each request rechecks ordinary scope/tenant before rule lookup. Missing, global, privileged, across-scope or mismatched contexts refuse with a fixed classification before mapping-store access. A nondefault tenant cannot silently use the default partition. One activated host freezes its namespace and trust enrollment; changing them requires a fresh activation. No generic resource-binding semantics are added to IAM.

## Registration and final options

1. Existing `AddFoundationIdentityOidc` configure delegate captures the selected scheme and opt-in intent as it already captures interactive registration intent. Feature settings use this same path.
2. Repeated opt-in registration in the same service collection is refused with a fixed configuration diagnostic; no last-write-wins or duplicate adapter descriptor is permitted. Explicit opt-in registers one owned scoped events adapter and its named-options setup/validator; ensure one selected normalizer registration and the rule-store contract are present. The rule store uses its existing explicit replacement guard; the normalizer is not a marked replacement contract, so the opt-in bridge must reject absent or multiple normalizer descriptors rather than assume the store guard covers it. No user-principal factory is used.
3. Before installing guarded events, capture ordinary `JwtBearerEvents` callback delegates. A foreign EventsType or Events subclass is incompatible and refuses; do not silently replace it. The opt-in lane owns Challenge/Forbidden: reject custom callbacks on those two events, before installation and in final options. Compare ordinary callback delegates with a fresh base `JwtBearerEvents` default using delegate equality under the installed framework; prove default acceptance/custom rejection against that actual version rather than assume reference identity. No custom Challenge/Forbidden response callback composition is supported. Captured MessageReceived, TokenValidated and AuthenticationFailed delegates remain trusted host code: their response side effects cannot be detected or rolled back by activation and are outside the adapter response guarantee.
4. Post-configure selected bearer options to install the exact owned EventsType and fixed safe challenge behavior. Preserve captured ordinary callback intent under the request rules below. Validate final options, actual registered handler type and exact scheme before serving, after all configure/postconfigure contributions. Run this gate at actual shell activation through IShellInitializer as well as hosted startup; root-only ValidateOnStart is insufficient for shell-owned services. Validate issuer/audience/lifetime/expiration/signed-token enforcement in this opt-in layout; reject disabled validation flags. Existing host-supplied token-handler/validator code remains trusted host code, not sandboxed by these option checks.
5. Enroll the fixed `Elsa.Foundation.Identity.Oidc.Bearer.Normalized` authentication type only together with this bridge. Validate that the raw token identity type differs; do not enroll the raw scheme/type as a shortcut. Final OIDC options must match the captured opt-in/scheme. Late opt-in without a bridge, scheme renaming, duplicate/replaced handler, disabled provider or foreign event replacement refuses with fixed configuration classification. No whole-host success is inferred from options validation alone; the activation fixture must resolve the actual named handler/options and exercise it.
6. Option reload that would change the frozen trust boundary refuses; support is fresh activation, not a claim of safe hot reconfiguration. The actual replacement and both feature-registration orders are acceptance controls.

## Request trust transition

- **MessageReceived**: permit existing ordinary token extraction. Preserve Fail/NoResult semantics: replace a prior value-bearing Fail with a fixed refusal and leave NoResult unchanged. Catch non-cancellation callback exceptions inside the guard and convert them to a fixed event-stage refusal before the handler can log raw text. A prior successful result is refused, because it could bypass JWT validation. No owned mapping lookup here.
- **Token validation**: existing real JWT handler validates issuer, signature, audience and lifetime; no fake validator, disabled-validation switch or fallback handler in the acceptance host.
- **TokenValidated**: check RequestAborted; invoke prior ordinary callback first. Preserve Fail/NoResult semantics with fixed failure text; catch non-cancellation prior-callback exceptions into a fixed event-stage refusal, reject success short-circuit, null principal/token and observed cancellation. A trusted host callback may alter external claims; it cannot supply a successful normalized ticket outside this guarded transition.
- **Input filtering**: copy the surviving validated principal, removing all `IdentityClaimTypes.Normalized/TenantId/Provider/Role/Permission` types, including ordinal-ignore-case spelling variants, before passing it to rule matching. Preserve ordinary external claim types and the default normalizer's supported external-role behavior. External role claims are not direct Elsa permission grants.
- **Rule capture**: first verify the existing request `IPersistenceAccessContextAccessor.Current.RequireScope()` equals `new PersistenceScope(configuredTenant)`. Host initialization supplies the context; no JWT claim selects it and the adapter does not call Bind to replace it. Mismatch/missing/global/privileged/across-scope context yields fixed authentication refusal before invoking the mapping store. Then call `ListForProviderAsync(configuredTenant, configuredProvider, RequestAborted)`. Capture that returned rule list once for this normalization; the next request loads again. Verify filtering by provider/tenant through existing normalizer behavior and adverse store controls. No incoming namespace selection and no transactional cross-request snapshot claim.
- **Normalization**: call the selected `IClaimsNormalizer` with filtered principal, configured namespace, captured rules and fixed distinct normalized authentication type. Check cancellation before/after both awaits.
- **Output admission**: require a non-null result containing exactly one authenticated identity, exact fixed distinct normalized authentication type, exactly one canonical `v1` normalization marker and exactly one configured tenant/provider claim. Reject extra identities, duplicate/conflicting namespace/marker claims, wrong types and malformed result. Only admitted output replaces the principal. Host-selected normalizers are trusted collaborators whose failures/malformed outputs refuse; this is not an audit of arbitrary host-supplied code.
- **Publication**: check cancellation immediately before successful ticket publication; make normalization/admission the final principal-changing operation in the owned path. No partial principal/ticket survives a refusal.
- **AuthenticationFailed**: preserve refusal/no-result intent with fixed failure text but never a successful result. Catch non-cancellation callback exceptions inside this guard as fixed refusal; callback-authored logging/response side effects remain trusted host code and are outside the adapter privacy claim. Propagate active request cancellation; do not convert it into an ordinary401/403 or suppress it via a captured callback. Mapping/normalizer failures have already been converted into fixed authentication refusal within TokenValidated, without logging raw collaborator exceptions.
- **Challenge/Forbidden**: the owned adapter supplies bearer401 with detailed error descriptions disabled and ordinary403. It does not invoke response-writing/handling callbacks. Custom OnChallenge/OnForbidden callbacks or later overrides are incompatible and refuse activation. Do not attempt to undo a response after a custom callback writes it. No token-derived detail is echoed; the existing permission evaluation pipeline remains unchanged.

## Failure ownership

| Failure | Outcome |
|---|---|
| Invalid trust/namespace/audience/scheme/events setup | Configuration/activation refusal before serving. |
| Anonymous or invalid JWT |401; mapping/normalizer not called. |
| Store/normalizer exception or malformed output |401; fixed stage code, no successful ticket or raw exception. |
| Valid normalized caller without legitimate grant |403; no account provisioning. |
| Evaluator/resource backend exception | Existing operational propagation; never403 or grant fallback. |
| Active request cancellation | Cancellation propagates; no successful partial ticket/workflow effect after observation. |

Proposed fixed classifications: `oidc-normalization-configuration-invalid`, `oidc-normalization-events-incompatible`, `oidc-normalization-short-circuit-refused`, `oidc-normalization-events-failed`, `oidc-normalization-persistence-scope-invalid`, `oidc-normalization-mapping-unavailable`, `oidc-normalization-failed`, `oidc-normalization-result-invalid`. These codes do not contain field values, claims, rules, connections or peer exception messages. Configuration may name the setting/stage only. Framework/host logging beyond the adapter is independently controlled and cannot be certified by a local adapter test.

## Compatibility and ownership

No opt-in means no guarded events or added trusted scheme. Retain first-party OpenIddict selection, configured root defaults and interactive registration. Keep external-provider TokenRefreshBoundary metadata. Local rule updates affect later requests; upstream claim changes require a refreshed token. The bridge makes no immediate external revocation promise. The IAM target is explicit and schema provisioning is host-owned; workflow resource defaults do not redirect it.
