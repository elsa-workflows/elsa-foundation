# Initial direct BPMN process recovery

Source [`48bf343b51f9db4c682bacb737758d0c6dbdcfbc`](https://github.com/elsa-workflows/elsa-foundation/commit/48bf343b51f9db4c682bacb737758d0c6dbdcfbc) was rebuilt and run through the real production Workbench with its built-in single-node mailbox and EF SQLite. The isolated host explicitly enables direct admission; admission remains off by default. The authenticated HTTP journey publishes immutable model material, starts, waits at a model-owned human task, stops the owned process, restarts on the same store and completes the exact surviving invocation/attempt. Full material pin, physical incarnation, protocol and waiting revision survive. A stale attempt is retained as rejected, a conflicting replay cannot advance state, body properties cannot replace route identities, and exact completion replay preserves the terminal revision.

[Public observations and exact binary versions/hashes](direct-process.json) record both process IDs and HTTP results. The stopped-host [waiting](waiting.sqlite.gz) and [completed](completed.sqlite.gz) Runtime backups include the coupled physical state/receipts and pass integrity/hash checks. Identity/Design databases and configuration are excluded. Native workflow, activity and bookmark row counts are zero. The [qualification receipt](qualification.json) records 1,320 passing local checks, whole-suite discovery counts, unchanged native budgets and the actual removed-attempt-guard failure followed by restored success. It distinguishes the rebuilt exact-source host suite from pre-commit suites over identical production source.

This proves the initial same-source, combined-host human journey. It does not prove partial fork/join or the full crash/race matrix, source-retirement admission serialization, generic settlement, native-work/ETL bindings, clustered placement, runtime-only recovery without Design storage, actual changed-host/legacy resume or Studio compatibility. #2898/#2907 and Program #2892 remain open; the full-PR review loop has not started.

Reproduce with the [owned-host suite](../../../../Essentials/tests/Activities/Bpmn/Hosting/Tests/README.md). Set `ELSA_BPMN_HOST_EVIDENCE_DIRECTORY` to an output directory and `ELSA_BPMN_HOST_SOURCE_REVISION` to the committed source before running the whole host project; the test checks the host product version against that revision. Rebuild rather than using an old test/host binary. Do not use a developer host or alter saved state to manufacture a wait/result.
