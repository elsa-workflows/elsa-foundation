# Static trace: cancelled native worker with an obsolete compensation retry

Candidate 5ff0d52c6245ab89bc673e45da683a0f6c3cc141. This is a production-source proof of the branch conditions below, not an executed counterexample or actual-host acceptance run. The private helper never compiled successfully; no runtime scenario was executed.

## Supported concrete scenario

Publish a closed-input native worker whose root is the built-in CompensationScope. First step: built-in WriteLine, with built-in Fault as its compensation handler. Second step: built-in Fault. Set handlerMaxAttempts=3, handlerRetryDelay=01:00:00, handlerRetryMaxDelay=01:00:00. Publish a format2 BPMN start -> service task bound to that worker -> end. Run until the first compensation attempt faults and the second attempt waits. Cancel the model through the existing IBpmnModelRuntime.CancelAsync / product cancel endpoint before that hour elapses, and let the ordinary outbox and actors deliver the native Cancel and result.

No custom activity, model alteration, seeded claim, fake clock, manually manufactured execution state or unsupported native profile is needed. Publication validation accepts a fully pinned native worker with an explicit empty input contract and matching live source; it does not prohibit this built-in root (BpmnModelRuntime.cs303-322). Existing CompensationBackoffJourneyTests.BK4, lines141-158, already treats cancelling an ordinary native run while its retry waits as a supported native journey. That existing test is code evidence here, not a test newly executed in round10.

5. The model's original result input therefore cannot be accepted until the future source becomes due and is transported. A one-hour retry produces up to an hour of avoidable pending model cancellation; the supported cap permits nearly24 hours. The native worker is already physically Cancelled throughout this wait. The existing terminal native drain may purge such queued work even earlier. The blocked work is obsolete native scheduling, not an outstanding descendant cancellation effect.

Primary changed lines: BpmnNativeWorkBoundary.cs136-137. The provider lookup is behaving according to its new documented all-source contract; the settlement caller is applying that deliberately broad contract to a narrower cancellation obligation.

## Existing metadata and narrow repair considerations

RuntimePostCommitOutboxItems.CreatePending lines46-48 retains commit.Metadata on the physical source (separate from intent.Metadata). The actual round9 earlier CancelEmbedded source in the retained whole-worker-cancel.json has runtime.checkpointReason=ActivityScopeCancellation and runtime.scopeCancellationReason, while intent.Metadata is empty. The ordinary CancelActivityScope producer writes both markers (WorkflowCancelActivityScopeSchedulerWorkHandler.cs59-66). That existing physical provenance can distinguish the original round9 cancellation source from this ordinary delayed callback source without adding a replacement authority.

Do not simply restrict the proof to that one checkpoint marker: structural subtree cancellations use ScopeCancellationReason/SubtreeCancellationRequestedBy in activity metadata (StructuralParentEvaluationSupport.cs192-207; ActivitySubtreeCancellationPlanner.cs38-44), while the outbox copies the encompassing callback commit metadata (StructuralParentEvaluationSupport.cs279-302). Those genuine descendant cancellation responsibilities must remain covered. Likewise, do not revert to due-now scanning, ignore all future cancellation sources or alter the old queued result's bytes.

The minimal required behavior is to keep prior genuine child-cancellation responsibility fenced and positively proved, while avoiding settlement dependence on an obsolete delayed native scheduling continuation. Reuse existing source provenance/typed cancellation evidence and actual terminal owner proof, or retire the obsolete continuation through its existing authoritative transport boundary. No schema, new model input, replacement cancellation source or invented Delivered receipt is required by this finding. The precise implementation remains the writer's choice; this review makes no source change.
