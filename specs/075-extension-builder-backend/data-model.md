# Data Model: Extension Builder — Backend Pipeline

## ExtensionWorkspace

- `id`: stable server-generated workspace id.
- `ownerId`: trusted caller identity that owns the workspace.
- `displayName`: required user-facing name.
- `trustContext`: trusted/admin context captured at creation.
- `createdAt`, `updatedAt`: UTC timestamps.
- `projectIds`: contained `ExtensionProject` ids.

Validation: list/get/delete operations are owner-scoped. Deleting a workspace deletes authoring workspace/project state only and does not unpublish or unload promoted packages.

## ExtensionProject

- `id`: stable server-generated project id.
- `workspaceId`: owning workspace.
- `templateId`: source template id.
- `packageId`, `packageVersion`, `targetFramework`: editable identity/metadata.
- `manifest`: manifest metadata including display name, description, categories, feature/activity manifest content where applicable.
- `currentSourceRevisionId`: latest immutable source snapshot id.
- `createdAt`, `updatedAt`: UTC timestamps.

Validation: project ids must resolve to an owner-visible workspace. Package id/version must be valid enough for NuGet packaging and later promotion validation. Deleting a project removes authoring files/build state but leaves promoted package feed/runtime state intact.

## ProjectFile

- `path`: normalized relative path under the project root.
- `content`: text content for editable source/configuration files.
- `kind`: source, project, manifest, configuration, or other.
- `size`: content length.
- `updatedAt`: UTC timestamp.

Validation: paths must be relative, normalized, and remain under the project root. File writes are last-write-wins. Unknown file reads/deletes return not-found.

## ExtensionTemplate

- `id`: template key.
- `kind`: `elsa-activity-module` or `generic-dotnet`.
- `displayName`, `description`: template metadata.
- `defaultPackageId`, `defaultTargetFramework`, `defaultManifest`: defaults.
- `files`: starter file set.

Validation: create-project requires a known template id. The Elsa activity/module template is primary; generic .NET class library is also available.

## BuildRequest

- `projectId`: project to build.
- `sourceRevisionId`: immutable snapshot created at submission.
- `submittedAt`: UTC submission timestamp.

Validation: only one build runner may execute for a project at a time; later requests are serialized per project.

## BuildResult

- `id`: stable build id.
- `projectId`, `workspaceId`, `sourceRevisionId`: traceability.
- `status`: `Pending`, `Running`, `Succeeded`, or `Failed`.
- `diagnostics`: `BuildDiagnostic[]`.
- `artifact`: `BuildArtifact?` only when succeeded.
- `logPath`: retrievable full log reference.
- `createdAt`, `startedAt`, `completedAt`: UTC timestamps.

Validation: failed builds do not produce promotable artifacts. Restore failures are represented as failed build diagnostics and logs.

## BuildDiagnostic

- `severity`: `error`, `warning`, or `info`.
- `message`: human-readable message.
- `file`, `line`, `column`: source location where available.
- `code`: compiler/MSBuild diagnostic code where available.

Validation: compile and restore failures should include at least one error diagnostic when tooling emits one.

## BuildArtifact

- `id`: stable artifact id.
- `buildId`: producing build.
- `packageId`, `version`: package identity.
- `fileName`, `path`, `size`: server artifact reference.
- `createdAt`: UTC timestamp.

Validation: artifact path must point to a `.nupkg` generated by a successful build result.

## PackagePromotionRequest

- `buildId`: successful build to promote.
- `artifactId`: optional explicit artifact reference; defaults to build artifact.
- `targetFeed`: optional feed selector; v1 defaults to the configured Nuplane directory feed.

Validation: build must exist, belong to the caller's project, have status `Succeeded`, and contain a `.nupkg` artifact.

## PackagePromotionResult

- `status`: `accepted` or `rejected`.
- `rejectionReason`: `duplicate`, `invalid-manifest`, `dependency-policy`, or `malformed-package` when rejected.
- `publishedPackage`: package id/version/feed/path when accepted.
- `reconcileOutcome`: `accepted`, `deferred`, or `failed`, with reason/correlation where available.
- `requiresReload`, `requiresRestart`: UX/runtime action flags.

Validation: validation failure publishes nothing. Duplicate package id+version is detected before copying into the feed.

## ExtensionRuntimeStatus

- `projectId`: project.
- `activeVersion`: active package version where known.
- `packages`: per-package statuses.
- `availableRollbackVersions`: promoted versions still present in the feed.
- `lastReconcileOutcome`, `lastReconcileReason`: latest known reconciliation result.

Package state values: `Loaded`, `PendingRestart`, `FailedReconciliation`.

Validation: each promoted package resolves to exactly one runtime state. Rollback requires a version available in the feed.

## ExtensionBuilderCapabilities

- `can-create-workspace`
- `can-edit-files`
- `can-build`
- `can-promote`
- `can-rollback`

Validation: capability flags are advisory for Studio. Endpoint filters enforce the same trust decision server-side.
