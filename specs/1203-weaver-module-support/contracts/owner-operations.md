# Proposed contract: owner operations for leaves 1–3

**Status**: Proposed Preview; PD2/PD3 prerequisites, implemented in their owning leaves, not leaf 0.
**Authority**: spec1203 FR006/007/014 and stories 2–4. No generic Weaver type contains these domain meanings.

## Boundary and identity

Add scoped replacement contracts `ISecretOperationsExtension` in Secrets Core and `IConnectionOperationsExtension` in Connections Core, with internal implementations in their respective Api packages. Base domains register none. Each Weaver tool/context provider requires exactly one implementation; zero/duplicate refuses owner-unavailable with no owner data/effect. Api registration diagnoses a second implementation. Supported features require their owning API composition; direct missing-API controls remain fail-closed.

Every member returns ValueTask of its typed owner result and is a distinct query/command with this parameter prefix:

    (ClaimsPrincipal principal, string actorId, string tenantId, TRequest request,
     CancellationToken cancellationToken = default)

The principal is the genuine current object from the generic seam. It is an ephemeral parameter, never part of a request DTO, prepared argument, digest, audit or provider payload. Every member requires authentication and exact actor/tenant match, then the owning permission rule. Factory/entry checks require exactly one `IPermissionAuthorizationService` before resolving manager/gate dependencies; missing/duplicate returns cause-free owner-unavailable, not DI last-wins or an authorization bypass.

Promote the pure resolver/matcher to `PrincipalActor` in `Elsa.Foundation.Identity.Core`; existing WeaverEndpointActor public wrappers delegate without changing behavior. Preserve actor precedence NameIdentifier → sub → Identity.Name, tenant canonical claim → tenant_id, ordinal equality and missing-identity refusal. New callers additionally require IsAuthenticated; do not silently change old CanAccess semantics or substitute the separate internal IdentityClaimTypes.UserId. Both owner APIs already reference Identity Core.

Permission constants remain in existing Secrets Core/Connections Core `Permissions` folders; no duplicates in Weaver. Connections authors its read/disclosure rule using existing `PermissionPolicyDescriptor.Any` for workflows/design:read or connections:manage. Secrets consumer DTOs therefore add the narrow Identity Core reference, alongside the required Events Core reference. Weaver.Secrets evaluates the source descriptor using the existing permission service; it does not reimplement the rule. No new permission-expression parser or hard Identity/Events feature dependency is introduced into base Secrets.

## Typed operations

Public DTO names below are the implementation targets; constructors/fields use existing domain metadata types where safe. No returned DTO exposes Secret/SecretVersion values, resolved credentials or connection setting values.

| Contract member | Request and response | Leaf |
| --- | --- | --- |
| Secrets ListAsync / ReadAsync | SecretOperationsQuery (bounded filters/page) / SecretOperationsReadRequest(Name); SecretOperationsMetadata includes Id, Name, safe metadata, opaque Revision, effective Condition, latest version number/expiry and store/type descriptors needed by story2 | 1 |
| Secrets UpdateMetadataAsync | SecretMetadataChange(Name, ExpectedId, ExpectedRevision, DisplayName, Description, Tags); confirmed metadata/readback | 1 |
| Secrets TestAsync | SecretVersionTest(Name, ExpectedId, ExpectedRevision, ExpectedVersion); SecretOperationTestResult with explicit Ran, safe Code and verdict | 1 |
| Secrets RevokeAsync / DeleteAsync | SecretLifecycleChange(Name, ExpectedId, ExpectedRevision, ConsumerObservation); confirmed owning state or absence, with observation attribution | 3 |
| Connections ListAsync / ReadAsync | ConnectionOperationsQuery / ConnectionOperationsReadRequest(Name); ConnectionOperationsMetadata includes name, incarnation/version, safe metadata, field keys and authorized binding names; omits settings values | 2 |
| Connections UpdateMetadataAsync | ConnectionMetadataChange(Name, ExpectedRevision, DisplayName, Tags); confirmed readback | 2 |
| Connections RebindAsync | ConnectionBindingChange(Name, ExpectedRevision, FieldName, SecretName); confirmed binding/readback and optional fixed CleanupIncomplete warning | 2 |
| Connections TestAsync | ConnectionRevisionRequest(Name, ExpectedRevision); ConnectionOperationTestResult with Ran, safe Code, verdict and persisted test state | 2 |
| Connections RevokeAsync | ConnectionRevisionRequest; confirmed owning revision | 2 |
| Connections PrepareDeleteAsync / DeleteAsync | ConnectionRevisionRequest → ConnectionDeletePreparation; ConnectionDeleteRequest(Name, ExpectedRevision, ExpectedCleanup) → confirmed absence/cleanup observation | 2 |

Both list requests default to50 and cap Take at250, with bounded filters using existing query conventions. List replies expose truncation/total-count observations rather than silently presenting an incomplete inventory as complete.

Each domain uses its own `SecretOperationResult<T>` / `ConnectionOperationResult<T>` and status enum: Success, NotFound, Refused, Stale, Unsupported, OwnerUnavailable. Result messages/codes are fixed owner-owned values mapped by Weaver.<Domain> into its declared set; raw native exception text is never forwarded. Test Ran=false is refusal, not a performed success. Partial effects/unknown commit throw an owner exception with wrapped infrastructure cause; Weaver records uncertain. A confirmed rebind followed by cleanup failure is success plus CleanupIncomplete, not a replayable refusal. Existing native exceptions/results retain their behavior.

Reads require Secrets Read; metadata changes use Secrets Write, revoke/delete use Secrets Delete, and test uses Secrets Test. Connections reads use its existing compound read policy, mutations Manage, tests Test; rebind also requires BindSecret and Secrets Read. Lack of Secrets Read makes the target indistinguishable from unknown. Bound non-owned/named-credential names are projected only with Secrets Read. No server create command is added: prefill remains local state, requires current owner authority and never includes values.

## Same-load expected revisions

Add expected-request overloads with unsupported defaults to the existing owner manager contracts; owner Api calls these, and implementations share their existing domain helpers. Do not precompare then call a name-only manager that reloads a new target. Existing native overloads remain unchanged. New owner paths check capability and revision before the first possible effect.

Secrets uses existing `IRevisionAwareSecretRepository.FindWithRevisionAsync/SaveWithRevisionAsync`. Compare both Secret.Id and the exact expected token inside the same owner load sent to CAS. No unconditional fallback: current in-memory/custom non-revision-aware stores refuse revisioned mutations. New test loads and checks the reviewed Id/revision/version and passes that exact version into SecretTestContext; use the owner lifecycle evaluator for effective condition and separately project latest expiry. Missing secret/inactive version is not a test that ran; a store configuration not-found after invocation maps separately. Native create-if-absent and fallback behavior are preserved.

Add `ConnectionRevision(string IncarnationId, int Version)` in Connections Core. Empty/unknown incarnation refuses new revisioned operations. Every delete/recreate assigns a fresh creation identity rather than copying or reusing the deleted connection's IncarnationId; Version may restart, but the revision tuple must not be reused. An update/save preserves that incarnation and refuses an attempted identity change. The shipped create path already generates a new GUID; custom owners must honor the same identity invariant without a generic GUID-format assumption or new identity-history store. Add `SaveAtRevisionAsync(document, expectedRevision, ct)` and `DeleteAtRevisionAsync(tenantId, name, expectedRevision, ct)` to IConnectionRepository with default Unsupported outcomes; retain all old methods. A successful save increments Version once; its result returns the confirmed revision. Conflict/missing/unsupported are explicit outcomes, never fallback to the integer-only method.

- In-memory compares the actual stored incarnation/version and uses dictionary conditional TryUpdate/TryRemove against that same object; the caller's Find clone is not the CAS identity.
- EF uses a fresh context owned by existing EfSharedTransaction at explicit Serializable isolation: read and authenticate the row, compare reviewed incarnation/version, mutate metadata/reference rows and commit in the same context/transaction. Add an isolation overload retaining the old binary signature/provider-default behavior. Refuse an already-enlisted transaction that cannot provide Serializable; do not silently weaken isolation. No secret cleanup or external call runs inside this transaction. No payload-string/collation comparison, new incarnation column or relational migration is needed.
- Prove same-version delete/recreate barriers on SQLite, SQL Server, PostgreSQL and MySQL: assert a fresh incarnation distinct from the deleted target even when Version restarts, reject the old tuple, and prove save cannot change incarnation. Pre-commit serialization/busy failures may retry only the safe metadata command under existing bounded retry rules; no outer owner/external effect is retried. A provider unable to establish the contract refuses before effects.

Add explicit-principal Manage/Test/BindSecret overloads to IConnectionPermissionGate, defaulting to unavailable for existing implementations. Api authorizes the supplied principal, not ambient HttpContext.User. The new manager overloads use these; old methods retain the current native/no-op gate behavior. This preserves the manager's promise that every write passes its gate without duplicating another authorization mechanism. Compare resolved connection IncarnationId+Version immediately before external testing; its resolver currently reloads by name. A failed result-save after that call is uncertain, even if metadata CAS refuses.

## Bounded queries and cleanup

Add exact-prefix `ListNamesByPrefixAsync(tenantId, SecretPrefixQuery, ct)` to ISecretRepository with default Unsupported. Query fields: Prefix, Skip, Take (1–250, default250); reply: ordered unique name/Id identities, optional repository Revision, TotalCount and Truncated/Complete state. A missing revision still permits enumeration/native best-effort cleanup, but strict revision-bound cleanup refuses unsupported. Implement every shipped repository with ordinal normalized exact-prefix semantics and deterministic name/Id ordering. The prefix must fit existing secret-name bounds. Native substring Search is not a substitute. Reads are read-committed observations, not snapshots.

Connection cleanup scans at most four pages/1000 names; page failure, shifts, inconsistent identities/count or more data makes it incomplete. Weaver completes this bounded preflight before effects and refuses incomplete results. The Connections Core convention owns exactly one definition of `connection:<name>:` and helpers for actual owned fields, deterministic OAuth grant and PKCE nonce-pattern names; Integrations OAuth uses it too. Only those recognized identities are cleanup candidates. Hand-made names that merely match the inline-field prefix remain.

ConnectionDeletePreparation freezes a ConnectionCleanupObservation: the ordered existing secret names/Ids/revisions, reviewed Delete or KeepReferenced disposition, completeness/count and observation time. Its approved summary lists those exact names and kept outcomes. ExpectedCleanup is part of the frozen prepared arguments/digest. At execute, recompute the bounded set and dispositions before any effect; added/removed/recreated/changed observed identities or dispositions are stale, even when the Connection revision is unchanged. OAuth can create PKCE/grant secrets independently. ObservedAt is attribution rather than an equality key.

Never broaden deletion to a freshly discovered name. Delete only frozen Delete identities, with each expected secret Id/revision carried into the same Secrets owner load before value-store I/O and metadata CAS. Leaf2 introduces that narrow expected-delete manager overload/helper for owned cleanup; leaf3 reuses it for the direct secret operation. It adds no direct Secret-delete Weaver tool early and leaves native name-only methods intact. If another connection is observed using a candidate at the last reference check, keep it and report that observation; a reviewed KeepReferenced identity cannot become a new deletion. A later secret creation is left behind, and comparison/reference/value-store intervals remain non-atomic as documented in PD3. A failure after any possible cleanup is uncertain, not a zero-effect stale refusal.

Native #3779 retains owned-field cleanup, adds deterministic grant and enumerated nonce-pattern cleanup, and stays best-effort when enumeration fails. It must not acquire Weaver's strict preflight. The leaf2 PR closes #3779 with native complete/incomplete/hand-made regression tests. Concurrent OAuth creation after enumeration can leave a later secret; record the observation, not universal cleanup. Rebind cleanup after commit is a warning; Connection deletion cleanup before final row CAS can be partial/uncertain.

## Consumer fan-in and confidential observation

Secrets Core defines `ISecretConsumerSource` and Sequential `SecretConsumersCollecting`, with one aggregator in Elsa.Secrets. No pipeline or no answering source is NotChecked, never an empty safe answer. Source failure/unsupported query refuses the new lifecycle operation. Connections contributes its source from Elsa.Connections, backed by an additive default-unsupported bounded repository query implemented by all shipped stores. Return at most250 deterministically ordered connection identities per secret, total count, truncation, observed time and the source-owned disclosure rule; ownership-by-name is also explicit. This advisory truncated answer is allowed, unlike incomplete cleanup preflight.

The Weaver.Secrets module renders names only if the current principal meets the source rule; otherwise counts. Private full comparison identities never enter generic prepared arguments in plaintext. An internal module token codec reuses ISecretValueProtector over a bounded canonical envelope with version/purpose discriminator, actor, tenant, Secret.Id+revision, source identities/incarnations/page/count/truncation, observation time and prepared deadline. The protector has only Protect(string)/Unprotect(string): context is authenticated inside the protected plaintext, not an invented purpose/AAD overload or claim of key separation. Reject foreign context/purpose, tampering, missing keys, expiry, oversized decoded data and tokens over128KiB with safe fixed outcomes. No principal/value is in it; no store/prepare mutation is added. Keep ciphertext opaque and out of rendered/provider summaries.

At explicit execute, re-authorize, re-read ownership and recompute the same bounded source answer. Compare observed full identities plus page/count/truncation; an observed change is stale. Observation timestamps are attribution, not equality keys. A later binding can still appear after final comparison: review warns, receipt records what was observed, and UI never says unused at deletion. No global consumer hash, cross-owner coordinator or process-local fake fence is introduced. The required barrier inserts a binding in that exact interval. Separate Connection-delete barriers create a PKCE/grant after review but before execute (stale, zero effect), recreate a reviewed secret under the same name, and create a new secret after final comparison (never deleted under the old approval; observation-attributed residual cleanup).

Secret value deletion precedes its metadata CAS; a later conflict/fault is partial/uncertain and never automatic retry. Readback after any confirmed command may see later native changes: attribute it to the actual owner observation. Lost response or Weaver receipt-retention failure never authorizes a second invocation.

## Placement and evidence

Owning Core contracts/models and conditional operations; owning implementation shared domain/repository mechanics; owning Api current-principal authorization; Weaver.<Domain> guidance/tools/risk/code mappings and safe prepared projections; owning Studio SDK renderers/prefill. New references are recorded in the corresponding catalogs and package closure. Missing custom integrations refuse rather than change native behavior.

Each leaf proves direct tool/context paths without a host authorizer, missing/duplicate authorization, principal identity/tenant, exact revisions, native regressions, the plan's interval barriers, redaction and owning-resource readback in real composed and immutable-package consumers. These are future gates, not claims of completion.
