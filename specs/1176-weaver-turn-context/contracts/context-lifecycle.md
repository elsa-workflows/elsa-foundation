# Context lifecycle contract

This records the behavior to qualify for #3439. It does not freeze new API shapes before the experiments or expand M1's accepted minimum.

1. A request carries explicit source/correlation, attachments and its current active surface. The surface does not grant permission or change older operations.
2. Admission returns the sanitized evidence actually accepted, with diagnostics. The client must not label its pre-admission snapshots as provider evidence.
3. Installed sources own resource interpretation, authorized reads and trusted guidance. Shared code enforces ownership, transport bounds, policy, cancellation and consistent failure handling.
4. Before provider disclosure, current identity, module and policy restrictions apply to retained evidence/results/history. If an owner cannot establish authorized disclosure, withhold or refuse explicitly. Preserve accepted receipts and do not reexecute effects.
5. Required missing evidence blocks provider use. Optional failure remains visible without discarding unrelated complete evidence. A configured bound and Stop terminate collection even for noncooperating asynchronous contributors; late completion cannot change accepted state.
6. Shared chips use declared metadata only. Resource payloads and applied-result rendering remain opaque and module-owned.
7. Both existing adapters receive the same admitted tools/refusal causes. Domain-specific filters and resource switches in adapters are prohibited.

Implementation tasks update this note with actual signatures/wire deltas, defaults and compatibility evidence. Update the owning extension catalog and public API baselines for each actual externally visible change.


## Implemented boundary, under package qualification

- `IAgentContextProvider.AdmitDisclosureAsync(AgentContextDisclosureRequest)` reuses the existing named fan-in. Default support fails closed. The host stamps original `ContributorId`; exact source/module/kind/schema must remain installed.
- `AgentToolDescriptor.DisclosureSourceId` is frozen into preparation and its review digest. The engine stamps result `Access` with owner, contract, original target, source and invocation identity. Result-only turns route to that exact source; a same-module decoy is not selected.
- Source success authorizes original historical evidence/results unchanged, while its returned context is the current permitted projection. Current host policy checks original retained evidence as well as the projection. Unsupported, missing or failed disclosure gates cannot become optional collection warnings.
- Before every delegated callback or host batch operation, current module admission and the admitted tool set are checked again. A narrower projection cannot retain an old tool scope. Authorized detail targets may be added while retaining the original target/revision. A changed resource identity/revision in this accepted turn requires fresh intent; the captured callback cannot silently follow it.
- The shared provider dispatch boundary journals genuine results before handing them to either provider loop, independently of assistant text. The existing session store must preserve the result, context, fingerprint and provenance; missing metadata stops disclosure. Legacy history that cannot establish provenance requires a fresh supported session. No second result store or orchestration engine is added.
- New requests carry current `activeSurface`; admitted message context and `ContextAdmitted` stream events replace displayed candidates. Shared chips inspect declared metadata only. Provider adapters remain resource-agnostic.
- Server `AgentContextOptions.SourceTimeout` and the client collector's `contributorTimeoutMs` default to10seconds per source. Backend descriptors default required; the existing frontend `required` marker governs client outcomes. Cancellation does not wait for asynchronous source cooperation. These bounds do not sandbox arbitrary installed code that blocks synchronously.
- A receipt may identify a newly created resource after a collection target. Shared code validates generic owner/preparation identity; the module owns before/after resource semantics. Display labels/routes do not redefine resource identity.

Most shared API shapes are additive. The public `DefaultWorkflowAgentContextProvider` constructor changes from `(IWorkflowRevisionProvider, IWorkflowActivityCatalogProvider)` to `(IWorkflowRevisionProvider, IWorkflowActivityCatalogProvider, IAgentSessionService, IAgentToolAuthorizer, IEnumerable<IWorkflowDefinitionAuthorizer>? = null)`. This is a source and binary compatibility break: direct consumers must rebuild and supply the owning session, host authority and selected workflow domain authority, or use the supported workflow feature registration to resolve them through DI. An authorization-free legacy constructor would undermine the disclosure boundary and is not retained.

There is also a deliberate pre-GA behavior change: contributions without the new disclosure support now refuse provider use rather than reuse unproven evidence. Custom session stores must retain the new journal provenance. A release would require the appropriate breaking-change classification; this work performs no release or publishing. Agent Core, workflow Design Core and the workflow integration are not currently enrolled in the repository's text API baseline mechanism; the enrolled `Elsa.Agent` public feature/registration API is unchanged. The [live domain catalog](../../../Extensions/Agent/src/Elsa.Agent/EXTENSION_POINTS.md) owns current extension-point documentation.

Tool catalog discovery validates that every declared disclosure source ID resolves uniquely to an installed source owned by the same module, before a tool is advertised or prepared. This uses public descriptor metadata in the existing named tool aggregator; collection and current-authority behavior stay on the context fan-in. Registration metadata does not establish current authority or guarantee that a future result will be admitted. A reviewed operation whose owner disappears receives an explicit executor-unavailable refusal before module execution, rather than a false uncertain-effect report.

The current workflow domain also exposes `IWorkflowDefinitionAuthorizer` in its owning Core, with native read/manage decisions independent of authored revision. Design.Api supplies the normalized tenant, typed definition/folder and metadata checks; workflow contributions consume that Core port. No native API resource type enters Weaver Core or its provider adapters. Missing or duplicate authority fails closed. The existing native GET honors the selected owner decision while preserving the reader's not-found behavior. The built-in authorization path reads metadata only; a replacement details reader's compatibility method may perform its full read.

Infrastructure failures at this owner boundary become `WorkflowDefinitionAuthorizationException` from Workflow Design Core, retaining the requested definition, read/manage operation and original `InnerException`. Its outer message excludes infrastructure details. An existing exception of that type is preserved; known native denials remain false and cancellation propagates. Replacement implementations honor the documented exception boundary. Failure to establish a decision never grants authority.

The optional `IAgentToolAuthorization` companion adds module-owned constraints alongside existing host authority on the same tool. The shared engine calls it for advertisement, concrete/duplicate dispatch and post-approval execution/completion. It uses no second tool/authority registry and does not redefine historical-result disclosure, which remains source-owned.

Additional public constructor deltas: the workflow context provider now also accepts an optional `IEnumerable<IWorkflowDefinitionAuthorizer>`; graph/layout tool constructors accept the same collection. Optional parameters preserve ordinary source calls but replace CLR signatures, so existing binaries must rebuild. The native definition GET endpoint constructor additionally receives the selected authority collection; normal feature/DI composition supplies it. These source/binary changes remain within the documented pre-GA breaking classification and perform no release.

## Cumulative disclosure obligation

An answer and a paused transcript remain dependent on every context snapshot already disclosed during their turn, including authorized detail added by a module and omitted by a later projection. Retained provenance must preserve those distinct snapshots and current authority must cover them before another provider handoff or historical replay. The original operation binding and current executable projection stay separate; provenance cannot silently retarget an operation. A flattened union keyed by attachment ID loses distinct resource/revision evidence and is insufficient.

The candidate round 7 correction uses one generic `AgentDisclosureSnapshot(Context, ToolResults)` value. Nullable `DisclosureHistory` properties on `AgentMessage`, `AgentMessageCreateRequest` and `AgentPausedTurn` retain whole snapshots without replacing current context/results. An assistant's existing `DeliveryFingerprint` binds its content and disclosure provenance. The paused state adds `DisclosureHistoryFingerprint`, a checksum of its complete state excluding that checksum field. These detect incomplete or accidentally modified storage; they are not signatures or authority supplied by a store.

Custom session and paused-state stores must preserve this metadata, including valid empty histories. Missing legacy generated-transcript provenance refuses provider disclosure explicitly. Retention is bounded to 64 distinct snapshots and 8 MiB of serialized snapshot evidence; exceeding either bound refuses another disclosure without evicting an earlier dependency. Identical complete snapshots deduplicate, while distinct versions sharing an attachment ID remain separate. Inherited transcript dependencies do not turn an ordinary request into a receipt continuation or change the operation's original binding.

Causal repaired-source tests, independent review and final native qualification remain live gates on the owning issue and PR. An earlier package pass does not qualify this correction.

## Write-ahead disclosure and storage failures

A verified metadata-only checkpoint precedes provider input and a callback's expanded context, including a refusal derived from that context. The final assistant insert is not the only record of evidence already sent to an SDK session. Identical verified checkpoints are reused within the foreground turn; current authority is still checked before each handoff. Pending projections remain distinct from the last successful checkpoint, so a failed or cancelled first write cannot later present an unexposed projection as a disclosure. Pre-disclosure writes honor foreground cancellation; accepted effect receipts retain their existing persistence and no-replay semantics.

Unexpected contribution/disclosure infrastructure failures cross the Core streaming boundary as the existing `AgentContributionException`, with a localized operation/session and original cause. The API transport caller logs that domain exception server-side and emits a fixed redacted SSE error. Expected missing or changed provenance remains a bounded refusal. Cleanup attempts turn-state removal, source-status completion and lease release independently; multiple failures retain their causes in a domain-wrapped aggregate. An early admission failure still finalizes its identified new prompt, while a receipt continuation preserves its pending state.

This adds no storage port or public exception type. A store that commits and then reports failure remains uncertain; no durable restart or uncooperative-store timeout guarantee is established by this slice. Supported recovery remains owned by [#3441](https://github.com/elsa-workflows/elsa-foundation/issues/3441).

Successful asynchronous checkpoint storage is followed by current admission of the exact retained evidence before provider, callback or UI-result delivery. Initial tool advertisement uses a fresh ordinary source projection for current scopes and authority, while provider evidence stays checkpointed. A dispatch checks the current generic binding envelope without substituting an uncheckpointed payload: changed owner/schema/target/client/sensitivity or execution scopes refuse explicitly, while authorized opaque body/summary/reference refreshes may leave the frozen invocation evidence unchanged. Target identity is module, resource type, resource ID and revision; authorized display-name or route refreshes preserve the checkpointed presentation. Historical admission's unused returned projection is not new intent. No recursive checkpoint/reprojection loop or domain payload comparison is introduced.

The private foreground boundary invokes replaceable asynchronous and synchronous delegates inside its error boundary, including provider enumeration/disposal. Distinct primary causes survive cleanup aggregation. Unexpected receipt-resume journal errors reach the Core caller with their cause while the accepted receipt/pause stays retained; an expected incomplete-provenance refusal remains bounded and cannot replay the effect.
