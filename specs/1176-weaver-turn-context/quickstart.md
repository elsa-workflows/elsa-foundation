# Qualification guide

Live completion and merge/main receipts belong on [#3439](https://github.com/elsa-workflows/elsa-foundation/issues/3439). This guide specifies the required run; it is not a passing result.

1. Check the issue's winning claim, current main health, dependencies and Project65. Use one implementation leaf. Check `uptime`; respect build slots.
2. Run focused causal Hosting tests for admitted context display, current surface, noncompletion/Stop/late completion, required/optional failure, permission advertisement and two synchronous correlated requests. Use existing Vitest configuration and bounded controlled promises. Run affected Agent tests for retained disclosure/tool policy and collection bounds. Capture the pre-fix failure and post-fix pass.
3. Native baseline: create a new private owned output root. Copy only hash-verified M1 product/SDK/module/protocol archives and locked author graphs; materialize fresh package consumers, regenerate configuration and create fresh stores/keys/identity. Never restart or modify a completed proof root or developer host.
4. For each actual adapter, accept a native resource request without streaming; change native IAM grants to the predefined without-read profile, sign in normally as the same subject/tenant and confirm the owning resource denies its read. Stream once and inspect actual provider input/tools/refusal. Repeat after one genuine accepted effect, retaining its receipt and owner readback before revocation. Never replay the effect; restore authority only for independent final readback.
5. Qualify A-to-B navigation/selection/editing with fresh context and an older A preparation; identity and module remounts plus custom retained editor lifetime; displayed admitted provenance/revision; secret/unrelated/instruction-shaped data; required/optional faults, noncompletion, cancellation and budgets. Inspect actual adapter inputs and native owner effects, not only endpoint success.
6. Rebuild the supported distribution from the integrated source and run the existing independent package witness using `tools/studio/Weaver.Conformance.Probe/README.md`. Preserve normal workflow validation, atomic working edits, whole-batch undo, explicit save and every existing M1 negative control.
7. Run complete affected-project tests and repository architecture/maps gates. Reconcile discovered versus executed test counts and report skips individually. Publish gate evidence on the scoped PR, converge independent review, merge through the repository process, then verify resulting main before marking #3439 Done.

Record deterministic tests separately from actual-adapter protocol/native evidence. Live-provider qualification is opt-in within the Program boundaries and cannot be inferred from protocol fixtures.
