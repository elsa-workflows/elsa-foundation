# Research

- A URL-only switch is unsafe: App builds one registry/auth context; cached ES modules retain FeatureManagement moduleApi/completion and Workflows latestModuleApi. Full navigation after successful preparation provides a small, complete lifecycle reset.
- Host and backend credentials must be independent. Existing registry copies host SignalR credentials into backend even when backendHttp differs; pass complete contexts explicitly.
- Existing SDK and authentication root-anchored paths drop shell prefixes. Use explicit shell-path resolution for backend sessions without changing the legacy root URL contract or double-prefixing already resolved capability links.
- Reuse Preferences.Core at the Studio host. Preferences.Api would pull domain identity/API infrastructure into lightweight Hosting. Project host subject/tenant from authenticated introspection; demo tickets are not real identities.
- Feature administration already provides settings editors, dependency cascades and review/Apply. Extend its target identity and state display, not its configuration semantics. Missing newer availability fields mean unknown for older servers.
- Capability absence is different from discovery failure. Existing Workflows parser silently accepts malformed envelopes as empty and ignores dormancy; shared discovery must preserve those distinctions.
