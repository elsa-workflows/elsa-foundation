# Data boundaries

## Embedded occurrence

An embedded block persists as an ordinary ActivityNode with an exact `activityVersionId` and activity-owned structure. Extraction introduces one composite node and preserves child node IDs and versions. It changes the owning parent's child membership/routing and corresponding layout/presentation; a supported result crossing can also require the explicit typed transfer described below. No generic kernel child/edge/block model is added.

Sequence stores authored list order. Flowchart stores its activities, explicit start and connections. BPMN stores elements, flows and bound child activities; its subprocess binds a nested BPMN process. New structures begin without local variables or execution policy overrides.

## Presentation

Extend typed Activity Definition presentation alongside layout, not inside the provider manifest or executable material. Each record has the existing node identity, optional display name and description. Missing older values mean an empty collection. Create/replace/clone/conflict-copy/version/source-freeze paths retain the collection; history snapshots include it. Provider-neutral public contracts must not depend on Workflows implementation projects.

T001 uses Activities Design-owned `ActivityNodePresentationRecord` collections named `ActivityPresentation` on the existing draft/version layout sidecars. Node IDs remain exact; names/descriptions trim to null when blank and reject values beyond 200/2,000 characters or duplicate identities. Omitted/null replacement metadata preserves the prior collection; explicit `[]` clears it. Revision fencing covers graph, layout and presentation together. Thin wire envelopes preserve existing command constructors/deconstructors while the endpoint binder handles the additive array.

Publication and Test Run freeze names for template nodes and graph dependency occurrences. Placement remaps each occurrence to its executable identity; unknown source identities never fall through to outer nodes. Authored call-site names take precedence over template root names. Review/dirtiness/recovery identities include presentation, while provider/template/executable behavior hashes exclude it. Historical inspection uses the execution's exact frozen source reference. Activities Design migrations follow the pre-release regeneration policy in [ADR 0078](../../docs/adr/0078-workflow-executions-are-virtual-actors-and-cluster-membership-is-a-foundation-contract.md); default-empty JSON compatibility does not imply an upgrade path for an existing pre-GA development database.

Actual T001 qualification found that the graph compiler embedded the proposed release version in its runtime contract, changing the template hash even when provider content was identical. Graph compiler `4.0.0` pins that contract to the existing runtime descriptor schema, matching source-owned CLR templates and [ADR 0038](../../docs/adr/0038-artifact-hash-is-purely-behavioral-and-executables-are-content-addressed.md). Newly compiled material has the new compiler fingerprint; previously published templates remain pinned and are not rewritten. Cosmetic releases compiled by the same compiler can share behavior material and retain separate frozen source metadata.

Editor history compares presentation using the persisted normalization rules, so a server acknowledgement containing `null` rather than an omitted field does not discard Undo. Input fields retain in-progress whitespace across equivalent autosave acknowledgements; actual document changes, Undo and Redo update their values. Provider, layout and substantive presentation changes still reset history when they arrive from outside the editor.

## Refactoring preview

Internal Studio plan input: current resource document, scope address, selected node/element identities, exact authorized catalog and requested name/body kind. Output is either located refusal diagnostics or a complete document edit including structure, layout, presentation and post-apply selection. Apply only against the unchanged source snapshot and catalog identities.

The native planner requires an explicit reference context for resource-owned declarations and bindings outside `rootActivity`, including reusable graph output mappings. Hosts supply those values alongside the normalized graph document; Ungroup inspects them for wrapper references, and preview freshness includes them even before a new server revision exists. An omitted context refuses the edit; an explicit empty array means the resource has no such bindings.

Current publication authority rejects direct reads of a child from outside its structured parent. For supported ordinary sibling result reads, extraction therefore proposes ordinary Set steps immediately after the selected producer, with fresh `Elsa.Any` variables on the original enclosing container. Outside typed arguments or explicit expression parameters read those variables; expression source, existing captures and declarations are retained. The proposal contains these visible steps and declarations, not a hidden runtime channel. Reads that cannot be preserved by this bounded profile refuse before mutation, including optional/member reads, authored conversion requests, opaque or ambient scope observers, nested producers and resource-owned mappings needing a wider edit. Adding a visible variable requires an expression-module preservation verdict for every portable expression in the affected scope; absent support refuses. Workflows does not analyze language syntax. The JavaScript contribution currently admits only a numeric literal or direct `args.<declared parameter>` operand, or one binary operation over those operands (optionally wrapped in one pair of parentheses). Calls, other member access, strings, comments, escapes, ambient/global identifiers and other source forms need a wider proof and refuse; extraction that adds no transfer keeps its existing opaque expressions unchanged. The host supplies this language-neutral contribution with a revision included in preview staleness checks. T003 must compose the contribution through the expression-module boundary before exposing these commands in the product; the planner fixtures supply it directly and are not composition evidence. Generated variable names avoid existing names case-insensitively and preserve their entered casing. Variable compilation does not preserve an authored result-conversion request, so even an explicitly selected Auto profile is refused until that profile has its own proved transfer. No declaring execution scope is invented: existing explicit result scopes are retained, and scope-free transfers require a proved root Sequence/whole-linear-Flowchart profile.

The host must validate the complete candidate through the existing resource authority before committing it. Undo of extraction restores the complete original document. Ungroup removes the wrapper and retains its ordinary Set steps, declarations and rewritten consumers; it never deletes transfer state or authored edits by guessing provenance from generated names. Publication and actual runtime/restart evidence are required independently of planner readiness or golden fixture equality.

## Promotion proposal

Internal Studio proposal contains exact source fingerprint, candidate schema-2 Activity Graph manifest, public contract, explicit input/output/outcome mappings, call-site replacement and diagnostics. Existing public authoring APIs persist/validate/publish the target; the planner is not a second catalog or publication engine. Published target selection triggers fresh comparison/review before replacement. No cross-resource atomic transaction or destructive cleanup is implied.

T005 keeps native local frames inside the candidate body. Graph compilation admits ordinary Set only for one declared enclosing native-container local below the closed boundary, with the declaration owning its assignment type. Publishing compiles those retained declarations through the same canonical literal-default/storage rules as workflows and pins typed assignment conversions from the actual declarations. Original-template checks require matching authored ancestry and canonical occurrence declarations before placement reconstructs the native tree. Native locals using the reserved legacy graph scope identity refuse before promotion; generated boundary identities avoid collisions with authored nodes. Graph-global, external, sibling and undeclared assignment targets remain refused; Merge/Reduce and other intrinsic forms have no promotion proof. Literal-initialized root locals and supported externally consumed child results are proposed as public outputs through ordinary boundary-aware Set Output steps, rather than lifting mutable locals into a different scope. Original whole-result reads and explicit result parameters on staged Set/Set Output steps require the same successfully analyzed source revision and exact immutable producer dependency/template contract. Matching includes the original role, parameter identity, producer/projection, scope and optional flag; unrelated colliding runtime IDs cannot authorize a read. Literal JSON remains data. These temporary compilation facts are not persisted and do not relax the reconstructed placement checks. Candidate graphs use existing schema-2 outcome mappings and active authoring types/storage drivers. The proposal contains the complete call bindings, resource-owned reference rewrites, source/capability/catalog fingerprint and candidate identity; binding a version still requires T006's ordinary published-target/authority/material review and normal whole-resource validation.

Captured request reads require guaranteed presence (required inputs or ordinary defaults). External result reads need a complete normal sibling path proving producer completion before the call; outside consumers must follow the call. External mutable reads/writes, deferred/custom evaluators, opaque or unsupported reference metadata, changed Complete/Break targets, unsupported activity effects, configured routing policies and unproved existing capture profiles refuse at their authored locations. The current activity admission profile covers inspected native structures/primitives; it does not infer arbitrary custom activity dependencies. Expression owners expose a separate revision-bound closed-parameter preservation contribution; variable-addition permission alone is insufficient. These are analysis profiles, not publication or runtime proof.


## Runtime causality and BPMN interchange

No new runtime model is selected solely from source inspection. S001 must prove the current causal-completion behavior and design a narrowly owned supporting bridge if needed. T004 must extend the existing vendor binding-retention boundary for the supported XML profile rather than silently dropping native configuration. Any resulting additive interface/persistence change is recorded and reviewed with its implementing task before production acceptance.

### T004 interchange profile under qualification

The native process remains the source document. Export/import are explicit conversions, with whole-resource candidate validation and unchanged-source/authority checks before one history edit. Import replaces only the selected native body; it retains the owning activity's exact identity, version, inputs, outputs, invocation settings and presentation. The review retains the original file, exposes conversion issues and requires explicit confirmation of retained exact activity versions and literal input keys. Unsupported or degraded imports cannot be applied. Confirmation is not trust in the file: the importing host must verify each binding against its visible catalog. References from retained resource content to a replaced body refuse before mutation.

The supported task-binding extension retains the original child identity, exact version and catalog-declared portable literal inputs. Ordinary native subprocess bindings use the same explicit review; their body stays native BPMN. Sensitive, credential/connection, expression, output-mapping, background and intrinsic settings are outside this XML profile and must produce located export refusals. Native extraction preserves those configurations where supported independently of interchange; an XML refusal does not alter the source.

The pinned `Bpmn.Interchange` 0.5.0 library writes scalar variable names and type hints but does not write variable default values. Its exact source is [commit 021d2c5](https://github.com/valence-works/bpmn/tree/021d2c5bba494f17d346144d97763cd3b2a13a4b). The adapter supports known single-value scalar aliases with matching name/reference key, no storage configuration and no default. Defaults (including literals), collection types, custom aliases and other unsupported declaration settings explicitly refuse export; no private encoding is introduced to simulate support. The failed default-value experiment remains distinct from the subsequently passing refusal tests.

Each native subprocess has its own BPMNDI plane, local fractional positions, dimensions and edge waypoints. Studio bridges positions recursively without changing retained sizes/bends. Native child names can travel as standard BPMN element names and return as child presentation; conflicting native/BPMN names or summaries that this profile cannot retain explicitly refuse export. The current body's owner name stays with its resource. These are bounded profile claims: unqualified foreign DI/extension content is not covered by a general lossless-interchange claim. Native execution, XML fidelity, fixture tests and composed-host acceptance retain separate producers and gates.
