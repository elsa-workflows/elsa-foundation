# Evidence: the ETL design store on all four EF engines (spec 1202)

## Requirements and tests

| Requirement | Evidence |
|---|---|
| FR-001: provider contexts and selection | `EtlDesignSqlServerDbContext`, `EtlDesignPostgreSqlDbContext`, `EtlDesignMySqlDbContext` beside SQLite; `The_design_module_registers_the_engines_context` on each server engine resolves the engine's context through `AddEtlDesignEntityFrameworkCore` and connects. |
| FR-002: generated internal migrations, retained SQLite chains | `Migrations/EtlDesign/{SqlServer,PostgreSql,MySql}` generated by `tools/etl/generate-etl-design-migrations.sh` through `Elsa.Etl.Tooling`, as internal classes; the SQLite design and runtime snapshots are unchanged, and the SQLite contract's `HasPendingModelChanges` check still passes. The shared `generate-module-migrations.sh` skips `Extensions/Etl` and `Extensions/Rules` in its deletion loop. |
| FR-003: catalog paging without a provider function | `EfEtlDefinitionCatalog` orders and seeks on `DefinitionKey`; `Definition_pages_use_stable_hash_cursors_and_preserve_opaque_ids` (with `orders` and `Orders`) passes on all four engines. Definition keys are uppercase hexadecimal hashes, which sort alike under any collation, so the collation is proven from the schema instead: `Key_and_hash_columns_use_the_engines_binary_collation` reads each server's recorded collation for the key columns. |
| FR-004: publication retry | `Concurrent_publications_of_one_draft_record_one_artifact_and_settle_without_a_provider_failure`: four writers on their own connections publish the same draft revision; one publishes, the others replay or conflict, one artifact is recorded. `Concurrent_updates_of_one_draft_revision_admit_exactly_one`. Both on all four engines. |
| FR-005: migrate, validate, model agreement | `A_fresh_database_migrates_validates_and_matches_the_model` on each server engine. |
| FR-006: contract suite and CI | The design-store tests are contract classes (`Extensions/Etl/tests/Shared/DesignStore`): `Elsa.Etl.Tests` runs them on SQLite with the SQLite-only cases (a storage-failure trigger, the retained pre-v2 database); `Elsa.Etl.Persistence.ProviderTests` (container suite `etl-ef`, shard `ef-3`, `ELSA_ETL_EF_REQUIRE_NATIVE_PROVIDERS`) runs them on PostgreSQL 16, SQL Server 2022 and MySQL 8.4. |
| FR-007: docs | ETL README persistence section, the design feature's manifest text, the package description, ADR 0087's EF admission paragraph. |

## Bite-proofs

[`bite-proofs.json`](bite-proofs.json) has five entries, recorded at `84b61a306`, and all bite:
- the registration selecting the PostgreSQL context;
- the binary collation on SQL Server, PostgreSQL and MySQL (without it the model disagrees with the migrations, and on SQL Server and PostgreSQL the recorded column collation differs);
- the publication retry: with a single attempt, the concurrent-publication contract fails on all three server engines, so the races are real there.

**Not bite-proven:**
- **The publication's transient-conflict filter on `catch (DbUpdateException)`.** Removing it survived: in the races the conflicts surface from the conditional update or the reads, not from `SaveChanges`, so that branch was not reached.
- **The catalog without `EF.Functions.Collate`.** Hash keys sort alike under every collation, so no paging case can tell; the collation itself is bite-proven above.
- **Exhausting the retry budget** (rethrowing the last conflict) is untested; it needs a database that refuses every attempt.

## Actual Workbench journey

[`design_store_workbench_journey.py`](design_store_workbench_journey.py) starts, for each server engine, its own database container and its own Workbench on ephemeral loopback ports, with the ETL design store on that engine and the runtime on SQLite. It creates two definitions whose ids differ only by case, validates and publishes one, runs the published version from a native Flowchart over a JSON Lines file, stops the host, starts a new one on the same database and reads the draft, the publication and the catalog back.

All 18 checks (six per engine) pass; the summary is [`workbench-journey-summary.json`](workbench-journey-summary.json), recorded at `9432455c1` with a clean tree. Container secrets are generated per run.

## Limits

- The ETL **runtime** store remains SQLite-only; its registration still refuses other engines. It needs narrower keys, provider-specific check constraints, ordinal collation and retried transitions, and is the next slice.
- Studio is unchanged by this slice.
