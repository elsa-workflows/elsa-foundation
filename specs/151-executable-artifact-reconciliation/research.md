## Decisions

### D1 — Project placement: two new projects, contracts shared via Runtime.Core

**Decision**: 
- `Elsa.Workflows.Runtime.Reconciliation.Core` (new, contracts-only): `IWorkflowArtifactReconciliationSource`, reconciliation option/result models, domain exceptions. Refs: `Workflows.Runtime.Core`, `Serialization.Core`, `Primitives`.
- `Elsa.Workflows.Runtime.Reconciliation` (new, feature): abstract `WorkflowsArtifactReconciliationFeature` + concrete `JsonWorkflowArtifactReconciliationFeature` (folder/files source), `WorkflowArtifactReconciler`, `WorkflowArtifactReconcilerStartupTask`, the import gate. Refs: Reconciliation.Core, Runtime.Core, Runtime, Tasks.Core, Tasks.Schedules, Locking.Core, Serialization.Core, Persistence.Core.
- Types shared with Publishing go in **`Elsa.Workflows.Runtime.Core`** (envelope model `WorkflowArtifactClosure`; `IRuntimeRequirementChecker`; the neutral activation contracts `IWorkflowActivationAuthority`/`WorkflowActivationSlot`/`WorkflowActivationSource` + `IWorkflowActivationCoordinator` — see D3 rev) with default impls in **`Elsa.Workflows.Runtime`** (per ADR 0033: contracts in `.Core`, defaults in impl; registered in `AddWorkflowRuntime()` via `TryAdd*`).

**Rationale**: Sibling-project-per-feature is the established Runtime shape (precedent: `Elsa.Workflows.Runtime.ReferenceGarbageCollection`); the Design reconciliation family (`.Core`/base/`Json`/`Git`) is the shape FR-B-002 mirrors. The JSON source stays **inside** the base project in v1 — §2.20 rule 1 forbids premature per-provider decomposition while only one source kind exists (Design's split is justified by Json+Git being two kinds); a blob/OCI source later triggers the split. The thin `.Core` is exempt under §2.16.1 class "contracts-only `.Core` seams" and lets future sources implement the contract without the base feature's Tasks/Locking envelope. **Mechanical caveat**: adding sibling folders requires extending the `<Compile Remove>` glob in `Elsa.Workflows.Runtime.csproj`, and new assemblies must be added to `Elsa.Workbench/Program.cs` (~:251-258) and regenerated maps.

**Alternatives rejected**: 4-project exact mirror of Design (premature per §2.20); putting the source contract in `Workflows.Runtime.Core` (reconciliation is a feature-family concern, not an engine concern — Design keeps it out of `Design.Core` too).

### D2 — Requirements checker: extract to Runtime, two axes in one verdict

**Decision**: `IRuntimeRequirementChecker` in `Workflows.Runtime.Core`; `RuntimeRequirementChecker` (default) in `Elsa.Workflows.Runtime`, registered in `AddWorkflowRuntime()`. One call → one `RuntimeRequirementCheckResult` covering **both axes**: (a) consumer capabilities + storage drivers (logic relocated verbatim from `RuntimeRequirementPreflight.cs:111-144` — exact ordinal set-membership / key containment, unchanged per clarification); (b) per-node CLR type presence via `IWellKnownTypeRegistry.TryGetTypeOrDefault(ClrActivityDescriptor.TypeAlias)` — the exact predicate `ClrActivityActivator.cs:32` uses. Statuses: `Available | Missing | UnsupportedSchema | MissingActivityType` (extends the existing `RuntimeCapabilityStatus` enum or a runtime-layer sibling; plan keeps the existing enum and adds the fourth member — wire impact: none, it's in-process). Dependency check: `Workflows.Runtime.Core` already references `Activities.Runtime.Core` (consumer capability) and `Serialization.Core` (type registry contract); driver registry is local. No new project references.

**Publishing becomes a thin wrapper**: `RuntimeRequirementPreflight` keeps its retained-set scope selection, views, and `ActivityDiagnostic` formatting, delegating capability evaluation to the shared checker. *(2026-08-15 architect review)*: the neutral contract MUST accept requirement sets from **both executables and reusable-activity templates** — the preflight's template fallback (`LoadRequirementsAsync` :100-103) is preserved capability, not publishing residue. Two recorded fixes ride along: (1) **diagnostics asymmetry** — `BuildDiagnostics` (:149-188) today emits no diagnostic for a failing `ActivityConsumer` (hardcoded to `DurableValueStorageDriver`); the wrapper gains consumer diagnostics from the shared result, mirroring `ActivityPublicationReviewPolicy`'s `activity.runtime.consumer-missing`/`consumer-schema-unsupported`. (2) **`UnknownActivityTypeException` classification** — it extends plain `Exception`, so `ActivityActivationFailureHandler.Classify` returns null and a missing CLR type is never classified as a deployment incident; re-parent to `ActivityResolutionException` + add an `ActivityActivationFailureKind` member (e.g. `MissingActivityType`) so the defense-in-depth path (an artifact that somehow activates past the gate) classifies as non-retryable `CorrectDeploymentAndResume` like every sibling failure.

**Rationale**: FR-B-005/005a as clarified; the checker's dependencies are all runtime-layer (verified); extraction (not duplication) is the reviewed pattern. **Alternatives rejected**: type-presence as a separate service beside the checker (two calls, two result shapes, and the import gate must remember both — one verdict is the spec's "rejected on either axis").

### D3 — ONE runtime-owned activation authority + lifecycle coordinator, neutrally named *(rev 2026-08-15, architect review — supersedes the unrenamed-relocation decision)*

**Decision** (clarified A2; revised per @sfmskywalker's PR #1330 review — "two reconciliation inputs are justified; two independent activation authorities are not"): the runtime gains **new, neutrally named** activation contracts instead of relocated publishing types — `IWorkflowActivationAuthority` (definition-keyed ledger: `(DefinitionId, SlotName) → active activation + Revision`, CAS transitions, `TryActivate` returning the replaced activation), `WorkflowActivationSlot` (carries an explicit **`WorkflowActivationSource`** ownership field), and a **`WorkflowActivationCoordinator`** (sanctioned `…Coordinator` suffix, §E6 R4) that owns the **complete activation lifecycle** for every caller: atomic slot transition, root-write lease, source-reference mint/retire, trigger-binding + recurring-schedule projections, trigger-index observer notification, and compensation. Publishing's `IPublicationSlotStore`/`PublicationSlot` are **superseded and deleted**; `PublicationActivator` (and the publish handler's activation sequence) become *callers* of the coordinator, retaining only compilation, publication policy, and `IPublicationRecordStore` history. The importer likewise *requests* activation — neither path implements the sequence. Rationale for neutralization: moving publication-named classes would remove the dependency while leaving duplicated authority intact and make Runtime responsible for concepts still named "Publication". Grandfathered per §E6's persisted-identifier scope rule (divergence documented at the site, renames out of v1 scope): `PreparePublicationAsync`/`ActivatePublicationAsync` on the projection stores and the persisted `PublicationId`/`SlotId` fields on source references and trigger bindings — the coordinator writes activation ids into those existing fields. Contracts land in `Workflows.Runtime.Core`, default implementations in `Elsa.Workflows.Runtime` (per ADR 0033; a dedicated `Runtime.Activation` sibling project is the fallback if the implementation cluster grows past the composition root's comfort — task-time call).

- **One durable implementation, one physical home**: a new slot document kind in the **runtime Groundwork store family** (`ElsaRuntimeStorageManifest` + `GroundworkRuntimeStoreRegistration`), registered whenever runtime Groundwork persistence is composed — exactly like the trigger-binding store. The publishing-family `GroundworkPublicationSlotStore` and its manifest entry are **deleted**. In-memory default in `AddWorkflowRuntime()` (`TryAdd`) remains the non-Groundwork fallback. An empty slot table on an engine that never activates anything is harmless — cheaper than feature-scoped provisioning machinery, and both writers (publish pipeline, importer) are served by one registration since publish-capable engines already arm the runtime spine.
- **Why one ledger** (PR #1330, Copilot #2): the earlier two-implementation design ("publishing's table retargeted in place + a reconciliation-owned runtime-family table, publishing wins on combined engines") had a composition-transition hole — a runtime-only deployment that imports (slots in the runtime table) and later enables Publishing would switch DI to the empty publishing table, blinding the cross-authority guard. The "no data migration" constraint that motivated retargeting-in-place is moot: **elsa-foundation has no consumers yet**. One physical ledger removes the precedence rule, the sticky-ledger guard, and the hole outright. Accepted cost: Groundwork historical-schema/target-baseline tests update (named task, pre-1.0 legitimate).
- **Explicit multi-source conflict rules** *(rev 2026-08-15 — supersedes the id-namespace guard)*: the slot's `WorkflowActivationSource` field is the ownership truth. Rules enforced by the authority/coordinator: **same artifact from any source → idempotent no-op**; **concurrent change → CAS on Revision**; **different artifact from a non-owning source → loud rejection** with a diagnostic naming the owning source (importer-side: per-closure-unit rejection, batch continues; publish-side: surfaces on the existing preflight conflict path). Ownership transfer is an explicit operator action, post-v1. Id prefixes (`import:{sourceId}:…`, `publication-…`) MAY remain for log readability but ownership MUST NOT be inferred from them (they are opaque strings; prefix-sniffing was the rejected earlier design).

**Rationale**: single ledger per engine (clarification A2) made physically true AND single lifecycle made structurally true — the earlier design shared the ledger but let each path drive its own copy of the activation sequence, which is duplicated authority in Sipke's terms; the `EnsureCanActivate` preconditions on the projection stores remain the enforcement backstop beneath the coordinator. **Alternatives rejected**: parallel importer-owned record (two ledgers, silent double activation), scan-derived state (no definition-scoped query on the source-reference store; no rollback anchor), retarget-publishing-table-in-place + precedence (the transition hole above), shared-table-with-migration (nothing to migrate), unrenamed `PublicationSlot` relocation + prefix-based guard (publication-named runtime concepts + inferred ownership — superseded by this revision).

### D4 — Closure envelope: new portable format, carried bindings are expectations

**Decision**: `WorkflowArtifactClosure` (model in `Workflows.Runtime.Core`): `FormatVersion` (int, starts at 1, fail-loud on unknown — mirrors `ElsaRuntimeDocumentVersions.Parse` discipline), `RootArtifactId`, `Artifacts` (root + transitive closure, each a `WorkflowExecutable`), `SourceReferences` (the exporting engine's Published-scope references — **provenance/expectations, not imported rows**), `TriggerBindings` (the exporting engine's active bindings — **expectations, not imported rows**). Serialization via `IPayloadSerializer` with the same converter discipline the Groundwork runtime document serializer uses (drop recomputed projections `Nodes`/`NodesById`).

**Importer treatment of carried collections**: the importer **mints its own** source references (SourceKind/SourceId from the reconciliation source, its own `PublicationId`/`SlotId`, `TenantId` from the source option, Published scope) and **recomputes** trigger bindings from the executable via the existing runtime `WorkflowTriggerIndexer.PreparePublicationAsync` (deterministic `WorkflowTriggerBinding.BuildId`). The carried bindings/references serve as an integrity cross-check: a mismatch between recomputed and carried trigger surface (node/stimulus set) is a broken-source diagnostic. This keeps binding identity and publication stamping engine-local (the exporting engine's publication ids are meaningless on the importer) while staying faithful to FR-B-001/010's envelope contents.

**Rationale**: the executable store is one-document-per-artifact (kind 9, create-only) — a closure is necessarily a new envelope; single JSON file per clarification. **Alternatives rejected**: importing carried binding rows verbatim (foreign publication ids; binding ids embed publicationId → guaranteed re-stamp churn); zip packages (deferred).

### D5 — Import pipeline: per-artifact gates, Model X alignment, wrapped exceptions

**Decision** — reconcile pass per closure file, then per artifact in **explicitly computed topological order** (dependencies first). *(rev after PR #1330 review, Copilot #12: `WorkflowExecutableDependencyGraph.ResolveClosure` returns its result sorted by artifact id/hash — `WorkflowExecutableDependencyGraph.cs:56-60` — NOT dependency-first; the importer computes its own topo sort over the validated graph. Persist-all-artifacts-first is order-free — the store is create-only — then activation proceeds dependencies-first so a parent never activates while a child's reference is absent.)*

1. **Parse + format gate**: unreadable/malformed/unknown `FormatVersion` → `InvalidWorkflowArtifactClosureException` (file-scoped, carries path; §2.23.5 wrapping — no raw `JsonException`/`IOException` escapes). Missing folder → pass-aborting `WorkflowArtifactReconciliationException`; empty folder → no-op (mirrors `JsonWorkflowReconciliationSource.cs:78,99-102`).
2. **Closure/dependency validation — against the envelope alone** *(rev after PR #1330 review, Copilot #4/5/6)*: wire-format validity is environment-independent — every `Dependencies` edge of every member must resolve **within the envelope's `Artifacts`**, with declared-hash equality, no identity conflicts, no cycles (`MissingArtifact`/`HashMismatch`/`ConflictingIdentity`/`Cycle` → reject the dependent, batch continues). FR-B-010 promises a self-contained transitive closure, so an envelope that only validates because the target store happens to contain a child is a broken export and must fail everywhere identically. The store snapshot is consulted **only afterward**, for idempotent persistence (already-present members are skip-persisted, never re-minted).
   **2a. Content-hash recompute** *(added after Greptile re-review P1; upgrades clarification Q6)*: before any member persists, recompute its canonical content hash via the runtime-owned executable hasher and compare against `Identity.ArtifactHash` (and the id-embedded hash prefix); mismatch → broken-source diagnostic, member and its dependents rejected. This is the **third extraction**: `WorkflowExecutableHasher` (`src/Elsa/Workflows/Publishing/Services/WorkflowExecutableHasher.cs`) moves to the runtime layer as `IWorkflowExecutableHasher` (contract in `Workflows.Runtime.Core`, default in `Workflows.Runtime`); its canonical payload reads only `WorkflowExecutable` model data (rootNodeId, incidentStrategy, ordinally-sorted nodes, inputContract, dependencies — verify exact dependency set at task time), so the move follows the checker's precedent; the compiler becomes a consumer of the relocated service. Rationale: guards the ADR 0038 content-addressing invariant (equal hash ⇔ equal behavior; create-only dedup assumes id ⇔ content) against corruption/drift — explicitly NOT tamper-proofing (deterministic public hasher; signing stays deferred). *(2026-08-15 architect review)*: the extraction MUST be **byte-stable** — same canonical algorithm, same payload version, identical hashes for identical input before/after the move, pinned by a golden-hash test over a fixture executable.
3. **Requirements gate** (D2): both axes; any unmet → per-artifact rejection diagnostic; not activated. Trigger-surface cross-check (D4) folds in here.
4. **Idempotency/supersession** (Model X §E2.8 by extension): artifact already in store with same id → content-addressed no-op (`SaveAsync` is create-only; `ConcurrencyConflict` = already-exists). Same `(DefinitionId, ArtifactVersion)` claimed with different content → broken-source diagnostic (mirror `ActivityVersionHashMismatchException` shape — the workflow-design reconciler's log-only behavior is the weaker precedent; artifacts are content-addressed so the typed throw is safe here). **Latest-wins comparator** *(added after PR #1330 review, Greptile #14)*: "newer" = SemVer sort key over `ArtifactVersion` (`SemVer.ToSortKey` in `Elsa.Primitives.Versioning` + ordinal compare — the design reconciler's own mechanism, `WorkflowsVersionReconciler.cs:78-85`; the design store already indexes `entity.semVerSortKey`). Candidate ≤ active → skip; unparseable `ArtifactVersion` → reject with diagnostic. The active version is read from the active publication's minted source reference (carries `ArtifactVersion`) — no new state.
5. **Activate — one request to the shared coordinator** *(rev 2026-08-15, architect review — the importer no longer implements this sequence)*: the importer submits an activation request (artifact, definition/slot, its `WorkflowActivationSource`, minted activation id, tenant option) to the **`WorkflowActivationCoordinator`** (D3), which owns the full lifecycle for every caller: root-write lease (`IWorkflowExecutableRootWriteLeaseManager`, so reference GC cannot race) → mint/save live source reference → prepare **both** projections (trigger bindings via `IWorkflowTriggerBindingStore.PreparePublicationAsync` with recomputed bindings; recurring schedules via `IRecurringTriggerScheduleStore`) → slot CAS on the activation authority (conflict rules from D3 applied here: same-artifact no-op, non-owner rejection) → activate both projections → notify `IWorkflowTriggerIndexObserver` → retire the predecessor's reference (`"publication-replaced"`). The coordinator's internals absorb publishing's `PublicationActivator` sequence + `CompensateActivationFailureAsync` (:103-139): on failure after the slot flip it restores the replaced activation, re-activates its projections (`forceReplay`), removes the candidate's projections, and retires the failed reference (`"publication-activation-failed"`). Publishing's `PublicationRecord` bookkeeping wraps *around* its coordinator calls (stays publishing-side); the intent-store retry machinery is not pulled down — the importer's recovery unit is the next reconcile pass (idempotent by steps 1–4 + coordinator compensation).
6. **Closure-unit isolation** *(rev after Copilot re-review; supersedes per-artifact isolation)*: the isolation unit is the **closure file** (root + transitive dependencies). Steps 1–4 complete for the **entire unit before any write**; any member failing any gate rejects the whole unit with a named diagnostic — a failed unit writes nothing (no sibling persistence, harmonizing US2-3's mixed-batch semantics with the "no partial import" edge case). One unit's failure never fails other units in the mounted set; every rejection is a diagnostic on the pass result + log.

Startup: `WorkflowArtifactReconcilerStartupTask`, `[SingleNodeTask]`, distributed lock (`TryAcquireLockAsync(nameof(...))`, null-lock → log + return, mirroring `WorkflowsVersionReconcilerStartupTask`), ordered **after** `RegisterActivityTypesStartupTask` — mechanism: `[TaskDependency(typeof(RegisterActivityTypesStartupTask))]` (topological sorter honors it; requires a project reference to `Elsa.Activities.Runtime`, acceptable: the reconciliation feature is a leaf and any executing runtime composes `ActivitiesRuntime` anyway). Fallback if the attribute shape doesn't fit: `[Order]` above the scan task's order + documented. Re-reconcile: existing shell-reload path re-runs startup tasks (FR-B-008; no new coordinator).

## Risks

1. **Activation-authority neutralization blast radius** *(rev 2026-08-15)*: larger than the original relocation — publishing's slot contract/store/tests are superseded (deleted/rewired, not renamed in place), and `PublicationActivator` + the publish handler's activation sequence are refactored into *callers* of the shared coordinator. Mitigation: behavior-preserving by construction (the coordinator absorbs the existing sequence verbatim, including compensation); golden rule §2.21.1 — existing publishing tests must pass with wiring/location changes only, never objective changes; the coordinator inherits publishing's activator test matrix as its own baseline.
2. **Groundwork schema baselines** (D3 rev): moving slot storage into the runtime store family changes the physical schema set — `HistoricalSchemaUpgradeTests` / target-baseline tests must be updated deliberately (named task, legitimate pre-1.0 with no consumers). Silent baseline churn is the failure mode to avoid.
3. **`ExecutableDocument` legacy fields**: the store's private document shape carries legacy lease/guard fields — the importer writes through `IWorkflowExecutableStore.SaveAsync` only (never raw documents), so no exposure.
4. **Startup-task ordering across assemblies** (D5): `[TaskDependency]` signature must accept a cross-assembly type; verify at task time, fallback `[Order]`.
5. **Capability contract-version**: adding a rel to `elsa.api.publishing` may require a `contractVersion` review (additive → no bump expected; confirm against capability doc rules).
6. **Import compensation coverage** (D5 step 5): the compensation path is branch-heavy (§2.23.2 demands every branch tested) — failure injected between each pair of steps in the activation sequence is the test matrix, mirroring publishing's activator tests.
