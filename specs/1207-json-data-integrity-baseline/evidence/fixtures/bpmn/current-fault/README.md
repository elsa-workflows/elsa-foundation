# Current concurrent-fault stores

These six complete SQLite backups come from the ordinary current writer in
`A_concurrent_service_fault_settles_every_original_start_without_another_semantic_decision`,
captured at `cc3ab5bf7db1a5313da7693cfecc5a7b846fcdce`. The two scenarios retain the initial two
requested starts, the authentic fault with cancellation still owed, and settlement after a cold
service-provider restart with new admission disabled. This is an SDK/store restart witness.

Each receipt binds compressed and raw bytes, its capture report, all table row counts, the clean
writer source and nine actual loaded binaries, including the canonical and schema hash writers.
The packager checks the original physical identities, native worker count, accepted result or
not-admitted retirement receipt, and acknowledgment order to exact .NET ticks. Four Python controls
cover missing/stale writers, changed bytes, rewritten histories and early acknowledgments. The
focused replay/refusal group initially passed nine tests; subsequent changes require its rerun.

The unchanged spec1017 originals are linked and independently pinned in every receipt. Those
historical captures contain the fixed `TerminalSettled` plus outstanding work bug. A current writer
correctly records `TerminalPendingSettlement` and cancellation debt, so these stores do not claim
historical late-start upgrade acceptance. Initial requested attempts and later cancellation-pending
attempts have separate inspection checks. Historical hash refusal preserves all original payloads;
the initiative's existing startup recovery adds exactly one scheduler input. The refusal itself
changes no physical row. No old-hash verifier or fixture-repair shim was added.
