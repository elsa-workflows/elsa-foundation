# Data model: Local composition file bridge

The [semantic v1 contract](contracts/file-bridge-v1.md) controls the portable/local boundary. These types describe an implementation seam; exact C# names can change without changing the contract.

| Entity | Fields and relationships | Validation and lifetime |
|---|---|---|
| `SourceSelection` | Host directory, shell ID, environment ID, pinned catalog input, explicit supported-file mode. | Required at each invocation. IDs are safe references; paths stay local and never enter a portable result. An explicitly selected missing overlay refuses. |
| `SourceSnapshot` | Copies of all supported root `shells*.json` and `appsettings*.json` files, selected base/overlay identities, private per-file content digests, original bytes. | Invocation-local. Reject unreadable, symlinked, escaping, malformed, or duplicated sources. Recheck *every copied file* before acceptance and publication. Never serialize snapshot or digests to authored output. |
| `LayeredHostView` | Selected shell's exact enabled IDs and object-map disabled IDs; setting paths with value, type, presence, and base/overlay provenance; shell resource bindings; selected appsettings resource definitions. | Derived from raw JSON layers. Object-map overlays may override the same ID/path; array overlays replace numeric indexes, leaving untouched base indexes. Duplicate or case-equivalent IDs within a layer or the effective array refuse. Cross-shape object-map/array layering refuses in v1. Process environment, CLI overrides, and unselected overlays are not effective evidence. |
| `PortableFieldReview` | Exact feature/JSON-pointer path, expected JSON type, explicit safe classification from a local review file, source layer for an existing field; reviewed logical resource names/bindings. | Deny by default. A declaration covers one exact path, not a parent subtree. A newly authored path needs an explicit target layer. Unknown nonempty or secret-like values cannot be inferred safe from type or name. Mismatched type refuses. |
| `ImportPreview` | Safe IDs, selected-file effective state, classified field values, masked unclassified field identity/type/presence, provenance, planner findings, unchecked evidence labels, private snapshot association. | Redacted projection only. No raw path, connection, unknown raw value, source bytes, or exception text. Preview is never accepted by default. |
| `ReviewDecision` | Which preview/diff was shown, explicit acceptance/cancellation, snapshot identity, accepted field paths. | Invocation-local and single-use. A changed snapshot invalidates the decision; cancellation publishes nothing. Non-TTY callers have no accept-all shortcut in v1. |
| `AcceptedAuthoredComposition` | Existing `AuthoredComposition` v1: exact catalog pin, null profile, empty groups/locks, enabled `add` and `accepted.featureIds`, disabled `remove`, reviewed safe settings and logical resource refs. | Strict v1 top level. The shared planner resolves candidate IDs; if candidate and accepted IDs diverge at generation, refuse until the document is explicitly revised. No source path, provider, physical connection, or unknown raw value. |
| `GeneratedCandidate` | Private copies of supported source files plus patches only at reviewed feature/setting/resource paths; redacted semantic diff. | A fresh output directory only. All other JSON nodes stay semantically equal; untouched files should stay byte-identical. Stage privately, recheck source, then publish atomically. |

## State transitions

`SourceSelection → SourceSnapshot → LayeredHostView → ImportPreview → ReviewDecision → AcceptedAuthoredComposition`. Import refusal or cancellation ends without an authored file. A later `composition generate` starts a **new** source snapshot, reads the accepted document, validates its catalog pin and exact selection, computes a candidate and redacted diff, receives a new review decision, and publishes a fresh directory. The accepted document does not prove that a later source snapshot matches the earlier one.

The [existing planner](../../src/essentials/Modularity/Planning/Services/SelectionPlanner.cs) alone computes selection/dependency findings. The bridge maps observed enabled IDs to `add` and explicitly disabled object-map IDs to `remove`. It refuses a new `remove` decision targeting array syntax rather than inventing an array disabled-state encoding, and does not invent profile, groups, packages, or readiness. Resource-name existence in selected local definitions is a syntactic reference check only.
