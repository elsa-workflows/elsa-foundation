# Actual local, correlation and TestRun receiver recovery

This bounded T051 increment qualifies local/correlation eligibility and TestRun receiver isolation through actual owned source-built hosts. It leaves T051, historical upgraded-host/Studio acceptance and the adoption PR open. The [machine-readable receipt](broadcast-scope-recovery.json) binds the source and portable host observations.

|---|---|
| `local-scope` | A catalog-authored native Parallel parks two Event waits and a gated PublishEvent with IsLocalEvent=true. An ordinary unique control stimulus releases that send. The saved cohort contains only the publisher's two waits and zero starts; same-name preexisting published and TestRun listeners remain excluded. Standard-host fence 1→2 recovery completes only those two callbacks. |

Each scoped case creates two actual same-artifact TestRuns using the normal version TestRun API. Their authoritative SQLite scopes are distinct, open and unexpired; their real suspended waits physically match the stimulus in the same persistence/partition context. Before the crash, their official wait API views expose the exact two bookmark IDs through the installed Event driver. Complete physical projections and full API instance/activity records remain unchanged across normal source recovery; no callback, receipt or incident appears in either scope.

A third actual TestRun of that same artifact proves private deliverability before the crash, while its original Publishing handle is live. The official wait/event APIs deliver both exact waits, one durable receipt per consumption. Each requested bookmark retires, the other original generation remains unchanged, and the corresponding exact activity completes with one additional attempt and no remaining bookmark. Repeating the first delivery before the second returns AlreadyDelivered and preserves full physical/API facts. The real BPMN join completes. Both untouched original test scopes and every normal workflow/source remain unchanged throughout; the completed third execution also retains its full physical/API facts after restart.
