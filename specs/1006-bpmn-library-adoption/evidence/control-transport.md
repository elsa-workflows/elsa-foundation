# Immutable control sources and terminal resume (T042)

This increment stages one deterministic nonterminal notification intent and carries a terminal root batch only in the existing single waited parent-resume result. Fixed safe diagnostics, policy-safe outputs and ordinary DispatchWorkflow outcomes remain intact. Completed, Faulted and Cancelled child workflow facts do not become a fabricated local leaf fault or foreign incident absorption.

A nonterminal projection atomically retains its logical source commit ID with its outbox responsibility. Carrying that projection into another checkpoint never emits it again, including another checkpoint from the same scheduler work. A new batch resets the anchor; an equivalent staged precommit re-enrichment remains valid. Replaying an equal or older ordinal requires its original source row even after the root advances. Missing authority is refused rather than reconstructed. Source work identity alone was insufficient; review caught and corrected both same-work carry-forward and older-source replay cases.

The notification responsibility belongs to the producing child workflow/root. Its immutable typed payload carries the exact parent/call/consumer address. The actual running-root witness initially caught an invalid parent-owned notification responsibility; using the same source-ownership pattern as child-start work preserves the generic checkpoint target invariant without weakening it or inventing a terminal dispatch. Coalescing can fold the logical source checkpoint into a later outer provider commit; the source outbox row and matching root anchor still commit atomically.

The scoped replacement IRuntimeChildControlAuthorizer resolves the retained exact boundary and looks up the carried source commit/intent/outbox identity directly. It verifies the whole immutable transport payload, ordinal and target independently of the latest root projection. Missing, forged or conflicting authority refuses. Store/JSON failures retain their contextual domain exception and original cause; cancellation passes through. Override, lifetime and missing/duplicate-provider controls are included.

Opted-in terminal resume authorizes the source and compares the complete result against the persisted source payload before completing the leaf. Omitting its terminal barrier, changing notifications or adding forged outputs refuses before completion. The original activity constructor and completion-enricher constructors remain available. The generic IRuntimeChildControlCompletion result projection copies validated terminal control into ActivityExecutionState.ChildControl in that same leaf completion checkpoint. The runtime snapshots this public getter inside the resume fault boundary before activation disposal; a throwing getter becomes the normal consumed ActivityResumeFaulted outcome with disposal, rather than poisoning scheduler work.

Actual in-process runtime witnesses verify successful and authored-fault child terminal checkpoints, one exact-source resume, ordinary leaf Completed status with its matching outcome and no local fault, complete typed leaf projection, truthful child fault/incident and separate safe diagnostics. An actual still-running structural root executes and schedules a real child while staging two ordered notices; its one pending source row and matching root anchor share the provider commit, and that row authorizes successfully. These are actual writer/resume controls. They are not upgraded-host, nonterminal delivery, ordered inbox, EF crash/restart or BPMN consumer qualification. Nonterminal delivery is not attempted in the staging witness; its handler and retry/acknowledgement path belong to T043 before the BPMN consumer is enabled.
