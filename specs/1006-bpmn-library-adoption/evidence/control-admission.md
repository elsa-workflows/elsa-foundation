# Called-workflow capability admission (T040)

This increment admits a generic control capability for one exact waited dispatch and resolves its retained root/caller/consumer address. It does not stage authored notifications, deliver outbox control, process an inbox or wire the BPMN consumer.

The compiler reads ActivityChildControlConsumerAttribute only on a structural consumer marker and writes owned key/version metadata without activating the type. DispatchWorkflow accepts requested capability only from its committed scheduling provenance, matching its exact direct parent's pinned declaration; ordinary no-capability and legacy paths retain their behavior. Fire-and-forget and mismatched capability refuse before any dispatch/start responsibility is staged.

The scoped single-provider boundary validates the admitted dispatch, child/caller executable snapshots, exact invocation/root history and scheduling provenance, tenant/partition/run kind/test scope/depth/authority. A parent workflow ID or lookup hint alone grants nothing. Cancellation/terminal history retains its address, while actual delivery will separately handle retired targets. Both shipped stores commit Started in TryAdmitAsync before child launch, so the earlier proposed Pending exception was removed and reviewed before resolver implementation.

The actual host witness resolves inside the child's initial Execute, observing committed Started and the exact root/caller/consumer identities. Its ordinary child control observes no capability. A retained terminal lookup is checked too. The actual host initially lost its hint because request metadata is not automatically workflow system metadata; explicit bounded preservation through start/completion and start-fault fallback corrected that failing witness.

The public service documents its replacement/override rules and contextual WorkflowControlBoundaryException with original InnerException. Cancellation passes through. Controls cover store failure, cancellation, scoped lifetime, explicit replacement, and missing/duplicate startup registration. Constructed state controls separately exercise conflicting retained identities and scope; they are not upgraded-host or control-delivery proof.
