# Permanent BPMN test reconciliation

This reconciles all **242 unique class-plus-method identities** in the permanent [four-part audit](https://github.com/valence-works/bpmn/issues/38#issuecomment-6392471534) against the actual Foundation adapter and released BPMN **0.5.0**. The historical disposition is preserved: 197 ported, 23 covered on main, 19 host-only and 3 intentionally changed. None of these 242 scenarios is deleted. Five selectors are renamed explicitly below. Theory cases count separately from methods. New adapter/compatibility tests are listed separately in the [machine map](semantic-ownership/242-method-map.json), not substituted for baseline methods.

All current selectors execute successfully in the whole BPMN suite. The [qualification](semantic-ownership/qualification.json) compares complete discovery and TRX display-name multisets, not just totals: BPMN 308, Interchange 130, Runtime EF 1,710, zero failures/skips. Portable compressed original TRX and discovery logs are in [the bundle](semantic-ownership/). The refreshed EF run and restored whole BPMN run qualify the current package source. These library/adapter/provider results do not substitute for post-deletion upgraded-host or Studio proof.

The [released anchor map](semantic-ownership/released-neutral-anchors.json) rereads immutable original and released source. It verifies method names and updated line locations, separately from host assertion equivalence. One prior escalation-host name is replaced by A_task_cannot_host_an_escalation_boundary, as already recorded in the parity PR. Historical implementation anchors remain labeled as such. Neutral links are context; the passing Foundation selector is the execution evidence.

## Fixture and expectation changes

Graph-focused host tests now call BpmnGraphAdapter.Build with Foundation authored payloads and complete compiled work inventory, rather than the deleted Foundation graph. Assertions inspect neutral BindingRef/ListenerBindingRef while authoring/roundtrip assertions retain childNodeId/listenerNodeId. Host exceptions retain the original library cause and its structural diagnostic. Runtime diagnostic literals retain their exact original strings without copying a constants-only engine facade.

Three backward-edge graph fixtures gain a bound work step so their unchanged cycles can wait under the released safety profile; the original flow/backward-edge assertions remain. A separate immediate-cycle refusal test covers the rejected profile. Duplicate catch-all boundaries and unbound signal/cron-only invalid fixtures remain rejected with precise released diagnostics; new positive graph controls cover distinct coded boundaries, bound signal and a valid cron cycle. The cron control establishes graph representation only: the current binder still reports cycle delivery unsupported.

One test added after the baseline audit, Original_reader_explicitly_refuses_an_actual_new_host_v2_checkpoint, is retired because it called the now-deleted old state persister. Its historical source/result remain in Git history. No fresh old-reader parse is claimed. Current EF upgrade assertions instead verify the actual continued v1 alias/schema/wire names and original per-record field presence against the captured document. Actual old/current process recovery evidence remains independent in [the active-compensation witness](ordinary-compensation-host-recovery.md) and [called recovery](legacy-called-workbench-recovery.md).
