## Placement and extension boundary

Use a native structural StateMachine activity and internal native state-visit activities in the same workflow execution. A machine or visit stays live while coordinating its ordinary children. Normal lexical frames belong to those real native owners. Source and target visits retain their applicable frames through Exit and Action; close exiting visits from children outward after Action, before target Entry. Preserve continuing parents and action-without-exit visits. No state-machine domain, workflow execution model, Saga type, independent scheduler or authored asset lifecycle is added.

Generic delivery tracking, pure invocation admission and exact invocation control belong to Workflows.Runtime and Activities.Runtime. State/transition selection, queue semantics, phase plans, completion opportunities and progress limits belong to the StateMachine activity implementation. Kernel code selects a declared capability/protocol; it does not select behavior by StateMachine/BPMN type names. Normal source, fence, checkpoint, value, fault and retention owners remain authoritative.

Pin a versioned optional invocation-input capability in ActivityContract, omitting it from old wire/fingerprint shapes when absent. Registration binds that pin to a pure admission reducer and a structural control callback. The reducer uses committed runtime-owned receiver state, never an activated activity instance or its resolved Entry inputs. The callback activates the ordinary activity with normal hydration/masking/scoped-variable projection. Executable compilation refuses an unsupported capability before a new machine can run.

## Canonical external stimulus source and cardinality

Introduce one runtime-owned **stimulus ingress source** for opted-in external fan-out. It has a real server-assigned ID, trusted persistence/tenant/run scope and admission authority, versioned request fingerprint, immutable selected start/wait cohort plus consumer manifest, fenced delivery state, per-recipient dispositions and owed seal deliveries. Persist it as a new source family in the existing runtime persistence composition. It is the canonical source, not a second ledger for a post-commit publication and not an API-owned queue. It requires no fictional publisher workflow.

Keep post-commit publications in their existing outbox rows and source claim protocol. Extend the existing RuntimePostCommitOutboxProcessor/resumption delivery orchestration with an ingress-source contribution, using the normal fenced-claim primitive and source-owner completion rules; do not launch another pump/scheduler. The source adapter supplies its real source address and validated content, rather than fabricating PostCommitDeliveryContext or RuntimePostCommitIntent with a fake workflow ID. Retention roots include either actual source family until all delivery/consumer obligations are discharged.

For external routing, capture all pre-existing matching wait generations and selected starts before starts or resumes have effects, then atomically install the complete ingress source and manifest. Concurrent keyed retries read the first committed source winner rather than match fresh waits; a lost response resolves through the same scoped source identity/content. An unkeyed call gets a new server source ID. Public idempotency keys select that ordinary retained admission; they are not delivery authority. Source retention and retry-window policy must be explicit in the ingress capability, separate from A1's machine-business receipt promise.

Opted-in consumers receive every exact captured matching wait in their trigger subtrees. Ordinary non-opted-in resolution retains its existing ambiguity rule, determined from the same pre-effect match snapshot: it must not newly resume a legacy wait which the original matching set would have made ambiguous. Skip the legacy branch when no legacy recipients exist; otherwise retain its explicit success/refusal/ambiguity result beside opted-in recipient outcomes. Do not choose a legacy winner by subtracting opted-in waits and rerunning lookup. Existing starts precede resume effects, and fresh waits created by those starts are not cohort members. Source/header preflight occurs before either path's first effect; ordinary per-recipient refusal remains partial, not rollback of already performed effects.

Keep old routes unchanged when no opted-in consumer is involved. An unsupported selected composition refuses the opted-in route before effects; it cannot run starts first and discover the missing durable fan-out boundary afterward. Exact direct resumes use the same ingress source with one original captured recipient. Timer/background/return owners use their actual committed occurrence/result sources, with the classifications below.

## Target handoff, source seal and causal progress

Choose a **tracked-delivery admission operation** on the existing target workflow actor. The normal dispatcher validates the current canonical source/claim and its immutable manifest, then sends one deterministic admission operation per exact consumer, containing that consumer's captured recipient slots. The operation establishes the normal target execution fence and checkpoint before entering a native resume handler.

That checkpoint seeds the full group, records each accepted slot Queued, and creates its ordinary exact-resume enqueue intent atomically. The intent is the durable work obligation; transport enqueue alone is not the source acknowledgment. Native material/owner reads, validation, activation and bookmark consumption happen afterward. Consequently their early return/fault/poison paths always have an existing source/slot/work relation to settle, park or block. Retired original waits receive explicit retained retirement evidence. Duplicate admission cannot create another intent or overwrite the first manifest. It does not consume replacement waits.

The actual bookmark-consumption checkpoint marks Applied and advances the same token into its resume-attempt stage. RetainSchedulerWork keeps the token outstanding at attempt-claim boundaries; the corresponding activity decision transfers/parks it. No separate claim, native work ID or queue acknowledgment can settle it prematurely.

Extend normal source-claim completion with a typed successful-delivery finalization branch which atomically records exact source dispositions and one owed **seal batch**. For publication sources this is an additive claim-completion/outbox branch, distinct from the existing dispatch-failure follow-up. For ingress sources it is part of that source's own fenced completion transaction. Delivery of the batch uses its own current claim and references retained original final evidence. Each consumer seal is acknowledged only after durable target acceptance. Source completion must not wait for semantic transition work, and target closure must not wait for the acknowledgment of its own closure wake-up.

| Native/runtime boundary | Chosen responsibility treatment and hook |

Receiver admission accepts that exact set once; the semantic activity subsequently evaluates it under its normal work/recovery gate. Semantic rejection/staleness is an explicit disposition, not reopening the group. Result/value roots transfer to the receiver's retained input at acceptance before group cleanup releases its holds.

## Invocation controls, guards and lifecycle

Add distinct internal native invocation **admission** and **control execution** commands through the existing actor/router/pipeline. Public business-event endpoints cannot manufacture a phase control. Ordinary transport command IDs remain separate from business IDs: the mailbox cache must not swallow a same-business-ID/different-content attempt before the semantic conflict check.

Pure admission permits initialized live receivers in Running, Waiting or Suspended under a nonterminal workflow and the existing writer; it rejects Scheduled/uninitialized receivers as not ready. Workflow pause may retain admission but blocks evaluation; normal cancellation remains available. Faulted, Cancelled, Completed, Recovered and Superseded owners admit no new work. Retained duplicate/conflict/receipt queries use the committed projection without reactivation, including after workflow terminality. Waiting caused by missing activation dependencies must not require those dependencies for an already initialized pure reducer.

Authored phase/control execution permits a Running live visit whose pinned capability, sender relationship, operation and phase match. Waiting/unavailable activation leaves its control obligation pending through normal incident policy; terminal owners yield explicit stale/ended results. Controls derive executable slots from pinned owner structure, not arbitrary sender-supplied node IDs. Transport acceptance schedules a phase at most once; ordinary child completion is the separate phase acknowledgment. Close controls cannot reopen frames.

Evaluate conditions through ordinary internal condition-work children in the relevant live state's lexical scope. The machine retains its Evaluating input/configuration and guard-result progress before scheduling those children. A guard failure stays at that recoverable child boundary; the machine remains live, preserves previous successful evaluation/phase work and accepts bounded inputs. Resume/retry follows normal eligible recovery and external-effect rules. No guard exception is converted to false or unhandled. Selection persists the transition set, cancellation/exit set and complete phase plan before authored Exit/Action/Entry work. Every plan/phase acknowledgment names a logical operation plus its actual child lineage, so normal eligible child successors preserve completed siblings without redirecting machine receipts to a new receiver.

Receiver or ancestor supersession uses A1/r2's atomic old-address settlement. NewSuccessor must explicitly clear new invocation-input/control fields instead of copying them with a record `with` expression. Only eligible continuing-receiver child recovery transfers phase/trigger responsibility. The normal fault recorder still closes a terminal owner's frames.

## Coalescing, adoption and first implementation boundary

Classify changes to tracked source/slot/work state, pure admission/receipt, semantic selection/phase-plan and invocation control acceptance as durability-critical in CoalescingRuntimeCheckpointCommitStore and RuntimeCheckpointFold. Flush the complete buffered segment and the new boundary to physical storage before acknowledgment or externally deliverable follow-up. This first implementation favors a simple physical boundary for every tracked responsibility mutation; Balanced remains the host default and ordinary untracked work keeps its normal behavior. Any later relaxation needs equivalent crash/closure evidence, not a renamed flag.

Implement and qualify the generic source/group/input/control slice as an M0 integration work unit before treating native StateMachine placement as qualified or closing #3820. Use the real normal ingress, actor/checkpoint, native work and physical stores. The source-level decision may be adopted after independent review under the fresh owner instruction; actual capability proof remains a delivery gate. No successful prototype result or advisory is substituted for that proof. The full hierarchy/parallel/Studio/saga implementation follows the reviewed specification and technical plan; it is not reduced to this shared slice.
