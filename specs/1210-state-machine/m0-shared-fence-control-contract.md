# M0 shared delivery fence and invocation-control contract

> Historical M0 research/proposal, recovered from 6 November. See [current status](README.md); revalidate runtime mechanisms against the 12 November kernel direction before implementation.

**Revision:** C1/r2, proposed for independent review and shared-runtime owner coordination. The revision makes queued-versus-consumed handoff explicit and identifies the actual HTTP ingress gap.

**Authority:** The [scoped principles decision](https://github.com/elsa-workflows/elsa-foundation/issues/3815#issuecomment-6669211076) agrees the [input/occurrence and owner-lifetime principles](m0-input-profile-proposal.md). It does not approve the mechanism below, its API/schema, native placement or the production plan. All names below describe proposed logical records/operations, not published CLR contracts. Q1–Q3 remain open. No producer or implementation is authorized by this document.

**Route:** StateMachine M0 #3820 within Program #3815; shared source, scheduler, checkpoint and native-control ownership must be coordinated with Unified Execution #2892 before shared code changes. Existing native/BPMN/model contracts retain their current semantics and qualification boundaries. Draft Model X and constitution §E2.9 are not authority for this design.

Those IDs do not supply a shared publication identity.

The source claim/content/scope still need normal revalidation before effects.
- [Outbox completion](https://github.com/elsa-workflows/elsa-foundation/blob/9eaed8b3302f7cdaaa8366315adfbc37b181d92a/Essentials/src/Workflows/Runtime/Elsa.Workflows.Runtime/Services/Checkpoints/RuntimePostCommitOutboxProcessor.cs) has an atomic claimed-delivery completion path with a specific dispatch-failure follow-up. Reuse or extend that owner deliberately; its current follow-up is not proof of a generic chart fence.

It does not implement or qualify the records or transitions below.

## Records and authority

| Proposed logical record | Required fields and authority |
|---|---|
| Current cause | Persistence/tenant scope, registered canonical source kind, stable source ID/fingerprint and delivery protocol. A saved publication uses its complete outbox identity; another ingress must have its actual committed source identity. Created by validated runtime delivery, not public payload IDs, caller metadata or one command ID per fan-out recipient. |
| Original provenance | Optional retained reference to earlier input/result ancestry, such as A when a later B completes a composite. It grants no dispatch, admission or grouping authority. |
| Consumer address | Exact workflow execution and native receiver invocation, pinned material, declared receiver protocol/version and expected hierarchy boundary. An operation key, node name or latest activation is not a receiver address. |
| Source recipient manifest | Immutable association of the winning saved recipients with their captured consumer addresses and original trigger/visit identities. Install with the winning source cohort before its first effect. It adds no recipients or replacement waits. |
| Delivery group | `(scope, target workflow, consumer invocation, current cause)`; immutable manifest identity, revision, unresolved recipient slots, causal work tokens, failure/disposition evidence and closure state. It belongs to the target execution's existing writer. |
| Causal work token | Stable durable native scheduler/control work ID and stage, consumer/group, current activation/attempt where applicable, predecessor and state. Retries do not create an untracked second token. |
| Ready occurrence | Exact trigger activation/attempt and committed completion/result reference, original visit, current cause and any earlier provenance. It is distinct from a business admission receipt. |
| Internal progress chain | The semantic receiver's persisted chain ID, count, effective limit and blocked/recovery state. Controls/continuations carry the current ID; group closure, a new work ID or a queued arrival does not reset it. This is separate from the group's outstanding-work count. |
| Invocation control | Stable command ID, exact sender and receiver addresses, source checkpoint/outbox authority, declared control kind, semantic operation/phase ID and bounded typed payload. Receiver derives allowed slots from its own pinned material. |

For saved post-commit publications, the source-side manifest is proposed as an optional typed source-header contribution installed atomically with the normal winning cohort. Other ingresses require the real durable source/admission boundary specified below. Their concrete representation/version requires shared-owner review. The per-target group/tokens are proposed runtime checkpoint state in the target execution aggregate, not an API queue or a second scheduler. The source deliverer must not write another workflow's activity/private state directly.

Consumers opt in through a versioned generic runtime capability. The kernel does not branch on a StateMachine/BPMN model name. Runtime validation captures consumer membership from real admitted scheduling/hierarchy information, including the trigger role; an arbitrary descendant of a machine is not automatically a trigger recipient. The declaration cannot move work into another lexical parent or expose closed-scope values.

| Group state | Allowed meaning and progress |
|---|---|
| Open | Manifest known; source seal or recipient/work dispositions remain owed. A zero work count alone cannot close it. |
| SealedWaiting | Matching source seal is committed; native causal work still remains. Continue only through accounted transfers. |
| Blocked | A failure or unknown obligation needs its normal recovery/disposition. Preserve the prior accounting and completed work. |
| ClosedReady | The closure predicate and fixed ready set were committed once, with the owed receiver input. No new tokens join or reopen it. |
| ConsumerEnded | Canonical receiver/workflow terminality ends selection for this address. Retain the explicit disposition and discharge remaining transport obligations; do not activate the receiver to resume evaluation. |

Normal terminal checkpoints must reconcile the affected open groups with the actual ended invocations. Later delivery may resolve their retained ended disposition without executing the owner. Already closed/ended groups and superseded history are not rewritten by a broad cancellation sweep. The concrete terminal participant and retention lookup remain part of shared-owner review.

## Ingress coverage and recipient responsibility

| Actual ingress | Required treatment before feature enablement |
|---|---|
| Saved post-commit publication | Use the existing canonical source/cohort, with its validated immutable consumer manifest and stronger target handoff proof. |
| Runtime HTTP/global fan-out | `StimulusDispatchService` calls `IStimulusRouter.RouteAsync`, not the saved-source path. Capture one real durable ingress/source and its immutable fan-out identity before recipient effects; do not synthesize unrelated causes per recipient. The exact adapter/storage placement must be agreed with the execution-model owner. This required path is not qualified by N10 and cannot be silently left with weaker grouping. |
| Exact direct bookmark resume | Capture the actual committed singleton ingress and exact original recipient, linking its target responsibility before recipient code. It is not proof of a shared fan-out identity. |
| Timer, background/offload completion, native/model-call result | Use that normal owner's actual committed delivery/return cause and declared durable boundary. Preserve earlier provenance; do not infer current cause from returned data. Each boundary needs explicit compatibility qualification. |
| Native child/control continuation | Inherit the existing group until a real recorded boundary, transferring its token atomically. A new scheduler work ID or drain yield alone is not a new input. |

No ingress may invent a publisher workflow merely to fit an outbox shape, install a private API queue, or use user idempotency strings as trusted source identity. Existing routes outside the opted-in capability retain their declared behavior. The full initial StateMachine profile must qualify its named normal ingress paths; an unsupported coherent boundary refuses admission before effects and remains a delivery gate, not a downgrade to singleton arbitration.

Recipient slots have explicit states: **Expected**, **Queued**, **Applied**, **Retired** or **Blocked**. `Queued` requires a durable target command/work link but does not mean bookmark consumption, trigger success or eligibility. `Dispatched`/`AcceptedQueued`/`AcceptedButFaulted` alone cannot settle a slot. An `Applied` consumption checkpoint or an authoritative retained fault/retirement disposition is required. A failed or missing handoff stays owed.

A group may first be observed through a source seal arriving before recipient execution. Either path creates/reads the same immutable manifest and full expected slot set under the target writer; a seal does not manufacture Applied outcomes for unregistered slots. Registration/link failure cannot let recipient code run without the cause/slot relation already durable. Every early no-op, hydration failure, activation failure, poison and retirement arm must settle or block that relation explicitly through the normal checkpoint/fault owners.

## Closure algorithm and checkpoints

1. **Capture before delivery.** Normal source selection fixes the original cohort and the optional consumer manifest together. Preserve the first winning snapshot, including an empty one. Re-read the canonical winner after an ambiguous install. A losing candidate cannot authorize a group or an effect.
2. **Link before execution, apply at consumption.** At the target actor's durable command/scheduler handoff, create/read the group, seed the full captured recipient-slot set, mark this slot Queued and link its resume work token before hydration or recipient code can fault. The work and accounting link are indivisible; a selected provider unable to commit that handoff cannot qualify. Later, exact bookmark/registration consumption and its activity/group updates atomically mark Applied and transfer the initial token. A failure before consumption retains a Blocked/owed token or an authoritative normal retirement disposition; it cannot disappear because another recipient became ready.
3. **Transfer runnable responsibility.** A native continuation checkpoint settles its current token and registers all causally runnable successor tokens with the actual child schedules, parent notifications and relevant scheduler-enqueue intents in one commit. A crash cannot expose zero outstanding work between predecessor and successor. Queue acknowledgment is not a substitute for that commit.
4. **Mark a genuine durable boundary.** A committed wait, future delayed schedule or explicit durable offload/handoff ends that runnable segment; it does not leave the whole activity lifetime counted as runnable. The parked invocation/result obligation remains under its normal owner. Later external input, timer occurrence or handoff result supplies its actual new readiness cause, retaining earlier provenance separately. Merely returning structural `Defer`, yielding a drain, having an empty local queue or waiting for an unflushed continuation is not this boundary. Concrete native/model/call handoffs require an agreed classification before enablement.
5. **Seal source dispatch through its normal owner.** Record the final source disposition and exact per-recipient queued/definitive-retirement outcomes, with a durable follow-up to each captured consumer. Completion recording and creation of that follow-up must be atomic under the existing source claim fence. A queued acknowledgment leaves target consumption outstanding; it never discharges an unregistered or faulted slot. Only a definitive retained retirement proof can resolve a slot without target consumption. Failed/unavailable/unknown handoff remains owed or blocked, not successful closure or ineligibility.
6. **Close under the target writer.** Close only when the source seal matches the canonical manifest, every recipient slot has an authoritative disposition, every causally runnable token is settled or explicitly parked, and no unresolved failure blocks closure. One target checkpoint records the closed group, the fixed ready-occurrence set and the owed receiver input/control. Closing a group cannot immediately enlist that closure input back into the group it closes.
7. **Admit, then select semantically.** The receiver durably consumes/deduplicates that exact closed-group input and retains its ready set before the shared source can release its owed consumer delivery. Chart selection remains the StateMachine owner's next checkpoint: validate the current active configuration and exact live visits; evaluate guards in their real scopes; atomically consume the input/occurrences, persist selected transitions and the full phase plan, cancel relevant leaving-state waits and enqueue the first required phase work. Generic group closure does not choose transitions.

The concrete contract must specify stable tombstones/receipts and retention until normal source, work-queue and consumer obligations are discharged. A duplicate predecessor or delayed seal cannot reopen a closed group after cleanup. Required result/material references remain protected by the existing retention owners until their receiving checkpoint takes responsibility; a promise is not discharged by deleting the evidence it needs.

The seal follow-up is a new normal outbox delivery with its own current claim. It references the original source's committed final disposition and manifest; an expired original claim is not its authority. Keep the required original-source evidence until both the follow-up delivery and the consumer's durable acceptance obligations are discharged. Likewise, inherited cause identity on a native continuation is provenance/group membership; its actual work authority comes from the normal checkpoint and delivery that created that continuation.

### Work and failure dispositions

- Ordinary completed native work transfers or settles its token. A real suspended wait remains an activity obligation, with no implicit wait-for-all barrier in the earlier delivery group.
- Native workflow-control continuations remain accounted even when staged in an outbox or carried across drain yield/restart. Fire-and-continue publication creates another input source rather than keeping its publisher's entire future fan-out inside the old group.
- A fault/poison/unavailable dependency keeps the affected responsibility visible. Normal fault absorption, cancellation or retirement may explicitly settle it. A guard error is never false eligibility.
- Supported retry replaces/transfers the affected work responsibility atomically and preserves the original interrupted evaluation's group. An operator's repair audit cause is not silently treated as new business admission. Concrete `RetryFaultedActivity`/`RescheduleActivity` interactions must be reconciled with the existing successor protocols; they do not authorize forwarding inputs to a successor machine invocation.
- Already completed sibling work stays complete. No group accounting resets at a fresh work ID, retry or process restart. The independent semantic progress-chain ID persists through immediate continuation/rearm loops and produces a normal actionable incident on exhaustion; a scheduler drain budget is not proof of that bound. Genuine external input starts another chain only when the receiver is allowed to evaluate it, never merely because admission occurred while blocked.
- An ended/superseded consumer yields an explicit stale/ended disposition. No source, control or completion is redirected through an operation key to a new invocation or state visit.

## Native receiver and live-visit control

Use a generic, explicitly declared native invocation-input/control capability, with separate admission and authored-work operations:

**Admission operation.** A pure reduction over the exact committed receiver state and its pinned static input contract. It may stage the receiver's canonical queue/receipt changes and normal value-retention changes, plus an owed evaluation wake-up. It cannot execute an Action, evaluate a guard, mutate a variable frame or schedule authored phase work. It does not rematerialize unrelated secret-bound entry inputs merely to accept an event. Capacity, business-ID/content comparison, retention and responses remain the semantic receiver's Q2 contract; transport deduplication is not its admission receipt. Only actual durable receiver acceptance can return accepted; an ambiguous commit remains unknown pending authoritative lookup. Receipt publication follows the physical admission commit independently of later authored-work completion. A wake-up is ordinary post-commit work and cannot bypass a selected phase or recovery block.

**Control execution.** A runtime-only command starts the normal structural callback/activation path for its exact live owner. It preserves normal hydration, masking, binding and lexical-frame rules. Allowed phase/slot requests come from the receiver's own pinned structure, not an arbitrary executable node supplied by a sender. It may stage ordinary child work and existing scoped cancellation/notification effects through the normal checkpoint. An external business-event caller cannot manufacture an internal phase command by choosing its kind in a payload.

**Phase completion.** A control's transport receipt means the receiver accepted responsibility, not that Exit/Action/Entry completed. Completion is a separate committed outcome tied to the exact phase, owner, scheduled ordinary child and result. Retries/duplicate controls cannot schedule that work twice or replay completed phases. Global Exit → Action → Entry barriers and hierarchy dependencies remain in the semantic plan; independent regional work can proceed in the same phase.

**Owner closure.** Close only owners in the selected exit set after their required Exit/Action work and child-closure dependencies finish. Preserve continuing compound parents, ancestors and action-without-exit owners. Native terminal owners retain their normal cleanup; control does not reopen a closed frame. Expected authored-work faults stay at ordinary child recovery boundaries so the coordinating owner and bounded admission can remain active. The exact native lifecycle allowlist, activation-wait behavior and terminal projections must be validated against normal runtime policy before agreement.

Terminal lifecycle prevents new work; it does not prevent scoped retained-receipt lookup, duplicate resolution or content-conflict checks promised by Q2. Those queries do not activate the ended owner or reconstruct its closed frame.

Internal controls use deterministic sender/operation identities and normal durable transport. The receiver validates source scope/material/authority, exact invocation/visit, permitted sender relationship, current phase/operation and prior disposition before effects. It records duplicates, stale commands, conflicts and ended receivers distinctly. Data in an acknowledgment file or user-supplied scheduling metadata is never that authority. `ScheduleActivity/1` remains an operator alteration, not this protocol.

## Atomicity and compatibility requirements

- Every target group/control mutation runs under the existing workflow execution writer and checkpoint transaction. Source-header mutation runs under its existing source/claim authority. No cross-execution activity writes, independent semantic lease, shadow queue or alternate acknowledgment store is introduced.
- Selected physical stores/decorators must qualify source/manifest installation, exact resume plus group registration, token transfer, source completion/follow-up and group closure/receiver acceptance together. A capability flag alone is insufficient. A host missing that coherent boundary refuses feature admission; accepted owed work remains visible when a dependency is temporarily unavailable.
- Coalescing may not publish a closure, accepted response or phase command ahead of the physical commit containing its entire responsibility transfer. Define the required flush boundaries and actual fold behavior; Balanced remains the default.
- Preserve existing source-cohort membership, native event/start behavior, material hashes, old model/native work-frame readers, typed child-control and receipt semantics. New fields are explicitly versioned and absent from old wire/hash representations when not used. Do not widen an installed old cohort or retroactively add a group manifest after effects started.
- Schema/readiness changes use normal family declarations, fleet/finalization and dormant-feature checks. No static availability answer, blanket PrivateState retention or schema-row override is accepted. The existing N9/N10 outputs and older native/BPMN/model receipts remain bound to their actual sources.
- Result/variable/secret policy stays with existing owners. Control/group records carry identities and permitted references; they do not copy resolved secrets or grant ancestor access to descendant-local frames. Inline reusable execution must preserve its normal value boundary while its causal-work treatment is explicitly qualified; a scope boundary alone is not proof of durable suspension.

## Contract qualification and review gate

The source-bound cases required before mechanism/native-placement agreement include:

1. Two independent child/parent Event triggers receiving one source in both physical callback orders; the parent cannot win before a ready child from the same group is considered.
2. One source enabling compatible regional transitions, with actual concurrent phase work, and a conflicting container exit selected by explicit order.
3. A composite parked durably after A while another is ready, followed by B completing the parked composite with retained result A; actual trusted readiness identity distinguishes the groups.
4. A child recipient queued but faulted before bookmark consumption while a parent recipient is ready; a source seal arriving before target registration; a staged child/notification not delivered; an empty live queue with owed work; drain yield and process death between every transfer/closure boundary. None can close early, enable parent fallback from the unresolved child or lose a wake-up.
5. Competing source claims/install candidates, duplicate delivery, an installed empty cohort, stale/retired recipients and receiver termination during dispatch. No later wait/visit joins the original group.
6. Fault/poison, supported child retry, fault absorption, cancellation and terminal receiver races, preserving sibling results and exact invocation addresses.
7. Duplicate, conflicting and reordered phase controls; one accepted request schedules work once; actual completion/closure evidence gates subsequent phases.
8. Admission while an ordinary phase waits or awaits recovery, including unrelated secret-resolution unavailability; no authored work is driven by admission and no undurable response reports acceptance.
9. Selected owner frames remain live through their required work, continuing parents/no-exit visits retain values/deadlines, and ended frames are never reopened.
10. Normal values/withholding and reusable/native/model-call boundaries, including the precise recorded point at which runnable responsibility parks or continues.
11. Saved-publication and actual HTTP fan-out ingress, direct resume, timer and return paths; coalescing/physical-store crashes and real first-party provider behavior for every new checkpoint shape, with legacy native/BPMN/model wire/hash and real journey regression evidence.
12. Repeated immediate continuations/rearms across work IDs/restarts and retained closure/tombstone cleanup under the configured budgets.

This is contract design and its proof scope, not an executable work-unit/task list. The execution-model owner must review shared representation, source-completion and successor/recovery compatibility; applicable architecture/spec agreement and resource gates precede implementation or qualification. Q2's full admission fingerprint/receipt/retention/terminal contract, Q3's actual Studio journeys, final native placement and the qualified saga composition remain explicit further work.
