# StateMachine composition spike

Run from `prototypes/kernel-model`:

```sh
dotnet build models/Statecharts.Run -c Release
dotnet models/Statecharts.Run/bin/Release/net10.0/Kernel.Statecharts.Run.dll
```

The runner sends frame-addressed business inputs through the simulation's real inbox. A transition from a compound state enters two parallel regions. One entry runs a normal native Event activity. A second signal remains in the inbox until that entry resumes and then transitions both regions. A denied guard and an unknown event each produce an unhandled outcome. A final transition exits both regions and returns control to the enclosing Flowchart when nested.

The twenty schedules cross root and nested placement, Balanced and Durable modes, and five cuts: no failure, failed commit before applying it, applied commit with a lost acknowledgement, crash after holding a signal, and overlapping owners with a stale fenced write. Each simulation action runs the kernel's `World.Check()`. The witness reads committed configurations, journal entries and the outstanding inbox row independently of the statechart plan. It checks event serialization (S1), one handled or unhandled outcome per accepted signal (S2), one active state per region (S3), and the exit/transition/entry barriers and hierarchy order (S4).

The original spike's four historical controls rejected accepting an input during pending work, a false handled outcome, retaining exited states and parent-first exits. Those runs do not qualify the later phase-progress implementation.

The engine takes no dependency on the kernel. The native composite stores its settled configuration, selected reaction and per-step prerequisites/completion/ordinary child frames. Independent regional work can run concurrently within a phase. Child-first exits and parent-first entries order each hierarchy chain; all exits finish before actions and all actions before entries. There is no global depth barrier between regions. Sender-facing inputs target an exact live frame. A stale or unsupported frame receives a rejection entry. Held signals wake when deliverable; a waiting child does not cause a continuation loop.

## Phase concurrency witness

Use `--phases-list` to discover56 cases and `--phases` to execute them. Forty-eight normal workflow schedules cross both modes, root/Flowchart placement, Exit/Action/Entry, regional completion order and one/two waiting children. They use ordinary Sequence/Event/value activities at unequal hierarchy depths, observe actual registered event deliveries, and reload under a new owner while phase work waits. Both children may remain waiting across reload; completing one cannot advance the phase or lose the other's wait. Additional parent entry/exit waits expose hierarchy ordering. Completed writes run once in the committed history, and ordinary shared values survive the controlled completion orders. These are selected business-input reactions, not publication-cohort proof.

Eight literal checkpoint-reader fixtures are listed separately from those workflows. The identity/progress reader preserves the serial format's completed prefix and exact pending child; unknown versions, invalid ownership indices and mixed shapes are refused. These fixtures are not historical-writer/binary or product-migration evidence. The runner and native bridge receive narrow friend grants for the private compiled types and reader evidence.

## General structural planner

`--selection-list` discovers 68 logical graph/visit fixtures and `--selection` runs them. The private compiled engine supports hierarchical and regional conflicts, action-without-exit, explicit self/parent re-entry, compound-parent preservation, whole-parallel re-entry, targeted/default regional entry and nested finals. It validates complete entered configurations, rejects activity work on structural roots and regions, and returns exited/source visit identities and structural phase dependencies. Input matching and guard results are supplied by the host; the engine does not admit inputs, discover cohorts, allocate physical visits or own values.

The existing public `Chart` constructors adapt the legacy sibling-only definition to that same engine; there is no second selector. The original20 and phase56 native schedules exercise this adapter. Full-graph fixtures are logical data, not actual native state-local scopes or support through a new public authored schema. The private native bridge below exercises full graphs without publishing a product schema.

`--selection-export` produces JSON for the [Node reference comparison](../../../../specs/1210-state-machine/selection-model/README.md). Twenty-eight common profiles compare candidate/selected sets, exited visits, source visits and phase dependencies. Two explicitly proposed child-to-ancestor re-entry cases are exercised only by the private .NET profile and excluded from that comparison. This is neither full SCXML compliance nor production architecture approval.

## Internal progress protocol

`--internal-list` discovers 55 entries; `--internal` runs 34 pure protocol cases (17 scenarios, directly and with JSON roundtrips) and 21 constructed progress/schema refusals. Automatic and completion categories are explicit; event names cannot select them. The existing compiled selector still computes every candidate, conflict and phase plan. Compound completion requires its active final child; a parallel requires every region's active final child. Completion is local and offered once per parent visit, including false/unhandled rules. Persistent ready order, automatic-first rechecks, fresh versus surviving visits, phase gates and guard-failure immutability are checked separately.

An explicit experimental limit bounds each causal settling sequence across phase acknowledgements and JSON copies. Exactly-at-limit stable configurations can settle; another would-be step produces a sticky block before work. Neither phase acknowledgement nor a new admitted event can release that block. This protocol exposes only a semantic-evaluation reset from stable/unblocked progress; it does not implement admission. No product default limit or supported recovery action is selected.

These are pure entered-configuration/acknowledgement fixtures. They do not qualify the native driver below. Two actual native refusal cases in `--native-graph` still reject internal rules without its explicit execution profile before authored entry work. Ordinary triggers/rearming and actual source-wave closure remain separately required. The protocol owns no configuration writer, queue, values, provider or new scheduler.

## Native internal driver (private B7b profile)

`--native-internal-list` discovers 556 entries; `--native-internal` runs the complete suite. It separates 448 successful actual workflow schedules, 14 actual early profile refusals and 94 constructed checkpoint/retry readers. The readers comprise 90 cases from `NativeInternalReaders` (two modes × 45 malformed/topology/host-version cases) and four existing held-phase retry-reader cases from `NativePreludeWitness`. The latter are malformed copies or pure preparation calls, not additional successful workflows or historical-binary migrations. Focused flags include `--native-guards`, `--native-checkpoints`, `--native-loops`, `--native-internal-phases`, `--native-internal-regions`, `--native-internal-structure`, `--native-priority`, `--native-prelude`, `--native-held-loops`, `--native-internal-readers` and `--native-control-cuts`.

An explicit frozen `InternalExecution` profile supplies a positive settling limit, an indexed private control activity and optional rule-ID to normal expression-text mappings. It requires the qualified invocation inbox and native recovery policy. Conditions read the exact source visit through the existing scoped evaluator and strict `Values.To<bool>` conversion: booleans retain their value; null/missing is false; strings, numbers, arrays and objects fault. An absent mapping is unconditional. `GraphRule.When` keeps its existing event-value meaning and is refused on internal rules. No parser, value owner or second selector is added.

The same native composite runs automatic/completion selection and all ordinary phase work. A private ordinary control child supplies continuation ticks or reported guard/loop faults. A checkpoint request stops the native agenda/input drain and owes a normal Continue through the existing writer; the flag alone is not durability evidence. Each request adds a checkpoint/Continue boundary; this cost is retained, with no throughput or product-default claim. The physical-cut schedules inspect the committed row and owed work before any guard or authored phase child runs, including the normal 1000-activity Balanced budget, before-apply loss, lost acknowledgement and cold ownership change.

Native receipts distinguish `Evaluating` from selected business phase work. Staging commits its evaluation-start marker and authoritative input identity before guards. Internal progress is rechecked against current visible values before business rules; cached stability cannot let an event overtake a newly eligible automatic transition. A held input can remain Evaluating across internal phase waits, faults and loops. `BusinessReady` records that business-rule evaluation itself was reached, so its guard retry preserves that stage. If internal progress ends the machine first, the receipt becomes NotProcessed/completed with evaluation-start evidence and no invented business-evaluated trace. Cancellation similarly distinguishes Evaluating/NotProcessed from Selected/Interrupted and queued/unstarted inputs. Metadata queries retain markers, reasons and clocks without loading authored material.

Guard and loop work use normal native incidents and verified fresh-successor retries. Recovery preserves completed phases, successful siblings, scope handles, held inputs and semantic counters; a loop acknowledgement resets only the explicit budget/block. A surviving cycle requires a new manual recovery. This private profile uses manual-only `WaitForIntervention`/`NativeRetry`; it does not adopt an automatic retry policy. Pure parent preparation validates the authoritative held payload before either control or phase rebind. Control-cut schedules qualify atomic receipt/rebind/owed-successor commits under before-apply loss and lost acknowledgement, including deduplication and conflicting retries. No private incident or acknowledgement store is introduced.

Machine checkpoint6 and native host schema12 gate this opt-in experiment. A native-owned checkpoint-control marker rejects relabelled older-host data even before any event receipt exists. Older machine profiles retain their paths and do not adopt current bindings on callbacks. These are private in-memory native model/worker/store witnesses, not provider durability, historical mixed-binary rollout, product API/operator recovery policy or release qualification. Product architecture agreement, ordinary trigger/rearming/source-wave integration, compensation composition and Studio authoring/inspection remain separate delivery requirements.

## Full graph native bridge

`--native-graph-list` discovers 472 cases: 448 actual workflow schedules, eight native profile/reference refusals, twelve literal identity readers and four literal-reader consumption schedules. `--native-graph` runs them. The same internal StateMachine accepts exactly one normal literal-bound legacy or private structural definition; dynamic graph bindings, internal rules without the opt-in profile above and missing ordinary child references are rejected before authored work. A real ordinary external activity counter checks early refusal, including references on inactive states. The public legacy Chart facade and native path share one compiled selector and phase scheduler.

Twenty graph profiles cover child fallback, self and compound/parallel re-entry, preserved compound parents, compatible/conflicting regional reactions including internal actions, one-region parallel targets, cousins and nested/top-level finals. Two ancestor profiles remain proposed engineering. Cases cross root/Flowchart, Balanced/Durable, each applicable durable phase and opposite regional callback orders. Ordinary Sequence/Event/value work waits and is resumed using actual registered deliveries after repeated owner changes/reloads. Later business input remains held until the selected work finishes. Committed checkpoints and completed ordinary work independently prove retained/fresh visits, current versus planned configuration, source/exit identities, persistent serial allocation, fixed selected plan and final-entry completion. These are real native durable logical visit records. Their writes now use the scope attachment below, but the older graph suite does not assert scoped-value semantics or source-wave closure.

Checkpoint version3 introduced current/planned visits, a frame-scoped monotonic serial, selected plan and phase work. Old serial/phase reader fixtures retain completed work and exact running children with explicit legacy-pending provenance. Old data never contained historical visit or transition identities; conversion allocates new reader-owned identities rather than claiming to recover those historical identities. Twelve additional literal readers cover v2 pending/idle, v3 migration and malformed/mixed identity shapes. Four additional reader-consumption schedules seed an explicitly labelled v1/v2 idle checkpoint into a normally created workflow, reload it, consume an unmatched signal, then reload/consume again. They prove migration persists even for an unhandled input without reallocating visits. None proves a historical writer, mixed-binary upgrade or product migration. Pending work uses the persisted selected plan rather than selecting again after restart.

## Ordinary scoped work (private profile)

`--scopes-list` discovers 55 cases and `--scopes` runs them: 24 actual native workflows, 17 explicit literal reader/definition fixtures and 14 deliberately seeded context-refusal schedules. `--scopes-red` is a separate minimal actual workflow that failed V1 before the attachment and now passes. Root and Flowchart placements cross Balanced/Durable; regional cases run both callback orders. Every wait is delivered using the real registration after a cold owner reload.

One generic lexical resource belongs to the machine invocation, and one to each entered state visit. The same StateMachine, compiled selector and phase scheduler attach ordinary Entry, Exit and Action work to those resources. Values remain in the normal native evaluator/assignment/capture owner; chart state stores only handles/progress. The private `Defaults` dictionaries are literal JSON declarations, not the product Variable/binding schema. Targets initialize at their actual Entry step, after the Action barrier and their parent Entry. Source resources remain through Action, then retire child-first before target Entry. That source visibility is an explicitly proposed engineering profile in [the values contract](../../../../specs/1210-state-machine/contracts/values.md), not a new accepted owner choice.

Lifecycle schedules assert ordinary bindings, output capture, ForEach shadowing, parent writes, repeated internal actions, fresh self/parent re-entry, preserved parent identity, machine value persistence, all three durable phases, final Entry waiting and disposal. Parallel schedules assert independent resources, concurrent work, opposite completion orders and whole-parent reset. An embedded machine proves its own declarations and ordinary outer-frame fallback; completion releases only its own resources. Ordinary cancellation and an absorbed activity fault prove generic cleanup, without claiming incident/retry or successful-sibling recovery.

Version4 adds machine/visit handle mappings and a source-retirement marker. Pure readers validate visit/handle shape without allocating; mutating execution materializes only empty legacy scopes. Any old checkpoint with newly introduced nonempty declarations is refused. The four older v1/v2 consumption fixtures explicitly remove new-writer resources when seeding a scope-less old shape; they do not prove a historical writer or mixed binary/provider migration. New actual reloads and seeded reader fixtures are counted separately. Current runtime reads verify each handle's owner/lexical parent and exact owned-resource inventory. Seeded context refusals cover wrong owner/parent, stray resources and a legacy shape retaining new resources; all refuse before allocation and preserve the technical-refusal input checkpoint. `--scopes-context` runs those 14 separately.

## Limits

The original business-input/phase/scope witnesses use frame-addressed inputs and the prototype's value-equality condition profile. The legacy definition profile remains sibling-restricted; the private structural profile supports the graph shapes above. Those earlier witnesses alone do not qualify automatic/completion progress or incident/retry and successful-sibling recovery; the separate private recovery, inbox and B7b suites described here supply their bounded model evidence. `NativeModel.Fail` still owns generic fault propagation/cancellation outside the opt-in intervention profile. Ordinary transition triggers/deadline ownership, product expressions, a public admission API and retention contract, full product value/default-expression integration, source-wave closure, provider durability, product/Studio adoption and native compensation composition remain required. These experiments supply M0 evidence for #3815 and do not close Q1/M0.

The native smoke run passed. The native cost tables for SQLite and PostgreSQL 17, with both fences, matched the baseline at `e5f3955adc` byte for byte. Those cost runs exercise the existing native workloads. Database costs of a statechart workflow and randomly generated statecharts have not been measured.

`--recovery` is the private phase-parent recovery profile: 60 actual Entry/Exit/Action fault schedules, root and nested machines, both qualified persistence modes. The normal native intervention/retry owner retains the selected reaction and values, stages a fresh child, and replaces only that phase's physical Running key. Completed phase work, visits and resources survive. `--recovery-red` isolates the original outer-catch baseline witness; `--recovery-list` inventories these schedules. `--regional-recovery` adds12 actual opposite-order parallel plain/stateful schedules. `--recovery-refusals` separates six seeded malformed-parent control cases and two seeded migrated-v8 policy contexts. Basic schedules include repeated faults, actual commit uncertainty, cancellation and pure terminal metadata. The delivery PR records current-head qualification, isolated controls and their historical failed/unrun attempts. This B5a experiment does not register or drain the machine's admission inbox; the separately required B5b bridge, source/product/provider/compensation/Studio/all49 gates remain open.


`--inbox` qualifies the actual machine's optional bounded input inbox in the private M0 model. 104 unique cases: 88 actual root/nested phase-fault schedules (Balanced/Durable, entry/exit/action; admission and retry commit uncertainty, cancellation, plus exit/action selection-commit uncertainty), 14 explicitly seeded pure retry-reader refusals, and two actual old-v4 profile runs. Ordinary native admission/receipt/capacity/retention, exact creation checks, selection and recovery remain the existing owners. The machine stores only frozen settings and a selected admitted ID in version5; unconfigured and old-v4 invocations retain raw signals. Configured machines reject raw signals observably. Metadata admission and terminal queries work without authored definitions; cold restarts resume persisted wakes and never reevaluate a selected input. These are model/store-boundary proofs, not production API/provider/Studio acceptance or source architecture approval. This inbox suite alone does not qualify automatic/completion priority; the separate B7b suite supplies bounded native evidence. Ordinary trigger work remains required.

`--inbox-settings` adds two actual ordinary Sequence/phase-fault runs with an expression-bound setting changed to an incompatible value after entry, and two explicitly version9-capability facade checks of the shared future-state gate. Native schema10 protects machine-version5 rows from older hosts; no historical mixed-binary qualification is claimed. Receiver and ordinary post-entry callbacks for the private inbox capability reactivate from context/checkpoint material without reevaluating entry-only bindings. Unrelated composites keep their ordinary binding behavior.

`--inbox-signal` preserves two actual ordinary stateful signal-receiver runs; the existing signal interface does not require CompositeActivity. Only ordinary parent callback sites impose that cast.

`--clr` qualifies360 actual authored CLR-fault schedules across Balanced/Durable, root/Sequence/Parallel and root/nested machine Entry/Exit/Action work, activation/leaf/Start/Resume/External-leaf, steady/lost-before/lost-answer/cancellation. Recovery uses fresh native successors with preserved pinned inputs/logical operation, prior phases/siblings/scopes and admitted identity. `--clr-readers` separately labels8 direct model/service boundary fixtures for runtime cancellation, nested-reflection cancellation, owner-side effects and bounded diagnostics,6 pure v10 policy readers, and10 explicitly constructed v10/policy4-context ordinary executions through the pure upgrader, retaining the current outer row version and normal simulator oracle. Per-kind authored failure counters/phases and exact first/retained causes are required; unrelated engine failures cannot satisfy compatibility. The shared future-state gate is also checked against a version10 capability facade on the actual new rows. These are not historical writer/provider/binary qualification. Fresh policy5/schema11 adds the bounded authored-call capability without promoting old policies. Unsupported activation families and full product/source/provider/Studio/all49 gates remain open.
