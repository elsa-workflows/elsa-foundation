# StateMachine composition spike

Run from `prototypes/kernel-model`:

```sh
dotnet build models/Statecharts.Run -c Release
dotnet models/Statecharts.Run/bin/Release/net10.0/Kernel.Statecharts.Run.dll
```

The runner sends frame-addressed business inputs through the simulation's real inbox. A transition from a compound state enters two parallel regions. One entry runs a normal native Event activity. A second signal remains in the inbox until that entry resumes and then transitions both regions. A denied guard and an unknown event each produce an unhandled outcome. A final transition exits both regions and returns control to the enclosing Flowchart when nested.

The twenty schedules cross root and nested placement, Balanced and Durable modes, and five cuts: no failure, failed commit before applying it, applied commit with a lost acknowledgement, crash after holding a signal, and overlapping owners with a stale fenced write. Each simulation action runs the kernel's `World.Check()`. The witness reads committed configurations, journal entries and the outstanding inbox row independently of the statechart plan. It checks event serialization (S1), one handled or unhandled outcome per accepted signal (S2), one active state per region (S3), and the exit/transition/entry barriers and hierarchy order (S4).

The original spike's four historical controls rejected accepting an input during pending work, a false handled outcome, retaining exited states and parent-first exits. Those runs do not qualify the later phase-progress implementation.

The engine takes no dependency on the kernel. The native composite stores its settled configuration, selected reaction and per-step prerequisites/completion/ordinary child frames. Independent regional work can run concurrently within a phase. Child-first exits and parent-first entries order each hierarchy chain; all exits finish before actions and all actions before entries. There is no global depth barrier between regions. Sender-facing inputs target an exact live frame. A stale or unsupported frame receives a rejection entry. Held signals wake when deliverable; a waiting child does not cause a continuation loop.

## Phase concurrency witness

Use `--phases-list` to discover56 cases and `--phases` to execute them. Forty-eight normal workflow schedules cross both modes, root/Flowchart placement, Exit/Action/Entry, regional completion order and one/two waiting children. They use ordinary Sequence/Event/value activities at unequal hierarchy depths, observe actual registered event deliveries, and reload under a new owner while phase work waits. Both children may remain waiting across reload; completing one cannot advance the phase or lose the other's wait. Additional parent entry/exit waits expose hierarchy ordering. Completed writes run once in the committed history, and ordinary shared values survive the controlled completion orders. These are selected business-input reactions, not publication-cohort proof.

Eight literal checkpoint-reader fixtures are listed separately from those workflows. The identity/progress reader preserves the serial format's completed prefix and exact pending child; unknown versions, invalid ownership indices and mixed shapes are refused. These fixtures are not historical-writer/binary or product-migration evidence. The runner and native bridge receive narrow friend grants for the private compiled types and reader evidence.

## General structural planner

`--selection-list` discovers 68 logical graph/visit fixtures and `--selection` runs them. The private compiled engine supports hierarchical and regional conflicts, action-without-exit, explicit self/parent re-entry, compound-parent preservation, whole-parallel re-entry, targeted/default regional entry and nested finals. It validates complete entered configurations, rejects activity work on structural roots and regions, and returns exited/source visit identities and structural phase dependencies. Input matching and guard results are supplied by the host; the engine does not admit inputs, discover cohorts, allocate physical visits or own values.

The existing public `Chart` constructors adapt the legacy sibling-only definition to that same engine; there is no second selector. The original20 and phase56 native schedules exercise this adapter. Full-graph fixtures are logical data, not actual native state-local scopes or support through a new public authored schema. The private native bridge below exercises full graphs without publishing a product schema.

`--selection-export` produces JSON for the [Node reference comparison](../../../../specs/1210-state-machine/selection-model/README.md). Twenty-eight common profiles compare candidate/selected sets, exited visits, source visits and phase dependencies. Two explicitly proposed child-to-ancestor re-entry cases are exercised only by the private .NET profile and excluded from that comparison. This is neither full SCXML compliance nor production architecture approval.

## Full graph native bridge

`--native-graph-list` discovers 470 cases: 448 actual workflow schedules, six native profile/reference refusals, twelve literal identity readers and four literal-reader consumption schedules. `--native-graph` runs them. The same internal StateMachine accepts exactly one normal literal-bound legacy or private structural definition; dynamic graph bindings and missing ordinary child references are rejected before authored work. A real ordinary external activity counter checks early refusal, including references on inactive states. The public legacy Chart facade and native path share one compiled selector and phase scheduler.

Twenty graph profiles cover child fallback, self and compound/parallel re-entry, preserved compound parents, compatible/conflicting regional reactions including internal actions, one-region parallel targets, cousins and nested/top-level finals. Two ancestor profiles remain proposed engineering. Cases cross root/Flowchart, Balanced/Durable, each applicable durable phase and opposite regional callback orders. Ordinary Sequence/Event/value work waits and is resumed using actual registered deliveries after repeated owner changes/reloads. Later business input remains held until the selected work finishes. Committed checkpoints and completed ordinary work independently prove retained/fresh visits, current versus planned configuration, source/exit identities, persistent serial allocation, fixed selected plan and final-entry completion. These are real native durable logical visit records. Their writes now use the scope attachment below, but the older graph suite does not assert scoped-value semantics or source-wave closure.

Checkpoint version3 introduced current/planned visits, a frame-scoped monotonic serial, selected plan and phase work. Old serial/phase reader fixtures retain completed work and exact running children with explicit legacy-pending provenance. Old data never contained historical visit or transition identities; conversion allocates new reader-owned identities rather than claiming to recover those historical identities. Twelve additional literal readers cover v2 pending/idle, v3 migration and malformed/mixed identity shapes. Four additional reader-consumption schedules seed an explicitly labelled v1/v2 idle checkpoint into a normally created workflow, reload it, consume an unmatched signal, then reload/consume again. They prove migration persists even for an unhandled input without reallocating visits. None proves a historical writer, mixed-binary upgrade or product migration. Pending work uses the persisted selected plan rather than selecting again after restart.

## Ordinary scoped work (private profile)

`--scopes-list` discovers 41 cases and `--scopes` runs them: 24 actual native workflows and 17 explicit literal reader/definition fixtures. `--scopes-red` is a separate minimal actual workflow that failed V1 before the attachment and now passes. Root and Flowchart placements cross Balanced/Durable; regional cases run both callback orders. Every wait is delivered using the real registration after a cold owner reload.

One generic lexical resource belongs to the machine invocation, and one to each entered state visit. The same StateMachine, compiled selector and phase scheduler attach ordinary Entry, Exit and Action work to those resources. Values remain in the normal native evaluator/assignment/capture owner; chart state stores only handles/progress. The private `Defaults` dictionaries are literal JSON declarations, not the product Variable/binding schema. Targets initialize at their actual Entry step, after the Action barrier and their parent Entry. Source resources remain through Action, then retire child-first before target Entry. That source visibility is an explicitly proposed engineering profile in [the values contract](../../../../specs/1210-state-machine/contracts/values.md), not a new accepted owner choice.

Lifecycle schedules assert ordinary bindings, output capture, ForEach shadowing, parent writes, repeated internal actions, fresh self/parent re-entry, preserved parent identity, machine value persistence, all three durable phases, final Entry waiting and disposal. Parallel schedules assert independent resources, concurrent work, opposite completion orders and whole-parent reset. An embedded machine proves its own declarations and ordinary outer-frame fallback; completion releases only its own resources. Ordinary cancellation and an absorbed activity fault prove generic cleanup, without claiming incident/retry or successful-sibling recovery.

Version4 adds machine/visit handle mappings and a source-retirement marker. Pure readers validate visit/handle shape without allocating; mutating execution materializes only empty legacy scopes. Any old checkpoint with newly introduced nonempty declarations is refused. The four older v1/v2 consumption fixtures explicitly remove new-writer resources when seeding a scope-less old shape; they do not prove a historical writer or mixed binary/provider migration. New actual reloads and seeded reader fixtures are counted separately. Current runtime reads verify each handle's owner/lexical parent and exact owned-resource inventory.

## Limits

These witnesses cover frame-addressed business inputs and the prototype's value-equality condition profile. The legacy definition profile remains sibling-restricted; the internal structural profile supports the graph shapes above. Automatic/completion transitions, ordinary transition triggers/deadline ownership, product expressions, a public admission API, retention, full product value/default-expression integration, activity-fault recovery and successful-sibling preservation after fault remain unqualified. `NativeModel.Fail` still owns generic fault propagation/cancellation; this change adds no recovery mechanism. These experiments supply M0 evidence for #3815 and do not settle source-wave closure, provider, product/Studio adoption or native compensation composition.

The native smoke run passed. The native cost tables for SQLite and PostgreSQL 17, with both fences, matched the baseline at `e5f3955adc` byte for byte. Those cost runs exercise the existing native workloads. Database costs of a statechart workflow and randomly generated statecharts have not been measured.
