# Ordinary native lexical-resource probe

Build `dotnet build models/Native.Scopes.Run -c Release` from `prototypes/kernel-model`. Run `dotnet models/Native.Scopes.Run/bin/Release/net10.0/Kernel.Native.Scopes.Run.dll --list` for the inventory, then omit `--list` to execute it.

The 87 cases consist of 62 actual ordinary workflow schedules and 25 separately labelled serialized reader/codec fixtures. They qualify a private generic resource in the existing native checkpoint, evaluator and activity-frame ownership. They do not attach physical scopes to StateMachine visits or provide product/Studio support.

Ten workflow schedules prove a value survives separate ordinary activity phases, direct leaf binding and a cold-owner restart across root/Flowchart and Balanced/Durable. Sixteen further schedules use parent/sibling resources, independent phase waits, opposite callback orders and repeated cold reloads. Normal SetVariable, expressions, ForEach iteration shadowing/assignment and output captures read/write the existing value machinery. Caller-owned nested JSON is cloned, parent writes persist, siblings remain separate, an explicitly released/recreated resource has a fresh handle/defaults, and outer workflow fallback retains its normal meaning. Existing parallel write ordering remains authoritative. Two Durable schedules also crash after scoped work is committed to the agenda and before that work executes, then reload again at its ordinary wait.

Four schedules reject resource creation after the owning frame has ended. Thirty-two ownership schedules qualify ordinary owner failure under an absorbing Parallel parent, cancelling one owner while its sibling continues, normal native cancellation, forced kernel termination and a descendant owner borrowing its ancestor's scope. They reload surviving resources and retire cancelled resources/handles; stale wakes cannot resurrect an ended invocation. Twelve queued-work schedules dispose an owner by completion, absorbed fault or a competing parallel winner before scoped child work starts. Actual foreign-scope schedule/create/release attempts and ancestor-release attempts are rejected without adding native work or modifying values. Lifecycle guards cover queued/running work, parent resources with children and released handles.

The 25 codec/reader cases cover omitted unused fields, old versions1–3 without invented resources, JSON-null checkpoints, the current private resource/owner/parent/work/frame codec, unsupported future/mixed versions and invalid ownership/reference/cycle/value shapes. These are serialized constructed fixtures, not a historical writer/binary upgrade guarantee. Actual writes/reloads are counted in the 62 workflows separately.

Creation/scheduling/release APIs and resource records are internal; only the focused runner has friend access. Resources belong to a live composite and may parent only accessible same/ancestor-owned resources. Only the owner releases them after child resources and scoped work have ended. Normal completion, cancellation and ordinary Fail cleanup remove owned resources. Forced workflow termination retires all new references/resources but leaves other existing forensic state intact; technical Park retains its previous checkpoint. This does not implement incident recovery or retry.

Full StateMachine attachment is mandatory next work, including the correct source/target scope and initialization boundary for every Entry/Trigger/Action/Exit activity. Machine/state bindings, shared source-wave/cohort closure, all trigger/automatic/completion/deadline semantics, normal sibling recovery, provider/secret retention, compensation and complete product/Studio qualification remain open. Source-Action visibility through the Action barrier is a proposed engineering lifetime for separate contract review, not an accepted owner decision. Existing native cost evidence is historical and does not measure these new workloads.
