# Ordinary native intervention experiment

Non-packable M0 evidence under [the proposed recovery contract](../../../../specs/1210-state-machine/contracts/recovery.md). This is an internal opt-in profile, not product incident/retry APIs or StateMachine acceptance.

`dotnet run --project prototypes/kernel-model/models/Native.Recovery.Run -c Release` runs one minimal actual child-fault witness, 38 actual intervention/policy schedules and 27 literal reader fixtures. `--minimal` isolates the original intervention witness. `--retry` runs20 actual successor schedules; `--retry-minimal` selects their four steady variants. `--retry-refusals` runs16 actual definition-replacement refusals and four explicitly seeded migrated-v5 contexts. `--list` inventories all groups separately.

The profile freezes its effective policy in a qualified Balanced/Durable invocation. A materialized, non-background stateless leaf with every input bound can retain a fault awaiting intervention when its immediate ordinary parent is Sequence or Parallel. Input bindings use the normal hydrator snapshot once; mutable activity inputs cannot alter the retained snapshot. The failed occurrence is not runnable. Parents, completed work, independent siblings and ancestor-owned lexical values survive; ordinary native cancellation still disposes the subtree.

Legacy policy and explicit custom fault absorption retain their existing routing. Unbound/constructor-default inputs, activation exceptions, intrinsic/stateful/background/composite faults, custom-parent routing and root-occurrence intervention/retry are **unsupported** and keep existing fault routing. No unsupported retry boundary is exposed.

The private retry control validates exact creation, source incident, material availability and the live parent obligation before mutation. One ordinary checkpoint archives the old source, creates fresh physical successor work, preserves logical operation/input/tag/iteration/borrowed-scope context and rebinds Sequence/Parallel routing. The owed continuation runs after that checkpoint. Accepted control IDs deduplicate by exact typed contents within the retained active experiment; conflicting contents and stale sources cannot create another successor. This is not product operator authorization, public admission, retention or end-to-end exactly-once delivery.

Native checkpoint version6 adds successor work, forensic lineage and original material descriptors. Prior v5 intervention and v4 scoped checkpoints remain readable; v5 incidents lack original executable identity and refuse retry as `MaterialIdentityUnavailable`. New activations detach a descriptor before authored execution, then compare current direct CLR type/module identities and exact authored declarations/routing before retry. Replacing a definition under the same ID is insufficient. This conservative in-memory/direct-module comparison is **not** source installation, dependency-closure identity, product version pinning or historical-binary rollout qualification. Mixed old-version successor data is refused. Literal readers and seeded migrated contexts are separately counted.

The intervention schedules cover root/nested ordinary composition, opposite branch orders, cold owner takeover, an independently completing waiting sibling, mutable input separation, retained scope ownership, cancellation and stale continuation. Successor schedules cover both persistence modes and parent kinds, ForEach/lexical context, changed input values, cold takeover before/after staging, actual lost-before-apply and lost-answer commits, duplicate/conflicting/stale controls and ordinary completion cleanup. Definition replacement changes leaf type, binding, capture or parent order before retry. Admission during recovery, broader activation/root recovery, StateMachine phase integration, source/product agreement, provider durability, compensation and Studio remain mandatory later units.
