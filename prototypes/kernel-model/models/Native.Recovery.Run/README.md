# Ordinary native intervention experiment

Non-packable M0 evidence under [the proposed recovery contract](../../../../specs/1210-state-machine/contracts/recovery.md). This is an internal opt-in profile, not product incident/retry APIs or StateMachine acceptance.

`dotnet run --project prototypes/kernel-model/models/Native.Recovery.Run -c Release` runs one minimal actual child-fault witness, 38 actual intervention/policy schedules and 40 literal reader fixtures. `--minimal` isolates the original intervention witness. `--retry` runs 24 actual successor schedules; `--retry-minimal` selects their four steady variants. `--retry-refusals` runs 16 actual definition-replacement refusals and four explicitly seeded migrated-v5 contexts. `--root-recovery` runs 56 actual root/direct-ForEach schedules; `--root-minimal` selects eight steady variants. `--root-policy` runs four actual disabled/unmarked-parent policy schedules, six seeded migrated-v6 contexts and 48 separate literal readers. `--stateful` runs 80 actual Start/Resume-fault schedules with mutable input/private-state isolation, cold takeover, competing/late deliveries, fresh waits, repeated faults/control replays, actual commit uncertainty, cancellation and terminal metadata. `--stateful-policy` separates two actual disabled profiles, four seeded v7 contexts and 13 literal readers. `--list` inventories all groups separately. Negative-control execution and its historical failed/unrun attempts are recorded separately on the delivery PR.

The existing 56 root/direct-ForEach and 80 stateful schedules now also check internal activity-context retry provenance against the actual durable successor receipts. Original and unrelated iteration activations have no predecessor; a verified successor exposes its exact immediate source through leaf, Start and Resume contexts, including repeated retry and cold reload. These strengthen existing schedules rather than add cases. The context value is computed from existing validated frame lineage, with no persisted schema or incident-policy change; it does not authorize a chart recovery or come from caller payload.

The profile freezes its effective policy in a qualified Balanced/Durable invocation. A materialized, non-background stateless leaf with every input bound can retain a blocking fault awaiting intervention. Legacy policy1 permits Sequence/Parallel children; policy2 also permits the actual workflow root and direct ForEach bodies. Policy3 additionally permits fully-bound non-External, non-background stateful activities reporting a fault from Start or Resume. Their inputs/material are pinned before Start; Resume uses detached input and private-state clones. A retry always starts a fresh invocation without old private state or payload. Parent support requires private minimum-policy metadata. New support cannot silently expand old invocations. Input bindings use the normal hydrator snapshot once; mutable activity inputs cannot alter the retained snapshot. Fresh policy4 additionally permits the explicitly marked StateMachine phase parent; its value-only retry preparation rebinds the exact outstanding child and validates the original borrowed visit handle. It does not grant interception to arbitrary composites. The failed occurrence is not runnable. Parents, completed work, independent siblings and ancestor-owned values survive; ordinary cancellation still owns cleanup.

Legacy policy and explicit custom fault absorption retain their existing routing. Binding failures before usable pinned inputs, intrinsic/background/composite faults, External stateful faults and arbitrary custom-parent routing remain **unsupported**, including those activity kinds at the root. Current private policy5 separately qualifies selected activation/leaf/Start/Resume/External-leaf CLR failures after usable input snapshots; the [Statecharts runner](../Statecharts.Run/README.md) records that boundary and its limits. No unsupported retry boundary is exposed. Opt-in root handling explicitly chooses blocking intervention; an Open/ContinueWithIncidents outcome is insufficient. It preserves a Running workflow rather than reopening a Faulted/Parked row.

The private retry control validates exact creation, source incident, material availability and the live root or parent obligation before mutation. One ordinary checkpoint archives the old source, creates fresh physical successor work, preserves logical operation/input/tag/iteration/borrowed-scope context and prepares normal parent routing. ForEach does not advance Index or reevaluate Items during retry; only ordinary success advances the iteration. Root successors use normal completion. The owed continuation runs after the checkpoint. Accepted control IDs deduplicate by exact typed contents within the retained active experiment; conflicting contents and stale sources cannot create another successor. This is not product operator authorization, public admission, retention or end-to-end exactly-once delivery.

Native checkpoint version11 gates the qualified authored CLR profile; version10 gates the opted-in machine inbox. Version9 freezes the StateMachine parent capability; v8 policy3/stateful pins remain unchanged on upgrade. V7 policy1/2 retains old stateful binding/fault behavior rather than adopting pins. Absent/zero policy on prior v5/v6 state stays policy1; valid prior retry work/history and scoped state remain readable. Old v5 incidents lack original executable identity and refuse retry as `MaterialIdentityUnavailable`. New activations detach a descriptor before authored execution, then compare current direct CLR type/module identities and exact authored declarations/routing before retry. Replacing a definition under the same ID is insufficient. This conservative in-memory/direct-module comparison is **not** source installation, dependency-closure identity, product version pinning or historical-binary rollout qualification. Mixed old-schema new policy/successor/stateful fields are refused. Literal readers and seeded migrated contexts are separately counted.

Name-only `native.resume` resolves the current wait at admission: a late name stimulus may match a successor. Fresh wait IDs protect against deliveries explicitly addressed to the old wait, not old business intent. Qualified Resume validates exact frame/wait ownership before mutation; suspended root retry validation rejects foreign waits both idle and queued. Qualified Resume removes stale queued resumes only for its consumed occurrence; independent work survives.

The intervention/successor schedules cover ordinary composition, opposite branch orders, independent siblings, value ownership, cold takeover, actual lost-before-apply/lost-answer, replay/conflict/stale controls and cleanup. Root/direct-ForEach schedules add repeated faults, two-item iteration, plain/external leaves and fresh durable attempt markers, cancellation before acceptance and termination after staging using normal input order, and terminal pure metadata after removing authored material. Definition replacement changes leaf type, binding, capture or parent order before retry. Separate Statecharts runner evidence qualifies bounded ordinary phase recovery and the actual machine inbox during recovery. Broader pre-snapshot binding/composite/intrinsic/background/External-stateful recovery, actual chart guard/loop recovery and internal progress, source/product agreement, provider durability, compensation and Studio remain mandatory later work.
