## M1 — CShells primitives and preview

Implement explicit host-owned service descriptors and committed catalog notifications in CShells. Publish a preview using the CShells pipeline.

**Acceptance and measurable proof:**

- Type and factory descriptors resolve one root-owned instance from root and all active shell generations.
- Caller-supplied instance descriptors preserve their documented ownership; disposing a shell never disposes that instance.
- Root shutdown disposes factory/type-created shared objects exactly once, including async-only disposal; shell disposal does not.
- Disposable and async-disposable type/factory services remain usable through shell drain and are disposed only by the owner.
- Ordinary singleton descriptors remain provider-local by default.
- Multiple registrations and `IEnumerable<T>` preserve descriptor order and multiplicity for the selected unkeyed singleton set; unselected service types remain provider-local.
- Exercise overlapping reload: old generation drains after the next generation starts; neither lifetime is truncated and neither shell can dispose root-owned services.
- Catalog refresh emits one committed-snapshot notification after commit; cancellation/failure emits no success notification; subscribers can read the announced generation without polling.
- A deterministic race holds a candidate before its first initializer while a new catalog commits and other old pins release. The candidate's exact old snapshot stays protected until build failure/cancellation or actual shell disposal. Verify successful promotion and overlapping drain, and define callback ordering without arbitrary subscriber work under a catalog lock.
- Run focused CShells tests, full required owner-repository gates, exact-head review, publish the preview, and record a consumer identity plus the executable overlapping-generation proof. No result is implied here.

## M3 — safe package-store pruning

The shared-root admission, compatibility and lifetime design is accepted in [Nuplane spec 030](https://github.com/valence-works/nuplane/blob/1a6456853d07cd95314d0942388b8d7689332302/specs/030-safe-package-store-pruning/plan.md), with its independently reviewed [128-artifact implementation checklist](https://github.com/valence-works/nuplane/blob/1a6456853d07cd95314d0942388b8d7689332302/specs/030-safe-package-store-pruning/tasks.md). [Nuplane #108](https://github.com/valence-works/nuplane/issues/108) / [PR112](https://github.com/valence-works/nuplane/pull/112) owns the active stack; 37 of the 128 task rows are checked as accepted, including bounded prerequisites; this count comes from the checklist rows, while the plan’s 33-task status and the checklist’s older 32/128 checkpoint paragraph describe earlier increments. The accepted design requires root/all-member ownership before package access on enrolled roots and persistent Active/LKG plus immutable graph-use protection for offline states and retained loading generations. Runtime protection publication, historical migration and actual startup-selector consumption remain in progress. Ordinary unenrolled compatibility remains required. This is an engineering selection under the existing delivery authority, not a pending owner-selection gate.

The [current program checkpoint](../../program-goals/modular-hosting-upstream-delivery.md#current-pruning-checkpoint--2026-10-10) links exact published heads, platform runs and bounded proof. Native inventory/retention and read-only inspection are implemented. Actual two-provider maintenance/Loading overlap proves a retired live-only graph is retained, and native control recovery primitives have local causal/review proof. The full driver/before-delete gate, recovery coordination, public preview/execute and physical package deletion remain incomplete; PR112 is not merge/release ready. The safe-pruning release-boundary proposal remains pending and does not reduce these gates.

**Before-delete gate:** complete actual component proof must precede recursive deletion implementation or executor tests. It covers every earliest package-read driver, complete old/new/shared graphs, live old shells and build-time catalog leases, sibling hosts, offline Active/LKG, aliases/native identities, cancellation and process termination. Requests to unload or a policy Eligible result are insufficient. The bounded deferred Loading overlap does not accept this whole gate.

**Execution acceptance:** preview defaults to non-destructive inventory/retention; absent retention keeps all. Explicit execution must confirm current root/epoch/policy, reacquire fresh root/all-member ownership, replan and revalidate exact completed-install identities before native no-follow quarantine/deletion. Report actual partial/quarantined/deleted outcomes and prove restart, stale-use recovery, repeated execution and supported Windows/Linux/macOS behavior in isolated stores. Do not mutate a user package store. Actual collectible assembly unloading remains Foundation #2362's upstream Nuplane scope.

Report-only pruning does not satisfy #108 or unblock final qualification #2509 under the delivery scope. Stable releases and downstream acceptance continue to depend on verified safe execution; no fallback or scope reduction is selected.
