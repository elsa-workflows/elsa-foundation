## Purpose and boundaries

Automate authoritative business records through discoverable metadata, stable references, authorized
reads/domain operations and truthful provider-declared events. Entity-aware integrations come first.
The owner selected service connections first and, after the bounded assessment, the optional Elsa-managed
record backend as an explicit [follow-on #3916](https://github.com/elsa-workflows/elsa-foundation/issues/3916).
The current production scope is external entity-aware integration. CRM/sales/claims applications remain
separate compositions; the follow-on creates no current implementation lane.

Reuse Connections/Secrets, the single activity catalog, normal module composition, User Tasks and shared
Runtime routing. Coordinate triggers #3582, messages #3583, decisions #3602, dashboards #3604, releases
#3590 and activity-data selection #3882 through their owning records. No competing shared authority.
New domain/constitution admission and initiative-owned decisions retain their applicable agreement gates.

Production deployment, production credentials, package release, wholesale external mirroring, arbitrary
database access and an unbounded data/application platform are outside scope. Preserve consolidation's
priority one and every unrelated owner pause; this authorization reactivates no other program.
