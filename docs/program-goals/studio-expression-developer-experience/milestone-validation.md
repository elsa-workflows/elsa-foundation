# Executable milestone validation: Studio expression developer experience

Each result records exact Studio and Foundation revisions, commands, browser/assistive-technology versions and retained evidence. A failed demonstration keeps its milestone and owning issues open.

## Milestone 1 — Normally composed expression editing

**Promised outcome:** A workflow author can select JavaScript and Liquid on a persisted activity input and receive rich editing plus actual location-scoped inputs, variables and outputs from the configured backend.

**Demonstration:** Rebuild matching hosts; create and reopen a disposable persisted workflow; use the real syntax picker and compact/expanded property editor; request completion, hover and validation; then exercise missing editor module, missing backend provider, unauthorized and incompatible states independently.

**Expected evidence:** module catalog and feature readiness; capability links; visible scoped symbols; source/cursor/undo continuity; actionable degraded states; normal-host regression coverage.

## Milestone 2 — Installed syntax and runtime conformance

**Promised outcome:** Every installed supported text Expression Type reports truthful readiness, and JavaScript editing accepts/suggests only runtime-compatible grammar and APIs.

**Demonstration:** Run the conformance matrix with independently composed languages, incomplete source, syntax switches and unsupported JavaScript constructs/globals. Confirm specialized reference/structured editors remain unchanged.

**Expected evidence:** conformance-suite results, runtime parity tests and adverse controls that fail when adapters/providers or grammar restrictions are removed.

## Milestone 3 — Deep language assistance

**Promised outcome:** Authors receive relevant JavaScript local/member/signature help and Liquid value/filter/tag help backed by the actual runtime profile, with precise known-shape diagnostics.

**Demonstration:** Author representative locals, callbacks, member chains, interpolation, filters and tags; verify signatures, documentation, runtime metadata parity and unknown-dynamic-shape behavior. Complete the bounded JavaScript service spike before any dependency adoption.

**Expected evidence:** focused provider/editor tests, runtime metadata parity, real producer-consumer journey and exact-head review.

## Milestone 4 — Complete developer experience

**Promised outcome:** Expression editing is readable, accessible and continuous across themes, sizes and editing modes, with active signatures and safe explicit formatting.

**Demonstration:** Exercise light/dark/dim themes, narrow inspector, long and multiline source, paste, expand/collapse, syntax switching, formatting and keyboard exit/help/completion.

**Expected evidence:** automated accessibility results for the scoped editor surfaces; documented keyboard-only runs for focus, completion, hover/signature help, diagnostics, compact-to-expanded transition, Tab capture/escape and unavailable states; source/cursor/undo assertions; Liquid whitespace preservation; and affected complete-suite/repository-gate results. This evidence is scoped to the named journeys and is not a product-wide formal conformance audit.
