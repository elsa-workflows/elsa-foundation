# BPMN 0.5.0: explicit cut dispositions

Companion to the [adoption comparison](README.md), for the first ordered PR of
[#2735](https://github.com/elsa-workflows/elsa-foundation/issues/2735). Foundation is pinned to
`98efed4fc2c07337ad0b30128b60f462b8ddcff0`; the released library is pinned to
`021d2c5bba494f17d346144d97763cd3b2a13a4b` (**0.5.0**, payload **1.10.0**).
Each row dispositions an explicit statement or cut in the baseline runtime or interchange README.
“Supported” means library source support, never a claim that Elsa has completed its adapter or UX.
The 242-method audit in the companion covers the common executable scenarios. This table separately
accounts for the documented limitations; repeated statements are cross-referenced or grouped by
one identical obligation. Links identify the pinned source, not moving main. Foundation paths abbreviated below: `Essentials/src/Activities/Bpmn/Elsa.Activities.Bpmn/README.md` and `Essentials/src/Activities/Bpmn/Interchange/README.md`.

Disposition vocabulary: **Supported** = library source supports it; **Retained cut** = pinned library itself does not model/execute it; **Host-owned** = library deliberately leaves it to the host; **Aligned** = the release retains the baseline restriction; **Host profile** = encoding or capability choices the host must make explicitly. This comparison proposes no silent profile change. The switch must preserve current behavior and readable data; any new capability needs an explicit host implementation and proof, or an explicit, visible unsupported/degraded result. Library support alone is not Elsa readiness.

## Integration notes

- The notable release-supported Foundation-side gaps surfaced by explicit cuts are: date/cycle timer fidelity at starts/catches/boundaries/event-subprocesses; coded BPMN error-event-subprocess matching and call-activity escalation-boundary support; link throw/catch; signal throw/end; expression-condition preservation; complete sequence/message-flow DI, lanes, full multi-process export, and vendor-extension preservation; the 10,000-dispatch guardrail; and the narrower one-error-event-subprocess rule. These require a separate Foundation compatibility decision or an explicit documented profile; this ledger does not implement them.
- Target-side retained cuts include: compensation on MI hosts, cross-scope compensation cascade, compensation/conditional event-subprocess triggers, nested event subprocesses, MI transactions, external-interruption rollback, transaction hazard semantics, transaction cross-scope cascades, escalation intermediate catches, standalone duration starts, one-shot-only timer execution at catches/boundaries, counted non-interrupting cycle accounting/re-arm throttling, standard loops/MI completion conditions/output aggregation, data I/O semantics, call outputs, correlations/payload mappings, conversations/choreographies, and full MIWG conformance.
- Host-owned items include child workflow resolution/tenant/version policy and teardown, host timer/event scheduling, expression execution, incident/retry policy, and correlation/payload delivery. Host ownership is not proof that Foundation already implements the adapter correctly.
- This ledger proves only the pinned source capability comparison and README cut dispositions. It does not establish package/version pinning, frozen authoring-fingerprint identity, persisted-state round-trip compatibility, Studio behavior, or any issue/PR acceptance gate.
