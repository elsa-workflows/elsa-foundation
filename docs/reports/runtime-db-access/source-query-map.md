# Source/query map (T02)

**Status: T02 remains in progress.** This is a bounded source audit for the captured successful HTTP reference and ordinary REST companion in Coalesced and Immediate modes. It identifies source-backed query families and why their read-before-write checks exist; it does not attribute an EF command to a specific method, estimate latency, establish provider round trips, or close T04 settled-work accounting. The complementary [EF identity ledger](ef-identity-accounting.md) supplies observed context/provider/lifecycle joins, and [before timings](before-timing.md) are now recorded separately. Exact callers, participants and T04 settlement remain open. See the [baseline accounting](baseline-accounting.md) for fixture identities, outcomes, command totals, and the accepted capture qualifications.

The later [bounded Azure settlement packet](azure-settled-accounting.md) adds a primary Coalesced settlement snapshot and six subsequent source-bound resumption sweeps. Its separate acceptance does not retroactively fill the exact-caller or participant gaps in the older packets mapped here.

## Smallest missing joins for T02/T04

1. **Exact repository method attribution:** the trace already closes EF command span parents to request roots and nearest engine spans, but EF command events are not tagged with repository method/span IDs. To assign a source method, retain a method/activity span ID correlated to the observed command/context/connection/lifecycle identities. The complementary ledger supplies process-local EF identity tuples, not method callsites. Until then, nearest phase and table token are causal/category evidence only.
2. **Checkpoint participant/marker linkage:** retain checkpoint ID and immutable commit ID/fingerprint with participant type and transaction ID/save operation ordinal. Engine spans currently export checkpoint/work-item/handler and mode/intents tags, not participant names. The source code's transaction boundary cannot be inferred from aggregate EF transaction log groups.
3. **Queue and outbox completion:** join workflow execution ID, work-item ID, command/handler, outbox item ID and originating checkpoint/intent ID to claim owner/fencing token, attempt, completion/delivery state and timestamp. Capture completion through a bounded settled point after the POST; request ancestry and after-response diagnostic writes alone are insufficient.
4. **Statement/provider accounting:** retain provider command IDs and statement/round-trip boundaries separately from EF Core event 20101. One leading SQL verb per EF event and a possibly multi-table shape hash do not count SQL statements or network round trips.
5. **Diagnostics separation:** the complementary ledger establishes observed diagnostics context/provider/connection alongside EF command identity; exact resource/store batch and runtime-event links remain unresolved. A root-closed `elsa_otel_*` command is causal to the request trace but is a write to the diagnostics store, not an engine-state query.

No totals in this map are counts of SQL statements, provider round trips, `SaveChanges`, checkpoint transactions, participant rows, retries, or settled background work. The separate preserved-source low-logging before controls are now accepted, while comparable final after measurements and T04 finite settled-work attribution remain open. This source map selects no persistence optimization.
