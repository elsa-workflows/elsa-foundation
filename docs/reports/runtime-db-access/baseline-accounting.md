## Attribution protocol and limits

Use the current runtime tracing surface when the host listener is active; the tracer returns no span when no listener subscribes. `ActivitySourceWorkflowEngineTracer` emits drain, dispatch, activity-execution and checkpoint-commit spans. Existing tags include `elsa.workflow.execution_id`; dispatch/execution tags include `elsa.work_item.id` and `elsa.command.kind`; dispatch sets `elsa.handler.name`; checkpoint spans include `elsa.checkpoint.id`, `elsa.checkpoint.persistence_mode`, mandatory-boundary state and post-commit-intent count. Carry TraceId and SpanId/parentage from the incoming W3C request through EF event 20101 where the active logger/exporter supplies it. See [telemetry names/tags](../../../src/essentials/Workflows/Runtime/Diagnostics/WorkflowEngineTelemetry.cs#L21) and [span creation](../../../src/essentials/Workflows/Runtime/Diagnostics/ActivitySourceWorkflowEngineTracer.cs#L45).

For each captured EF `Microsoft.EntityFrameworkCore.Database.Command` event 20101, retain timestamp, duration, provider/category/event ID, command text or a safely normalized form, TraceId/SpanId, and the nearest source phase/caller key. Redact parameters and credentials. Group by request phase and source API/handler; keep inspection GETs, database initialization, unrelated pollers, and commands after transport completion in separate buckets. If event logs lack SpanId/parentage or a stable workflow/work/outbox identity for a later command, mark the exact attribution **Pending** and route that gap to T04. The current engine spans do not themselves tag `ActivityExecutionId` or `outboxItemId`, and the EF command event does not supply a repository method name; SQL text plus source mapping may narrow a caller, but an aggregate request TraceId alone is not an exact source-call attribution.

Keep these units separate in the ledger:

- EF event 20101 **command executions**;
- SQL statements parsed from command text, if separately counted;
- provider network round trips, only with provider-level evidence;
- transactions, only with provider transaction evidence;
- logical runtime checkpoints and immutable marker records;
- scheduler work items, claims, retries and acknowledgements;
- outbox items/intents and their delivery transitions.

They do not have a fixed one-to-one mapping. In particular, an EF command can carry multiple statements, batching can combine writes, and one checkpoint spans multiple participant operations. The checkpoint-store source has two `SaveChangesAsync` calls inside its new-commit transaction, but this is not evidence for an exact event, statement, round-trip, or transaction count in the measured run.
