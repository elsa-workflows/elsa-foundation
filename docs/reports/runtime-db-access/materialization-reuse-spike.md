# Durable-value page reuse: conditional T08 candidate

**Status:** source-grounded candidate selected for T08 design. This is not a shipped cache, a T07 completion claim, or evidence of primary HTTP savings. Source order and behavior below are pinned to [`add868046e74c1620f7329b063ec708920019d83`](https://github.com/elsa-workflows/elsa-foundation/tree/add868046e74c1620f7329b063ec708920019d83).

## Decision

Design one bounded cache of **raw inner durable-value pages** inside the existing coalescing session. Re-run the coalescing overlay merge for every read. This targets a source-reachable start-to-invoke pair: typed activity start materializes its input snapshot, then commits `ActivityStarted`; under an applicable coalescing session and below the segment cap that checkpoint is buffered without an inner commit. Invoke performs durable-value `ListAll` before the attempt claim. The under-cap path therefore has no required inner durable-value write between the two traversals.

This does not prove that every primary request takes that path: Immediate/no-session dispatch and cap-hit segments can write between reads. It also does not say how many SQL commands or milliseconds reuse would save. Exact primary savings remain T18 work.

## T08 design gates

1. **Scope and authorization:** read `IPersistenceAccessContextAccessor.Current` on every page call. EF resolves scope per call and uses it in row filtering and cursor validation ([`EfDurableValueStateStore.ListPageAsync`](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Persistence/EntityFrameworkCore/Stores/EfDurableValueStateStore.cs#L105-L127)). A workflow ID does not partition a cache by itself. Key each raw page by the current access context (scope, access policy, purpose and across-scope mode), workflow ID, page limit and inner continuation. Perform the same authorization checks before serving a cache hit, or bypass modes the provider would reject. Ordinary `RequireScope()` refuses global/across-scope and privileged contexts ([`PersistenceAccessContext`](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Core/Models/PersistenceAccessContext.cs#L27-L50)). Verify the accessor’s DI lifetime and changing-ambient-scope behavior; do not capture a single scope at cache construction.
2. **Fresh overlay:** cache raw provider pages only; reapply current session upserts and tombstones on every read. The existing wrapper passes direct `SaveAsync` and `DeleteAsync` through to the inner provider ([`CoalescingRuntimeStateStores.cs`](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Services/Coalescing/CoalescingRuntimeStateStores.cs#L142-L176)), so invalidate before awaiting either write. Invalidate before every **inner durable commit attempt**, including a failed or cancelled attempt. A known under-cap deferred buffer is not an inner write; invalidating it would erase the target start-to-invoke reuse.
3. **Nested lifetime and ownership:** accessor pushes form a nested AsyncLocal stack ([`AsyncLocalRuntimeCoalescingSessionAccessor`](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Services/Coalescing/AsyncLocalRuntimeCoalescingSessionAccessor.cs#L16-L36)). Disable parent reuse on nested entry. Clear and deactivate cached state when the owning session is disposed or loses its active drain. Confirm whether any direct writer can bypass the scoped coalescing wrapper; if that cannot be excluded or made an invalidation source, bypass caching.
4. **Snapshot safety and bounds:** `DurableValueState` retains the supplied metadata dictionary and its JSON fields without cloning ([model constructor](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Core/Models/DurableValueState.cs#L11-L49)). A page cache must not return shared mutable backing objects or depend on disposed JSON storage. Snapshot metadata and clone `JsonElement` values/schema, or bypass reuse if safe snapshots are not implemented. Specify numeric page/row/byte budgets before #1306 implementation; on overflow bypass caching without truncating results. The checkpoint hop cap does not bound durable-value rows or bytes.

## Required design and implementation proof

T08 must specify these cases; #1306 must implement and pass them before delivery, using existing test projects:

- A nonempty typed start → deferred `ActivityStarted` → invoke fixture proves a real repeated raw-page request is served from cache while logical rows remain identical.
- A changed overlay between reads proves fresh upserts/tombstones are merged over the cached baseline.
- Different execution/scope/access-policy/purpose/cursor inputs cannot reuse an incompatible page; privileged/global/across-scope cases preserve provider rejection.
- Inner checkpoint success/failure/cancellation and direct Save/Delete invalidate before the write; cap flush and nested-scope entry cannot serve stale parent data.
- Cache overflow returns the complete uncached provider result; disposal and lost ownership leave no reusable cache. Mutating a returned metadata dictionary or disposing an originating JSON document cannot corrupt a later hit.

## Measured signal and limits

Root and independent QA verified the retained raw console output, TRX and exact temporary probe patch. The [evidence record](evidence/materialization-reuse-spike-2026-10-07.json) contains one passing test of the existing five-leaf ReplaySafe CLR flowchart with empty durable-value state and an in-memory provider. The original enabled/disabled completion, commit/state fingerprint, fusion and dispatch assertions remain intact and passed.

The run recorded 13 inner `ListPageAsync` calls and six input-binding **entry** observations. All five adjacent entry-to-entry windows contain two page calls in the same session, with no recorded direct durable-value writes or logical durable-value change items between them. The session is active and inner commit count is zero at each observed entry. This does not mean the completed workflow made zero commits. Ten calls fall within those five windows; the other three are outside them, including the initial start read and final output projection. Distinct caller chains include start-snapshot and invoke traversals. Each interval spans the preceding invoke and next start; it does not assign both calls to a single snapshot. The assertion requires at least one qualifying pair; all five are observations from this run.

The probe does not count durable `Find` misses, returned rows, frame reads, activation or serialization cost, SQL statements or provider round trips. Its page events lack per-call invocation IDs and content fingerprints. It is a mechanism signal, not complete attribution or general freshness proof. The [manual probe patch](evidence/materialization-probe-2026-10-07.patch) applies to the pinned base in a disposable checkout; it is retained as experiment evidence rather than added to the permanent test suite. The evidence record supplies the focused command. Earlier worker result transcriptions are not counted as retained raw runs.

The [existing M2 primary fixture and census](../../../specs/193-bounded-coalesced-pagination/reference-trace.md) cover Sequence → synchronous HttpEndpoint → intrinsic SetVariable → WriteHttpResponse and show eight durable-value SELECT touches after pagination. Those counts are not cache evidence. The source order above establishes a reachable reuse opportunity for the typed activities in this graph; it does not prove every request reaches it. T18 owns exact primary HTTP and valid REST savings and the response/terminal-state checks.

## Separate accounting and mutation surfaces

All source inventory references below use the pinned base. These are source-confirmed paths, not newly measured costs.

| Surface | Source and disposition |
|---|---|
| Complete durable-value readers | Start snapshot and CLR invoke above; `WorkflowIntrinsicExecutor.MaterializeValueAsync`; `GraphActivity`; parent notification/completion handlers; retry-boundary cloning; `WorkflowOutputSource`; and instance-detail readback. These readers project value sets. Replacing all traversals with selected point lookups has no proven complete key set and could lose identity, input or output visibility. |
| Point reads | No product caller of `IDurableValueStateStore.FindAsync` was found at this base. The public method and overlay/provider implementations exist. A separate point-miss cache is not selected. Empty successful inner pages are eligible page results, subject to the same invalidation and bounds as nonempty pages. |
| Frames and activity state | `RuntimeContainerScopeService` reads the workflow root and activity ancestor chain; snapshot materialization also lists activity state. These use different stores and remain outside this durable-page candidate. |
| Activation and serialization | Invoke separately claims the attempt and activates the activity after its value projection. This experiment measures neither activation nor serialization CPU/allocation costs. Page snapshotting adds potential CPU/allocation cost to assess in the implementation and final comparison. |
| Logical durable writers | Output capture, graph-input projection, initial workflow seeding, intrinsic execution and retry cloning produce checkpoint durable-value changes. Deferred changes must remain visible through the current overlay without replacing the cached persisted baseline. |
| Actual durable writes | EF checkpoint staging bypasses the public durable-value store, so its outer coalescing commit wrapper must invalidate before inner calls. In-memory checkpoint persistence calls Save/Delete. Public/direct Save/Delete and custom callers require the same freshness treatment; a provider bypass that cannot be covered prevents reuse for that composition. |
| Flush and lifetime | Quiescence, mandatory boundaries and cap flushes call the inner commit store. Overlay maps survive some cap/attempt boundaries, so merely clearing buffered checkpoints is insufficient. The current AsyncLocal scope restores its parent and disposal does not deactivate that session: new cache lifetime must be explicit. Single-writer leases fence the drain and cancellation follows ownership loss; cache reuse must stop with that authority. |

The [store wrapper](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Services/Coalescing/CoalescingRuntimeStateStores.cs), [checkpoint wrapper](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Services/Coalescing/CoalescingRuntimeCheckpointCommitStore.cs), [EF participant staging](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Persistence/EntityFrameworkCore/Stores/EfRuntimeCheckpointParticipantStaging.cs) and [drain orchestrator](https://github.com/elsa-workflows/elsa-foundation/blob/add868046e74c1620f7329b063ec708920019d83/src/essentials/Workflows/Runtime/Services/Scheduler/WorkflowDrainOrchestrator.cs) anchor those mutation/lifetime distinctions. T08 must carry them into explicit tests, including supported provider composition and partition isolation.

## Alternatives and disposition

A whole-collection baseline snapshot would eagerly retain all durable state: its cost grows with both row count and payload size and is not bounded by the checkpoint hop cap. Reusing only pages already fetched preserves lazy provider access and allows independent entry/row/byte limits. On budget overflow, discard/bypass cached state and preserve complete provider results. T08 must select numeric budgets and define reset behavior before implementation. This candidate reduces repeated provider access only; callers still traverse/project the value set in memory, and activity-state/frame reads remain outside this change. No global cache, public generic cache interface, altered paging contract or relaxed durability boundary is selected.

The original private inventory withheld selection because applicability and freshness were unproven. The subsequently checked start→deferred ActivityStarted→invoke order establishes a reachable candidate; the raw CLR run independently shows repeat reads. Together these justify the bounded T08 design work with the gates above. They do not waive its unresolved implementation questions. T07 remains open through review; #1306 implementation and final T17/T18 acceptance remain outstanding.
