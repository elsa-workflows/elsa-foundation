# Elsa 4 preview release notes

## Workflow submission validates drafts (#2792)

`POST design/workflows/definitions/submit` now runs the same composed draft validators as promotion before
creating a definition, draft or immutable version. Blocking findings return HTTP 409 in promotion's existing
problem envelope, with messages grouped by node/input path under `errors`. Warnings remain nonblocking.
The separate credential-literal admission keeps its existing HTTP 400 response.

Headless clients and test fixtures that previously submitted invalid graphs must correct those findings
before submitting. To save unfinished content, create a definition/draft and edit the draft through the
ordinary draft-authoring endpoints; immutable versions require successful validation. A refused submit
stores no authored rows or successful operation marker, so its operation key can be retried after correction.
A successful operation-key replay returns the committed result without revalidating it against newer rules.
